# 发现

- Desktop 用量经 getStats 计算无关的多窗口周/月汇总，反复构造 Intl formatter，并同步读取全部 JSONL。
- Trace 首先截断最近 5000 条全部类型事实，再筛日期，统计可能不完整。
- 模型汇总没有状态分项；Bot 不等于 Agent。用量已记录 agentId，Trace 的 run payload 已携带 agentId。
- 两页使用 styles.css 语义类；主题 family / recipe 决定颜色、表面、字体、控件。
- 工作树包含其他开发中的修改；只编辑本任务文件及明确文档段落。

## 修复收尾

- 根因类别：先截断再过滤导致统计范围泄漏；Bot/Agent 混用及模型 API 拆分导致聚合口径不清；逐条构造时区 formatter 与重复解析导致随历史记录增长的计算开销。
- 机器守卫：超过 5,000 条的临时 SQLite、午夜边界、Agent 缺失、跨 API 模型合并、全部模型状态分组、查询参数编码、formatter 构造次数上限、外部写入后的账本缓存失效与调用方副本隔离。
- 长期规则：现有共享层根修、临时数据和 UI 主题验证规则足够，不向 AGENTS/CLAUDE 添加一次性实现说明。
- 用量和 Trace 各自保留记账与执行事实语义；不能从没有返回用量推断零成本或请求成功，也不把一次失败重试等同于整轮失败。

## 第二轮视觉反馈

- 用户参考图的可复用结构是紧凑横向指标、独立主图、可直接比较的列表；不新增统计功能。
- 筛选错行根因是共享选择器默认 justify-items:end，分析面板需在统一样式中伸展实际 trigger；几何守卫验证同行并可用纵向故障注入击穿。
- 曲线越界属于图表插值错误：控制点未限制在相邻数据范围。原有用例只覆盖统计计算，未约束绘图几何；新增采样回归覆盖零平台和峰值平台。

## Trace 趋势与 Agent 表现

- 模型请求状态与 Agent run 状态必须独立；run 按 runId 去重并取最新状态，成功率不把等待/取消当失败。
- MCP 运行时工具使用 mcp__ 前缀，按该规范将趋势中的普通工具与 MCP 分开，不把两条线重复相加。
- 费用对象被既有 sanitizer 折叠为 [object]，不能直接交给统计使用。在 recorder 脱敏前提取有限、非负数值估算，lean SQL 显式投影，历史缺失保留未知，不写迁移。
- 趋势以 createdAt 和配置时区归桶；单日小时、长窗日期，先补零再累计，使用同一筛选数据源，不受明细分页影响。
