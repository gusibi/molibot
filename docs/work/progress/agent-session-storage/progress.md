# Agent Session 存储实施记录

规格：[agent-session-storage-spec.md](../../../requirements/agent-session-storage-spec.md)。

## 实施顺序

1. 迁移准备：只读扫描、固定源身份和归属、稳定目标映射、暂存复制及校验、失败重试。
2. 共享路径与存储：Agent 工作区、Session 元数据、入站当前路由、共享资源、固定归属。
3. Runtime 隔离切换：启动阻塞、队列/事件暂停、确认后的提交与恢复。
4. 全部消费者：历史、Web 展示索引、附件授权/预览、任务、删除/归档/导出。
5. Desktop：迁移摘要、确认/取消、进度/重试、中英主题及冷路径验证。
6. 全仓路径审计、文档、完整检查与审查。

## 当前状态

2026-10-10：迁移发现与暂存准备模块及 19 项回归已实现。后续步骤未交付；生产运行时尚未切换，没有操作真实数据。

模块处理 Context（JSON/JSONL 和旧 context.json）、配对元数据、当前 Session 路由、附件、scratch、运行详情/摘要/活动日志、Bot Skill 与 Event。映射记录固定归属和来源；正文原样复制，资源使用稳定来源命名空间，保留同目录相对引用。暂存文件经摘要校验后发布，失败重试复用已验证副本，不覆盖变化的副本；新源项复用已有映射，已登记源项变化明确阻塞。

未覆盖的渠道旧树文件（包括配置、规则、认证、连接状态和 Web 展示索引）会明确报告并阻塞准备。实际数据可能因此暂时无法完成 preparation，不能把此模块当作可用的整库迁移入口。它不提供完成标记、切换或长期旧路径 fallback。
