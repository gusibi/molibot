# 权限模式 × 沙箱策略 —— 两根轴的关系说明

> 面向所有用户（包括没用过 Agent 的小白）的官方口径。回答三个问题：
> 1. Chat 页面的 4 档是什么？设置页面的 4 档是什么？
> 2. 它们是什么关系？会不会交叉？
> 3. 谁覆盖谁？比如沙箱设了"严格"，Chat 里选 Auto，会怎样？

---

## 一句话总纲

**这是两根独立的轴，各自回答一个不同的问题：**

| 轴 | 在哪里选 | 回答的问题 | 作用范围 |
|---|---|---|---|
| **权限模式**（Chat 4 档） | Chat 输入框的模式菜单 | **"做事之前要不要先问你？"** | 当前 Session |
| **沙箱策略**（设置页 4 档） | 设置 → 沙箱 | **"事情本身能碰到哪些东西？"**（网络/文件/密钥） | 全局默认 |

一个管"问不问"，一个管"能碰什么"。**两根轴同时生效，缺一不可**——任何一次工具调用都要先过沙箱这把"能力闸"，再过权限模式这把"询问闸"。

---

## Chat 页面的 4 档（权限模式）

从严到宽，逐级放宽：

| 档位 | 一句话语义 |
|---|---|
| **Plan 计划** | 只读规划。只准看不准动，先出方案，你批准后才动手。 |
| **Manual 手动** | 每个有副作用的操作（写文件、跑命令）都逐个问你。 |
| **Accept Edits 接受编辑**（默认） | 写项目内文件、沙箱内跑命令直接放行；出圈的操作仍会问。 |
| **Auto 自动** | 在 Accept Edits 之上再放宽：更少打扰、更高自动化。 |

> 注意：无论哪一档，**安装/执行第三方代码（manage 类）永远会问**，这是安全底线，不随模式放宽。

## 设置页面的 4 档（沙箱策略）

从宽到严的单轴（按 §设计重构后的口径，见文末"现状与目标"）：

| 档位 | 网络 | 可写文件 | 环境变量/密钥 |
|---|---|---|---|
| **全开 Full Access** | ✅ 全放行 | ✅ 项目目录 + /tmp | 最小注入 |
| **标准 Standard** | ✅ 仅常用开发站点（npm/GitHub/PyPI 等） | ✅ 项目目录 + /tmp | 白名单注入 |
| **只读 Read-Only** | ✅ 全放行 | ❌ 仅 /tmp（不能改项目文件） | 最小注入 |
| **锁定 Locked** | ❌ 断网 | ❌ 仅 /tmp | 最小注入 |

手动修改任何细节（域名白名单、路径等）→ 自动变为"自定义 Custom"档。

---

## 它们如何结合：十字矩阵

每次工具调用按"沙箱档 × 权限档"共同裁决。以"Agent 想执行一条需要联网的命令"为例：

| 沙箱档 \ Chat 档 | Plan | Manual | Accept Edits | Auto |
|---|---|---|---|---|
| **全开** | ❌ 拒绝（只读） | 逐条问你 | ✅ 直接跑 | ✅ 直接跑，免审批 |
| **标准**（目标域名在白名单内） | ❌ 拒绝 | 逐条问你 | ✅ 直接跑 | ✅ 直接跑，免审批 |
| **标准**（目标域名不在白名单） | ❌ 拒绝 | 问你 | ❌ 沙箱拦截，命令失败 → 升级审批卡 | ❌ 沙箱拦截（见"现状与目标"） |
| **只读 / 锁定**（要写项目文件或联网） | ❌ 拒绝 | 问你 | ❌ 沙箱拦截 → 审批卡 | ❌ 沙箱拦截（见"现状与目标"） |

**关键规则：沙箱是能力边界，权限模式不能凭空授予沙箱里没有的能力。** Chat 模式再宽，也不能让"锁定"档里的命令联上网——那会绕过你精心配置的安全边界。

---

## 谁覆盖谁？（优先级链）

两条独立的覆盖链，**互不跨越**：

1. **权限模式链**：Session（Chat 里选的）→ Project → Bot 实例 → Agent → 全局默认（Accept Edits）
   - Chat 里选的模式只影响当前 Session，是这条链的最高优先级。
2. **沙箱策略链**：Session 级沙箱覆盖 → Project → Bot 实例 → Agent → 全局（设置页沙箱档）
   - 设置页选的档是全局默认；渠道 bot 可配置三态覆盖（开/关/继承）。

**所以"沙箱设严格 + Chat 选 Auto"的答案是：**
- ✅ Auto 生效的部分：不需要逐条审批的操作，全部免问、自动放行。
- ❌ Auto 不能生效的部分：网络/文件能力仍被"严格"档拦住。命令在沙箱内失败后，会升级为 Host Bash 审批卡——**这就是"选了 Auto 还在弹审批"的根源**：弹的不是权限询问，而是沙箱拒绝后的兜底审批。

---

## 现状与目标（已拍板的设计方向）

**现状（已交付）**：
- 两根轴完全正交、零联动。Auto 档与 Accept Edits 差异极小，不自动通过沙箱审批，也不放开网络。
- 设置页沙箱预设名为 observe / build / strict / custom，可读性差。

**目标（本设计，待实施）**：
1. 沙箱预设改为单轴 4 档滑条：全开 / 标准 / 只读 / 锁定（+自定义），如上表。
2. **Auto 档联动**：Session 选 Auto 时，该 Session 的有效沙箱档自动提升为"全开"，且沙箱审批自动通过——即"Auto = 全自动"符合直觉的语义。仅保留 manage 类（第三方代码）仍需确认。
3. 设置页沙箱档增加"全局锁定"开关：开启后所有渠道（含飞书/Telegram/QQ）强制使用该档，Session 不可覆盖；关闭时沙箱档仅作默认值，Chat 可按 Session 覆盖。
4. 渠道默认：飞书/Telegram/QQ 无审批交互面，Plan/Manual 自动钳位为 Accept Edits（现状行为保留）；沙箱档继承全局默认。
