# 子 Agent 执行与失败恢复

主 Agent 负责用户任务的整体结论；子 Agent 负责独立的委派任务。多个独立条目适合分别委派，并提前分配互不重叠的输出路径和共享 ID。共享构建、最终验收和发布由主 Agent 负责；会写入同一构建目录的验证应串行执行。

## 设置与预算

Desktop 或 Web 的“设置 → 系统 → 子 Agent 运行预算”控制后续新建子任务。保存只更新修改字段。

| 字段 | 默认值 | 作用 |
|---|---:|---|
| `subagentRuntime.maxModelRetries` | 12 | 模型失败后的重试预算；正常生成与工具循环不扣次数 |
| `subagentRuntime.maxToolCalls` | 100 | 每个子任务的工具调用上限 |
| `subagentRuntime.maxToolFailures` | 6 | 每个子任务累计工具失败上限 |
| `subagentRuntime.deadlineMs` | 1800000 | 每个子任务最长 30 分钟 |
| `subagentRuntime.maxTasks` | 4 | 单次委派的任务数上限 |
| `subagentRuntime.maxConcurrency` | 2 | 单次委派的并发上限 |

模型失败按原生 generation 身份累计去重。成功请求不扣失败重试预算，也不清空已使用的次数。连续模型失败时，首次请求加 12 次重试最多请求 13 次。重新打开同一子任务保留原预算与计数；已停止任务不能通过重开刷新预算。

子工具同时计入父任务的总工具预算。拆分任务不绕过父任务总限制。`maxModelTurns` 设置和 `MOLIBOT_SUBAGENT_MAX_MODEL_TURNS` 环境变量已移除；环境变量对应入口为 `MOLIBOT_SUBAGENT_MAX_MODEL_RETRIES`。

## 恢复与完成状态

脚本或内容错误作为工具结果交给模型，模型可以修改文件后重新验证。模型请求失败从已经提交的子任务上下文继续，保留执行回执，不重放已完成的写入。审批等待和用户停止不当作模型失败重试。

子任务因预算、超时或执行错误停止时，`subagent` 返回失败标记、任务描述、停止原因、子会话标识及最后执行记录。并行任务分别返回结果，链式任务停止后不执行后续依赖步骤。

主 Agent 可以在剩余授权与预算内接手，并必须说明整体状态、完成内容、停止位置、原因和未完成项。子工具失败不等于整体任务最终失败；主 Agent 完成接管和验证后可以报告完成。工具执行结束也不等于用户目标完成。

若主模型没有生成最终文本，或试图用 `[SILENT]` 隐藏已停止的子任务，Runner 输出“未完成”说明并记录错误状态。该说明只陈述已有执行证据；没有产物或验收证据时，不宣称完成。
