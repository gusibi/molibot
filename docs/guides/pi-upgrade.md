# Pi 运行时升级与回滚

适用版本：Molibot 锁定的 Pi 1.4.0。八个直接依赖统一升级，传递依赖由 `pnpm-lock.yaml` 固定。

## 兼容行为

- 模型请求传入 `telemetry: TelemetrySpan`。内置模型由 Pi Models 记录请求 span；自定义 Provider 的直接流由宿主记录，统一关联到原 run 与模型尝试。
- 派生 Chord 调用上下文使用 `withAbortSignal()`，保留取消、遥测与上下文值。
- 子任务策略和用量投影显式设置 `checkpointWhen: () => false`，普通更新保存为增量。
- 会话压缩摘要的输出预算由宿主显式设置为 `min(1600, model.maxTokens)`，不再借用上游忽略的 `reserveTokens` 参数。压缩触发阈值不变。
- Durable 的重试和延迟响应轮询可进入 `sleeping`。连续中断且没有进展的任务保留上游暂停策略；恢复入口明确报告暂停，不无限等待，也不自动重放未知副作用。
- 分类参考图片仍受宿主原有能力限制；升级依赖不会自动开放新付费能力。

## 数据迁移

Pi 1.4 会把原生执行 SQLite 从 schema v1 自动迁移到 v2。1.3 无法打开 v2 数据库。

正常执行和启动恢复检查统一经过 `piStorage.openPiStorage()`。首次打开 v1 库时，先在原文件旁生成 `<原文件>.backup-pi-schema-v1-<随机标识>.sqlite`，再交给 Pi 迁移。备份包含 WAL 中已提交的数据，使用独立 SQLite 文件和仅当前用户可读写的权限；备份失败则停止该库的迁移。新建或已迁移的库不生成这类备份。备份保留供人工恢复，不自动清理。

这些文件只保护各自的原生执行库，不是整个应用数据目录的同一时刻快照。

## 切换真实服务

1. 确认待切换的服务实例、构建与数据目录，结束或记录在途任务。
2. 停止该实例的写入，保留完整数据目录快照，以及原版本的构建、`package.json` 和锁文件。不要只复制仍在写入的 SQLite 主文件。
3. 使用新锁文件安装并构建，再启动目标实例。核对实际进程的构建来源、启动时间与状态。
4. 验证普通对话、工具调用、Trace、审批续接与已有任务恢复；检查旧执行库旁的迁移前备份。

本次代码适配不自动重启或替换正在使用的服务，也不调用真实 Provider。

## 回滚

先停止目标实例并另存升级后数据，再恢复切换前的完整数据目录快照、旧构建与旧依赖锁文件。恢复数据库时处理同名 WAL/SHM，不能把升级后的日志与旧主文件混用。重启后核对构建与执行状态。

仅恢复单个执行库的旁路备份，适用于人工排障，不保证整个应用回到升级前状态；升级后新建的 v2 库没有 v1 备份。不要用降依赖版本代替数据回滚。

## 验证范围

升级回归使用临时数据库和本地模拟模型，覆盖摘要预算、遥测、WAL 一致备份、备份失败不迁移、启动恢复迁移、暂停任务、审批、Stop、延迟响应与 Codemode 恢复。

真实 Provider、当前在用服务和原生安装包需在目标环境另行验收。完整整体验收由用户主动执行 `pnpm verify:feature`，本次不自动运行完整浏览器与原生套件。

2026-11-01 验证：核心定向回归 100 项通过；原生执行、延迟响应强杀恢复、审批、工具结果与上下文等另一组 55 项通过（两组有交叉）；备份测试 3 项通过。新增守卫在修复前确认失败，包括摘要预算失效、旧 span 参数、迁移无备份和暂停任务不返回。

扩展调用方回归观察到 5 项范围外失败：`runner.test.ts` 中 4 个旧存储 mock 缺少实现早已使用的 `markSessionMessageDelivery()`；`subagent.test.ts` 中 1 个源码正则断言与未改动的 `tools/index.ts` 不符。Runner 测试在上述失败后还有等待未收敛，已终止该测试进程，其后续用例未完成，不能把该文件报告为通过。断言和存量实现均未为升级而放宽或改写。

最后一次仓库 `pnpm check` 的 4 个错误均在并行改动的 `app/desktopMemory.test.ts`，本次 Pi 适配文件无错误；该检查不能报告为整体通过。

适配代码、新增测试及直接调用方的定向 TypeScript 检查通过，包含项目生成的 SvelteKit ambient 声明；上述仓库级错误未纳入定向配置。八个声明版本、锁文件入口和实际安装版本均为 1.4.0。
