# Desktop Agent 房间

打开房间后，点击标题栏「新建会话」即可开始新聊天，无需重新选择成员。会话选择器可切回历史聊天；每次会话独立保存记录、成员上下文、草稿和模型选择。新会话标题取自第一条消息；尚未发送时显示会话序号。新会话保留团队、默认回答者、Project 和权限，不带入旧会话聊天。Agent 的长期记忆和 Project 文件仍遵循各自原有范围。

现有房间首次加载新版数据结构时，原聊天会保留为第一条会话，成员原有上下文继续可用。升级前会在 Session 数据库旁保存 `<sessions-db>.backup-<timestamp>-<id>` 完整备份；再次启动不会重复升级。

切换会话不会停止原会话的任务，回复始终写回原会话。所有会话共享房间的写入资格；旧会话等待审批时，新会话的写入任务仍需排队。输入区「停止」只停止当前会话的任务；修改成员或删除房间按整个房间处理。

在 Desktop 侧栏打开「Agent 房间」，点击「新建房间」，填写名称、选择已启用成员和默认回答者（Primary）。普通房间使用独立工作区；Project 房间使用现有 Project 目录和工作约定。房间权限上限与全局、Agent 限制共同生效，取其中最严格的模式。

发送前可选择 `@` 成员。没有选择时由 Primary 回答；回复某位成员时由该成员回答；显式选择优先于回复对象。选择多人会进入只读讨论，成员直接提供各自的分析，不会自动切换成生成计划的 Plan 模式：不开放网络搜索、MCP、Mini Apps 或命令执行。每位成员独立流式回答，用户消息只出现一次。图片和文件可通过添加附件发送。未手动选模型时，输入区按后端解析出的成员模型显示；成员模型不同时显示「成员配置模型」。

要执行讨论结果，在成员回复上点击「交给此成员执行」，补充要求后发送。单成员执行仍遵守当前权限和审批要求。审批卡显示请求成员和实际操作，批准仅针对本次请求。

同一房间的写入任务串行，等待审批时保留写入资格。后续任务显示排队和阻塞成员；其它房间可继续执行。不同房间即使使用同一 Project 目录也不互相锁定，文件冲突需要自行处理。

「插入当前执行」只影响所选正在运行的成员，并在共享记录中保留指令。当前执行的保留策略已经确定；若插队文字要求更严格的隐私策略，系统拒绝注入，需先停止，再将该指令作为新消息发送。「停止」只取消对应执行；「全部停止」同时取消当前会话的运行、排队和暂停工作。已完成回复和文件操作不会撤销。停止中的工具尚未结束时保持「正在停止」。

服务重启后，未完成任务显示「已中断」，排队任务显示「已暂停」，不会自动重放。点击「重试 / 继续」只创建对应成员的新执行，保留原始输入、共同上下文快照和历史证据。外部操作结果未知时，先检查实际结果，再选择完成或未完成；系统不会擅自重复未知操作。

每位成员在房间的每次会话中拥有独立上下文。共享历史在接受消息时冻结，默认最多约 6000 token，并按最小可用模型预算缩小；扣除成员历史、提示词、输入附件和输出预留。旧内容先舍弃，超长引用显示截断标记。若引用及其来源信息无法放入剩余预算，发送会被拒绝；请取消引用或减少本次输入后重新发送。排队期间改成无法容纳原快照的模型，会拒绝启动并要求重新发送。仅本轮、不可搜索和不记忆策略随派生内容传递。

编辑成员时必须保留至少一位成员和一个 Primary。移除成员会停止其工作，重新加入同一 Agent ID 可继续其各次会话的上下文。删除房间要求先停止全部工作；房间进入现有 Session 回收站，可在保留期内恢复。彻底清理只删除房间记录、独立上下文和房间附件，不删除 Project 文件。

V1 不支持将普通对话转换为房间、编辑重发、分叉、自动轮流讨论或 Agent 自行邀请其它成员。需求和验收条件见 [Room 规格](../requirements/multi-agent-room-spec.md)。
