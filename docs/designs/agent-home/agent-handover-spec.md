# Agent Handover 交付 Spec

状态：已实施（2026-10-23），发布快照见 [Issue #67](https://github.com/gusibi/molibot/issues/67)。本文件是交付契约，不是产品规范；可引用的约束以 [Personal Agent V1 Spec 的 `PA-HD-*`](../../requirements/personal-agent-experience-v1.md) 为准，决策理由见 [ADR 0006](../../adr/0006-agent-handover-is-a-projection.md)，界面探索见 [原型目录](../personal-agent-home/index.html)。实施证据与边界见[能力矩阵](../../requirements/personal-assistant-capability-matrix.md)。

## Problem Statement

Desktop 默认 Agent 的首页现在只回答“我在跟谁说话”：头像、输入框、三个起点、三条最近对话。用户每天第一次打开时，真正想知道的是另外三件事——我不在的时候它做了什么、有没有事卡在等我、接下来它会不会自己动。现状下这些信息散在 Agent 活动状态、自动任务、计划和审批里，用户必须逐个页面翻，且翻完也不知道有没有漏。结果是助手在后台干活的价值看不见，而“等你决定”的事要靠推送碰运气。

## Solution

默认 Agent 的首页变成一份交接：助手先开口，用一两句结论说明离开之后完成了什么、有几件等你决定；结论下面挂着能点开的证据条目和待决定项；输入框仍在固定位置；安静时整页只剩一句结论和输入框。其他 Agent 的首页不变。交接是运行时证据的投影，不产生会话，也不承载模型上下文。

## User Stories

1. 作为 Desktop 用户，我希望打开应用就能看到离开之后完成的事，以便不用逐个页面确认。
2. 作为 Desktop 用户，我希望一眼看出有几件事在等我决定，以便先处理最要紧的。
3. 作为 Desktop 用户，我希望在交接里直接批准或拒绝，以便不用先找到那个会话。
4. 作为 Desktop 用户，我希望每个数字都能展开成条目，以便确认它没有夸大。
5. 作为 Desktop 用户，我希望每条记录都能点回产生它的会话，以便看完整上下文。
6. 作为 Desktop 用户，我希望待决定项标明来自哪个助手、哪个对话或项目，以便判断该不该批。
7. 作为 Desktop 用户，我希望在交接和会话页处理同一件事时结果一致，以便不会重复批准或看到残影。
8. 作为 Desktop 用户，我希望点开首页又马上切走不会让内容消失，以便回来还能看到。
9. 作为 Desktop 用户，我希望交接说明接下来会自动做什么，以便知道今天不用自己盯。
10. 作为 Desktop 用户，我希望安静的时候首页不摆一堆空卡片，以便不被无内容打扰。
11. 作为 Desktop 用户，我希望自动重试成功后不要再报成失败，但也不能被悄悄吞掉。
12. 作为 Desktop 用户，我希望失败的定时承诺出现在最上面，以便知道交给它的事没办成。
13. 作为 Desktop 用户，我希望交接里不出现模型编造的进展，以便可以信任这一页。
14. 作为 Desktop 用户，我希望在交接里打字就等于开一个新对话，以便保持现有入口语义。
15. 作为 Desktop 用户，我希望最近对话还在，以便接着昨天的话说。
16. 作为 Desktop 用户，我希望同一件事不在交接和最近对话里重复出现，以便列表不冗余。
17. 作为 Desktop 用户，我希望第一次安装时看到能做什么，而不是“暂无数据”。
18. 作为 Desktop 用户，我希望服务没连上时知道这是旧内容，而不是以为一切正常。
19. 作为 Desktop 用户，我希望中英切换、明暗主题和窄窗口下都能完成同样的操作。
20. 作为 Desktop 用户，我希望切换回其他 Agent 时看到的是开始对话，而不是别人的汇报。
21. 作为产品负责人，我希望交接的计数口径只有一处定义，以便界面和测试不会各算一套。
22. 作为产品负责人，我希望交接不新增第二套事件存储或第二个身份来源，以便不违背既有架构约束。

## Implementation Decisions

**单一读模型。** 新增一个服务端读模型负责整页数据：输入是默认 Agent 与 `lastAcknowledgedAt`，输出是结论句所需计数、条目列表、待决定列表、下一件已排期事项和三态标记。客户端不拼接、不二次聚合、不自行排序。所有“什么算一件事”“怎么排序”“怎么去重”的判断只存在这一处。

**数据来源，不新增事件表。** 已完成条目以 trace 的 `run` 与 `runtime_notice` 事实为窗口索引（`created_at` 已有区间索引，事实带 `agentId`）；承诺兑现与失约来自 Runtime Task 执行租约表（`finished_at`、`status`）；待决定来自三处现有查询（Host Bash 全局待审批原始记录、Durable Execution 与 Plan 的等待项、等待中的 Session 运行）。三者由读模型合并。

**去重与计数。** 同一任务执行与其派生 trace 事实只算一条，任务执行优先。计数单位是条目，不是运行、工具调用或产物文件。产物附属于条目。

**身份在组装处解析。** 现有四个审批/执行接口的载荷不改；读模型读取仍带 `sessionId` 的原始记录，再用唯一的执行身份接口解析 `agentId`。禁止在这些路径内联读渠道绑定。

**窗口。** `lastAcknowledgedAt` 与一份冻结的上一代快照一起持久化在现有的 Desktop 导航设置里，通过既有设置读写路径保存。离开首页（路由切换、窗口隐藏、应用退到后台）时写入；打开时不写。若进程在首页被直接杀掉，则不写入——下次启动重复展示同一份内容，这是有意选择的失败方向。待决定项不参与窗口，永远实时。

**上一代快照。** 确认时把当前渲染结果压成紧凑投影（条目上限 20，丢弃正文），只保留一份。不建历史表，不提供列表。

**审批状态单一来源。** 交接不存审批状态，只携带 `requestId`；批准/拒绝走既有的按 ID 解析动作，处理完由读模型自然不再返回。客户端两处都依赖同一份服务端状态，不做本地乐观保留。

**排期。** 下一件已排期事项由 Runtime Task 的 cron/一次性时间现场计算下一次触发；Durable Execution 直接读已有的 `next_run_at`。不新增持久化字段。

**三态。** 读模型返回 `quiet`、`first-run`、`stale` 三种标记：无条目且有待排期 → 安静；无任何历史与条目 → 首次；最后一次读模型成功时间超时或服务不可达 → stale，界面保留上次内容并标注。

**文案。** 结论句与条目文案全部由模板拼装。模型润色是一个可选后置步骤，输入只有“异常解释”片段，输出必须通过数字/时间/来源不变校验，校验失败则丢弃润色、保留模板文案。V1 默认关闭润色。

**界面。** 复用现有 Agent 首页组件与共享控件；身份区改为紧凑形态，输入框位置不变，最近对话保留三条并与交接条目去重。不新增导航入口，不改侧栏结构。

## Testing Decisions

好的测试断言用户可见结果：读模型返回的条目、处理审批后的两侧状态、重启后的窗口行为、切换语言与主题后的可达性。不绑定私有 helper、CSS 类名或组件源码文本。

**Seam 1（新增，最高）：`GET /api/desktop/handover`。** 一个读端点覆盖整页。用临时数据库与注入的运行时状态构造场景：只有完成、只有等待、两者混合、安静、首次、stale；断言条目集合、计数与条目一一对应、来源标识、排序与去重。这是唯一新增的业务测试入口，避免为每个区块各开一个接口再分别测。

**Seam 2（新增，最小）：确认窗口。** `POST /api/desktop/handover/ack` 写入 `lastAcknowledgedAt` 与上一代快照。按既有 settings 字段规矩做 save → 新 store → load 的整对象 round-trip；断言重启后窗口不漂移、上一代快照只保留一份。

**Seam 3（复用，不加新接口）：审批解析。** 用已存在的按 `requestId` 解析动作，断言从交接处理后源会话的待审批列表同步为空，重复处理幂等。

**Seam 4（复用，扩展现有用例）：浏览器界面。** 在既有 `tests/ui/agent-home.spec.ts` 上扩展，不新建并行 spec。覆盖：默认 Agent 显示交接、其他 Agent 不显示、打开后立即切走内容不丢、审批就地处理并消失、计数可展开、条目可回到源会话、安静与首次形态、中英与明暗与窄窗。

先例：`apps/desktop/src/api.test.ts` 的端点契约断言、`tests/ui/agent-home.spec.ts` 的首页行为断言、`sessionServiceAssembly`/`sessionMaintenance` 的临时数据库模式、设置字段 round-trip 用例。

验证边界：日常只跑与本次改动直接相关的定向用例与类型检查；全量 `pnpm verify:feature` 留给整体验收。真实 Provider 与外部渠道不进入本次测试。

## Out of Scope

- 永久主对话、把交接当会话续聊、交接历史列表页。
- Open Loop（PA-HD11）：规则已定义，V1 不实现、不上界面。
- 模型润色默认开启；V1 只保留校验与开关，默认关闭。
- Activity Feed、Dashboard、跨 Agent 活动流、移动端底部导航。
- 统一产物索引、产物“已打开”追踪、浏览器实时画面/截图。
- 修改现有四个审批/执行接口的载荷结构。
- Project、Room 首页改版。

## Further Notes

V1 交付 `PA-HD1`–`PA-HD10`、`PA-HD12`、`PA-HD13`；`PA-HD11` 留待后续，规则先行。

三个已知缺口会影响首版观感，需要在实施前确认取舍：普通对话运行没有步骤级进度（只有 Durable Execution 有），所以运行中条目只能显示任务摘要与时长；“今天接下来”需要新写 cron 下次触发计算，任务表里没有现成的下次运行时间；散落产物没有索引，“带交付物”的条目只能从会话引用反推，可能漏项。

计数口径与去重规则必须只存在读模型一处；界面与测试都引用同一结果，不得各自再算。
