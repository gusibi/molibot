这版改了什么

对照上一张图的问题逐条改。数据全是假的，只用来判断顺序和样式。

顺序

  1. 没办成 → 等你决定 → 今天的结果 → 接下来 → 最近对话。 DOM 顺序和视觉顺序一致，窄窗不会反转成“先读文章再看到审批”。
  2. 正在做的事不单独成区。 只有一条状态带，放在身份下面，回答“现在在干嘛”；它是状态，不是要读的内容，所以不占一个区块也不抢卡片。
  3. 没有再要右栏。 右栏在宽屏成立、在窄屏会把审批推到首屏外；改成全宽网格，宽 2 列、窄 1 列，同一份 DOM。
  4. 输入框不在视觉中心。 内容区自己滚动，输入框固定在底部，滚到哪都能直接说话。

一个决定只有一个家

  1. 选题只出现在“等你决定”里一次；大纲作为它的证据留在这张卡内，不再在结果区重复一张卡。
  2. “其他结果”只放已完成、不需要你动手的事，避免同一件事既要你确认又躺在已完成里。
  3. 运行中的任务只出现在状态带，不在“今天的结果”里提前出现；完成后才落到结果区。

文案的诚实性

  1. 结论句不含数字。 计数只在带标题出现一次，不会出现“另有两件”和徽标 2 对不上的情况。
  2. “已发送到飞书会话”，不写“已投递”。没有回执就不宣称送达；要写投递必须有渠道回执。
  3. 失败卡给出原因 + 是否重试 + 下一步能做什么，而不是只在表格里显示一个状态点。
  4. 页面顶部同时给出“上次离开”和“本页生成”两个时间，读者能判断这份简报覆盖哪段区间。

权限与风险

  1. 命令和目录直接摊开，不折叠在“查看详情”后面。
  2. “拒绝”和“允许一次”同样大小、同样描边，不给授权设默认主按钮；主按钮只留给可逆的软决定（确认选题）。
  3. 授权卡用暖色表面，“等你决定”的软决定保持中性表面，一眼能分出两种权重。

这条信息结构需要的新数据

  • 交付物投影：标题、2–3 条要点、来源会话、可执行动作。建议在服务端读模型里从“本次运行最后一条助手消息”推导（取首个标题、首段、前三个要点、首个链接），不新建产物索引。
  • 投递回执：渠道 + 时间 + 成功/失败。没有就先写“已发送到会话”。
  • 运行进度：已处理 N/M；现在的活动接口已有运行与子代理，缺的是阶段计数。
  • 条目级稍后/忽略：还没做，所以这一版没有“稍后”按钮，不做假按钮。
  • 截断计数：返回真实总数与“是否被截断”。超过 20 条时界面写“另有 N 件未显示”，不能只报 20。

故意没做的

  • “往期”入口——交接目前不保留历史列表（PA-HD13），要有入口先加需求。
  • 封面大图——在这个尺寸不传递信息，只抢注意力；正文里再看。
  • 等权 widget 网格、图表、KPI 数字——和“现在要不要动手”无关，也会和总览的 Agent City 重复。
  • 四态之外的边缘态（断连、审批洪水）——先定结构，再补这两张。

已定的四条

  1. 不做“全部结果”页。 当天在带内展开到上限；超过上限由读模型返回真实总数，写“另有 N 件未显示”。要翻更早的，去运行历史。首页不再造第二个列表。
  2. 首页只给“允许一次 / 拒绝”。 长期放行是设置里的白名单（可撤销），不在首页发会话级授权。同一个状态只留一个管理入口。
  3. “它在盯什么”只在安静日出现。 有结果的日子由“接下来”回答同一个问题；两者同时出现就是两套排期。
  4. 主卡按“承诺优先”选。 定时任务或计划产出的交付物优先于临时对话，同类取最新；当天没有交付物就没有主卡。把重要性交给模型判断会违反 PA-HD7 与 ADR 0006。
