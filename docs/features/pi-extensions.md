# Pi 扩展

Molibot 支持通过对话安装 Pi 扩展，并在 Desktop 设置 → 插件 → Pi 扩展中管理安装、搜索、启停、重载、运行方式和卸载。安装来源接受 npm 包名、npm 页面、Git 仓库、仓库子目录，以及 `npm:包名@版本`、`git:github.com/组织/仓库@标签`。Agent 使用已有 `extensionManage` 工具，安装继续经过所有者审批。

## 原生 Pi 运行方式

Desktop 设置中选择“原生 Pi（含终端）”。新配置默认使用该方式；没有 mode 字段的旧配置保留服务器运行方式，避免改变现有工具入口。Desktop 与 Web 设置页均可切换，修改后从下一轮任务生效。

原生交互需要已连接的 Desktop 客户端。没有客户端时，扩展的选择、确认、输入、自定义界面和编辑器请求立即失败；交互期间客户端超过 5 秒未续接，或单次交互超过 5 分钟未结束，任务会停止并保留副作用核对要求。没有交互请求的原生任务不受客户端在线状态限制。Web 与 Telegram / 飞书等渠道不能直接回答终端界面，可以在 Web 设置中切换到服务器方式。

让 Agent 使用已安装的扩展，或发送扩展的 `/命令 参数`。Agent 通过 `piExtensionRun` 在官方 Pi 1.4 交互式运行时中执行任务；扩展命令也有直接入口，不需要额外请求主模型。Desktop 在有任务时显示 Pi 扩展终端入口，用户主动打开后可以回答自定义界面、对话框和编辑器；后台任务不抢占聊天焦点。隐藏面板保留任务，可以再次打开；“停止任务”取消当前执行，Esc 由终端处理。

扩展工厂、组件和回调留在独立子进程。包的多入口、glob 排除、skills、prompt templates、themes 由官方资源加载器处理；npm 安装保留完整依赖布局；Git 子目录借用父目录依赖（包括 npm workspace）时，同样保留依赖所在的完整布局。配置中已保存的扩展 flags 传入原生运行时。扩展代码属于所有者信任代码，进程隔离不是操作系统权限沙箱。

原生模型目录包含已配置的内置与自定义服务商聊天模型，扩展可切换模型；请求仍经过当前 Molibot 任务的权限、审批、预算及用量记录。默认基础工具代理当前任务的受控工具。扩展自行注册的 Provider 留在子进程，通过宿主准入和用量回报接口执行，不复制宿主 Provider 凭据。扩展直接执行的本地代码和网络请求仍具有其进程权限。原生进程明确继承宿主 HOME、代理、证书路径和时区等网络及区域设置；不会创建独立 HOME，也不会复制整个宿主环境。

终端内容区固定使用 Pi 官方深色主题与匹配的 ANSI 配色，作为应用明暗主题的内容区例外；面板控件继续跟随应用主题。

## 会话与中断

原生 Pi 使用绑定当前 Molibot 会话的独立官方 JSONL 上下文。主会话保留兼容工具的结果与执行归属；两者不是同一份历史。原生生命周期发生在兼容任务内，不在主 Agent 每轮重复触发。

普通失败、停止、崩溃或长审批挂起可能留下未完成的原生上下文。失败与需要核对分别记录；模型失败不代表此前没有副作用。系统保留记录并阻止自动重试。检查已执行的操作后，在终端面板点击“已核对，允许新建上下文”；下次任务使用新上下文，旧记录保留。服务重启后也会发现待核对的任务。

原生文件保存在 `DATA_DIR/pi-native/<会话标识的 SHA-256>/`。移入回收站时保留；永久清除或回收站保留期到期清除时，同时删除 JSONL、状态、核对记录与内存终端输出。仍在执行或初始化的原生任务会阻止清除，停止后由清理重试处理。手动备份、搬迁完整数据目录时应包含 `pi-native/`；它不是主会话历史，单独导出主会话不能代替备份该目录。

宿主审批仍按原有流程处理；任意扩展的 JavaScript 内存续体不能在进程结束后恢复，不自动重放之前的副作用。

## 验证与边界

固定兼容基线为 Pi 1.4.0。已通过本地夹具验证自定义终端组件、真实按键、原生命令与 flags、动态工具、包资源、停止、并发会话限制、审批挂起、重启后的人工核对，以及真实 Runner 的模型预算和用量归属。新增回归覆盖无客户端、断连、应答期限、永久清除、失败核对、模型切换、宿主环境继承和受控 `!` shell；本地模拟 OpenAI 服务验证自定义模型切换后的请求与用量归属。WebKit 覆盖管理页真实安装、保存失败回滚、隔离服务重启、页面重载，以及终端 ANSI、输入、缩放、隐藏重开、停止、中英切换和窄窗。类型检查、Desktop Svelte 检查及 Rust 构建通过。

任意第三方扩展、旧 Pi 版本、外部桌面程序、原生依赖、账号登录和真实模型尚未逐项验收。LCU 等工具仍需满足自身平台与授权条件。终端交互当前在 Desktop 接管，Telegram / 飞书等渠道不能直接呈现任意 TUI。尚不承诺所有版本、所有扩展完全无缝；完整兼容目标与保留边界见 [兼容规格](../requirements/pi-extension-compatibility-spec.md)。

服务器运行方式保留原有接口，见 [服务器接口指南](../guides/pi-extension-runtime.md)。未重启或替换用户正在使用的实例，原生安装包的界面未走查。完整验收由用户按需运行 `pnpm verify:feature`、`pnpm test:ui`、`pnpm test:app`。
