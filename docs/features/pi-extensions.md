# Pi 扩展

Molibot 支持通过对话安装 Pi 扩展，并在 Desktop 设置 → 插件 → Pi 扩展中管理安装、搜索、启停、重载、运行方式和卸载。安装来源接受 npm 包名、npm 页面、Git 仓库、仓库子目录，以及 `npm:包名@版本`、`git:github.com/组织/仓库@标签`。Agent 使用已有 `extensionManage` 工具，安装继续经过所有者审批。

## 原生 Pi 运行方式

Desktop 设置中选择“原生 Pi（含终端）”。新配置默认使用该方式；没有 mode 字段的旧配置保留服务器运行方式，避免改变现有工具入口。Desktop 与 Web 设置页均可切换，修改后从下一轮任务生效。

原生交互需要已连接的 Desktop 客户端。没有客户端时，扩展的选择、确认、输入、自定义界面和编辑器请求立即失败；交互期间客户端超过 5 秒未续接，或单次交互超过 5 分钟未结束，任务会停止并保留副作用核对要求。没有交互请求的原生任务不受客户端在线状态限制。Web 与 Telegram / 飞书等渠道不能直接回答终端界面，可以在 Web 设置中切换到服务器方式。

让 Agent 使用已安装的扩展，或发送扩展的 `/命令 参数`。Agent 通过 `piExtensionRun` 在官方 Pi 1.4 交互式运行时中执行任务；扩展命令也有直接入口，不需要额外请求主模型。标准选择、确认、输入与编辑在任务所属的 Desktop 聊天中弹窗，保留扩展的原始选项与取消语义。LCU 的应用授权使用这条标准选择接口。自定义组件继续使用官方终端；仅在当前会话有自定义交互或待核对中断时显示入口，首页、设置和其他会话不常驻显示。后台自定义终端不抢占聊天焦点。切换页面或会话会保留未提交的弹窗草稿，提交、取消或请求过期后清理。侧栏对应 Agent 显示待确认／需核对标记，点击返回所属会话；“稍后处理”仅收起弹窗，不默认批准或拒绝。隐藏面板保留任务，可以再次打开；“停止任务”取消当前执行，Esc 由终端处理。

扩展工厂、组件和回调留在独立子进程。包的多入口、glob 排除、skills、prompt templates、themes 由官方资源加载器处理；npm 安装保留完整依赖布局；Git 子目录借用父目录依赖（包括 npm workspace）时，同样保留依赖所在的完整布局。配置中已保存的扩展 flags 传入原生运行时。扩展代码属于所有者信任代码，进程隔离不是操作系统权限沙箱。

启用的原生扩展通过完整 `piExtensionRun({prompt})` 入口直接提供给主模型，动态提示词列出实际可用扩展及用途。以 `@pi/扩展ID 任务` 或开头“使用／调用 扩展名”“Use 扩展名”明确指定已启用扩展时，共享 Runner 在主模型选择工具之前绑定 `piExtensionRun`；否定、引用和诊断性问句不作为这类执行指令。明确选择的 ID 不可用时直接报错，不启动替代执行。其他自然语言仍由模型根据目录选择。扩展失败会结束当前轮次，阻止尚未开始的后续工具和模型请求，不自动改用脚本或独立 MCP 客户端。扩展授权必须由用户应答。

扩展工具返回的图片先作为观察内容，不会自动发送到聊天。工作缓存保留最近 8 张、合计最多 24 MiB 的观察图，旧图会被淘汰，连续观察不会因累计张数失败。原生任务用 `molibot_deliver_images` 选择最终交付图片后，再通过当前渠道的附件工具发送；未选择时明确报告没有图片交付。单张上限 8 MiB。进入原生 Pi 会话的观察图超过 700 KiB 编码时保持像素尺寸并转为 JPEG（长边上限 2560px）；单次模型请求只重发最新的、合计不超过 800 KiB 的观察图，更早的图在请求中替换为文本说明，避免上游网关拒绝过大的模型请求体。损坏文件拒绝；纯色或透明图片可用于普通图像交付，选择为截图时则提示目标窗口尚未核实。像素检查不能证明捕获的是用户指定的窗口。部分附件发送失败时保留已交付回执，不应重跑原生任务。

原生模型目录包含已配置的内置与自定义服务商聊天模型，扩展可切换模型；请求仍经过当前 Molibot 任务的权限、审批、预算及用量记录。默认基础工具代理当前任务的受控工具。扩展自行注册的 Provider 留在子进程，通过宿主准入和用量回报接口执行，不复制宿主 Provider 凭据。扩展直接执行的本地代码和网络请求仍具有其进程权限。原生进程明确继承宿主 HOME、代理、证书路径和时区等网络及区域设置；不会创建独立 HOME，也不会复制整个宿主环境。

终端内容区固定使用 Pi 官方深色主题与匹配的 ANSI 配色，作为应用明暗主题的内容区例外；面板控件继续跟随应用主题。

## 会话与中断

原生 Pi 使用绑定当前 Molibot 会话的独立官方 JSONL 上下文。主会话保留兼容工具的结果与执行归属；两者不是同一份历史。原生生命周期发生在兼容任务内，不在主 Agent 每轮重复触发。

普通失败、停止、崩溃或长审批挂起可能留下未完成的原生上下文。失败与需要核对分别记录；模型失败不代表此前没有副作用。系统保留记录并阻止自动重试。检查已执行的操作后，在终端面板点击“已核对，下次用新上下文”；下次任务使用新上下文，旧记录保留。服务重启后也会发现待核对的任务。

原生文件保存在 `DATA_DIR/pi-native/<会话标识的 SHA-256>/`。移入回收站时保留；永久清除或回收站保留期到期清除时，同时删除 JSONL、状态、核对记录与内存终端输出。仍在执行或初始化的原生任务会阻止清除，停止后由清理重试处理。手动备份、搬迁完整数据目录时应包含 `pi-native/`；它不是主会话历史，单独导出主会话不能代替备份该目录。

结束任务时等待官方 `session_shutdown`，清理阶段独立记录。取消时给子进程最多 15 秒清理；超时强制结束并保留核对要求。普通扩展的回调结束不能单独证明操作系统共享已释放。

LCU 在 macOS 可安装 Molibot 的自动停止增强：正常完成、失败或取消后，先查询本轮活动应用，逐个发送带原始 session／turn／app 身份的 Stop，再查询确认本轮应用列表清空，最后结束回合和关闭连接。下次任务仍可正常重新打开应用共享；不撤销系统长期权限，也不停止其他任务或程序的共享。只有收到该核验回执才显示“本轮共享已停止”。

停止或回合结束超时时，任务失败并保留仅供清理的连接。“重试停止共享”复用原始身份，不调用模型、不重跑任务。清理未确认前不能直接允许新原生上下文或永久清除；服务重启后若连接已丢失，只能先检查系统共享指示并手动停止，不能声称仍可自动重试。

增强通过受版本校验的适配覆盖层接入，官方 LCU 文件保持不变，受管理入口修改前备份。覆盖层固定 LCU 发布目录和辅助模块版本；升级 LCU 后需要重新生成。命令为 `node scripts/runtime/install-lcu-auto-stop.mjs <受管理扩展目录> <LCU发布目录> <Molibot目录>`。入口或覆盖层存在自定义编辑时拒绝覆盖。

宿主审批仍按原有流程处理；任意扩展的 JavaScript 内存续体不能在进程结束后恢复，不自动重放之前的副作用。

## 验证与边界

固定兼容基线为 Pi 1.4.0。真实 Runner 回归覆盖首轮完整入口与扩展目录、失败后的同批工具和模型闸门、有效图片附件交付及空白图片拒绝。标准弹窗覆盖选项校验、重复与过期回复、取消和超时语义；慢 shutdown 与清理异常有隔离回归。Desktop WebKit 覆盖弹窗点击、提交失败重试、连续输入、页面作用域与完成隐藏。已通过本地夹具验证自定义终端组件、真实按键、原生命令与 flags、动态工具、包资源、停止、并发会话限制、审批挂起、重启后的人工核对，以及真实 Runner 的模型预算和用量归属。新增回归覆盖无客户端、断连、应答期限、永久清除、失败核对、模型切换、宿主环境继承和受控 `!` shell；本地模拟 OpenAI 服务验证自定义模型切换后的请求与用量归属。WebKit 覆盖管理页真实安装、保存失败回滚、隔离服务重启、页面重载，以及终端 ANSI、输入、缩放、隐藏重开、停止、中英切换和窄窗。类型检查、Desktop Svelte 检查及 Rust 构建通过。

任意第三方扩展、旧 Pi 版本、外部桌面程序、原生依赖、账号登录和真实模型尚未逐项验收。LCU 等工具仍需满足自身平台与授权条件。终端交互当前在 Desktop 接管，Telegram / 飞书等渠道不能直接呈现任意 TUI。尚不承诺所有版本、所有扩展完全无缝；完整兼容目标与保留边界见 [兼容规格](../requirements/pi-extension-compatibility-spec.md)。

服务器运行方式保留原有接口，见 [服务器接口指南](../guides/pi-extension-runtime.md)。未重启或替换用户正在使用的实例，原生安装包的界面未走查。完整验收由用户按需运行 `pnpm verify:feature`、`pnpm test:ui`、`pnpm test:app`。
