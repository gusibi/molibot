# Pi Codemode 接入验证

日期：2026-10-03。范围：阶段 4A。代码接入和本地验收完成；现有 Molibot 执行边界仍负责产品语义，Pi Durable 正式 Runner 替换属于独立阶段。

## 产品行为

Agent 可以调用 `codemode({ code })`，通过 `await tools.<name>(args)` 组合已授权工具，用 `text()` 输出筛选结果。`ALL_TOOLS`、`searchTools()`、`describeTool()` 只读取当前可用工具；Plan、只读房间和 Mini App 的限制仍生效。原来的直接工具调用继续可用。

每个内部调用以 `<parent-id>:codemode:<ordinal>` 为 invocation ID，经正式 Pi `runToolCall` 进入共享权限、审批、预算和 Trace hooks，再由 ToolRuntime 管理副作用槽、intent 与 receipt。外层只承担脚本编排，不占写工具的槽；任意 Codemode 脚本仍按不可安全重放处理。

审批挂起会结束当前脚本。批准后，模型根据已完成收据重新规划剩余工具调用，不能自动重跑整段代码。成功写入后脚本失败不会撤销写入。内部预算耗尽结束脚本，并使用现有 Runner 的预算收尾流程。

## 隔离与输出

使用 `@earendil-works/pi-codemode@1.0.0` 的正式 QuickJS 引擎，外包独立 Node 子进程。脚本没有直接 Node、文件、网络、凭据、模型或嵌套 Codemode 接口；所有外部操作必须经过注入工具。VM 堆上限 64 MiB，子进程 Node 堆上限 128 MiB；默认脚本截止时间 60 秒，可指定到最多 300 秒。

取消和审批挂起先通过 AbortSignal 收回 SDK 部分输出；2 秒未结束则强杀子进程。外层返回前等待已经发起的宿主工具结束，避免遗留写操作。强制杀进程不能保证回收尚未送出的控制台输出；已落盘的共享工具收据不依赖脚本进程存活。

默认文本上限约 8000 字符，最多约 32000 字符；这是字符近似，非真实 tokenizer 计数。超长完整输出保存在本轮 scratch 目录，返回相对制品路径；图片数据不直接回灌模型。脚本的 store/load 仅在该次执行内有效。

## 机器证据

临时目录、临时数据库、正式 Pi VM 与真实子进程覆盖：批量查询筛选、受限发现、审批拒绝/挂起后剩余步骤、成功写入后脚本失败、并行写入串行执行、预算耗尽、取消后等待宿主工作结束、部分输出保留、无限循环和内存耗尽隔离、输出截断与可读制品、无直接宿主能力及嵌套调用拒绝。

真实 MomRunner 使用确定性模型流执行 Codemode：外层加第一次内部写操作达到两次调用预算，第二次写操作被实际预算 hook 拦截；内部调用进入真实 Trace hooks，随后模型正常完成预算收尾。未调用付费 Provider。

Desktop release 的 runtime 模块复制规则包含 worker；Docker 同样复制 runtime 目录，打包守卫通过。类型检查和生产构建通过。未执行 Docker 镜像构建或真实远端模型验收。

## 同任务输入量对照

相同任务调用两次查询，各返回 100 条记录，仅需要最后一条的 ID：

| 指标 | 直接工具返回 | Codemode 筛选后返回 |
| --- | ---: | ---: |
| 底层查询调用 | 2 | 2 |
| 模型可见的工具结果块 | 2 | 1 |
| 结果文本字符 | 27380 | 7 |

Codemode 返回 `[99,99]`，底层请求次数不变。此测量不包含脚本输入、工具目录、模型策略和真实 tokenizer；直接工具调用也可以并行。因此不据此声称减少模型请求次数或必然降低费用。

## 全量检查限制

源码、脚本、eval 和 Desktop 测试合计 3180 项：3171 通过、7 失败、2 跳过。失败来自 Desktop composer 的模块加载、Provider 图标断言、Python 默认路径断言、Mini App 验证进程、Desktop 审批夹具、外部渠道禁用与所有权测试的冲突，以及 Desktop MCP 页面结构断言。未修改这些无关模块，不能把全量检查报告为全绿。最终改动另外执行相关工具、Runner 与部署守卫回归，共 63 项全部通过；类型检查、生产构建及 diff whitespace 检查通过。

## 修复与审查

外层和内部工具共用写执行槽的嵌套死锁、取消过早返回属于执行所有权与异步竞态问题；在共享包装层解决，装配回归覆盖。输出目录属于路径归属问题，复用正式 RunOutputLayout 并验证当前 workspace 内可读。Docker 部署遗漏以打包守卫覆盖。实现与 spec 双轴复核完成，未发现剩余必修问题；这些问题已有机器守卫，不新增重复长期规则。
