# Desktop 统一窗口 Header 改造规格

日期：2026-10-07。优先级：P1。状态：方案已整理，未实施。本次交付为其他 Agent 的实施规格，不是 UI 改造完成记录。

## Problem Statement

侧栏折叠后，原生红绿灯超出窄导航宽度。当前改造虽然增加了完整窗口材质和内嵌内容容器，但窗口顶栏与页面 Header 分成两行：顶部只放红绿灯和少量按钮，当前标题和页面操作仍留在内容容器内。这浪费高度，也使顶部和左侧在功能和视觉上没有形成完整的窗口框架。

用户需要的是 Codex 截图所表达的布局关系：顶部和左侧组成同一背景框架，正文放在框架上的内容容器里。参考图用于说明结构，不要求逐像素复制 Codex。

## Solution

整个窗口只有一条承载当前页面身份与操作的全局 Header。左侧放原生红绿灯、侧栏切换及既有快捷入口；当前页面或会话标题和对应操作也进入这一行。顶部与左侧共用背景材质、透明度与主题规则。正文容器位于 Header 下方，直接显示正文，不重复页面标题栏。

搜索展开、窄窗口、Inspector 打开、侧栏展开或折叠时仍保持这一结构。正文中的筛选、标签页、说明、成员管理等按功能归属保留；Inspector 的文件路径、关闭等局部操作不冒充全局页面 Header。

## User Stories

1. 作为 macOS 用户，我希望红绿灯有固定空间，以便侧栏折叠后不会被分隔线穿过。
2. 作为桌面用户，我希望顶部和左侧使用同一材质，以便窗口有完整一致的外框。
3. 作为聊天用户，我希望当前会话标题出现在顶部，以便立即知道正在查看哪个会话。
4. 作为外部渠道会话用户，我希望渠道来源仍清晰可见，以便识别只读会话及来源。
5. 作为项目用户，我希望顶部保留会话标题与项目上下文，以便确认当前工作对象。
6. 作为 Room 用户，我希望顶部提供当前会话身份及会话切换、新建入口，以便继续既有团队对话流程。
7. 作为工作区用户，我希望自动任务、技能、Mini Apps、计划和 Agents 页面标题使用相同位置，以便切换页面时布局稳定。
8. 作为用户，我希望页面搜索、文件面板及既有快捷操作进入顶部，以便充分利用窗口栏。
9. 作为用户，我希望正文不再重复全局标题栏，以便获得更多阅读空间。
10. 作为用户，我希望页面内筛选和标签页仍靠近正文，以便理解它们控制的内容。
11. 作为 Inspector 用户，我希望文件路径和关闭按钮留在对应面板，以便明确操作对象。
12. 作为用户，我希望展开或折叠侧栏时顶部控件不跳动、不遮挡，以便保持操作连续性。
13. 作为多主题用户，我希望每种主题保留自己的颜色、圆角和控件风格，以便改造后仍能使用原有主题。
14. 作为深色模式用户，我希望顶部和侧栏透明度一致且文字清晰，以便可靠阅读。
15. 作为减少透明度或低性能模式用户，我希望整个窗口框架一起变为不透明，以便避免只有一块区域改变材质。
16. 作为窄窗口用户，我希望长标题优先截断且操作可达，以便窗口不会产生横向溢出。
17. 作为键盘用户，我希望操作保留可访问名称、焦点和原有快捷键，以便继续键盘操作。
18. 作为中英文用户，我希望切换语言后标题和操作仍正常排布，以便较长文案不会破坏布局。
19. 作为用户，我希望切换页面或 Session 后顶部操作立即对应新对象，以便不会误操作上一个会话。
20. 作为原生桌面用户，我希望空白标题栏可以拖动窗口、按钮可以点击，以便基本窗口操作可靠。

## Implementation Decisions

### 结构与职责

- 共享窗口布局拥有唯一全局 Header、原生控件预留区、左侧导航、正文容器及 Inspector 布局。页面模块继续拥有数据、权限、状态与操作行为。
- 页面向共享 Header 提供标题、辅助上下文及操作内容。优先沿用现有 Svelte 组件组合与响应式模式，选择最小的共享接口；不要新增配置注册表或把页面业务全部搬进布局组件。
- 全局 Header 的所有权和渲染位置必须在共享层解决。禁止通过逐页面负 margin、绝对定位越出父容器或复制另一套标题栏实现。
- 当前聊天、项目、Room 和工作区 Header 的呈现内容迁入统一宿主；原页面的重复 Header 删除。设置页独立布局不在此次迁移范围，不因复用 PageHeader 而被改变。
- 当前窗口材质层和正文容器是实施起点。保留有用结构，修正双 Header 根因；不要退回只让顶部颜色贯通的方案。
- 不改后端、持久化 schema、设置字段或渠道 API，不增加依赖、主题开关或兼容层。

### 布局契约

- 顶栏高度采用现有共享窗口高度 token。若 Room 操作无法在现有高度合理容纳，应先把正文相关配置移回正文或采用既有菜单组合，而不是单独增加一条 Room 全局 Header。
- 原生红绿灯预留区固定，不随侧栏宽度变化。其后为窗口级入口，再后为当前标题及页面操作。窗口级入口不得被页面标题覆盖。
- 当前标题优先展示，长标题可截断；辅助来源保持既有层级。不得为了塞入标题而隐藏全部操作或丢失可访问名称。
- 顶部与左侧共用单一窗口材质。Header 不额外叠加独立白底、模糊或透明度，否则会形成接缝及重复模糊。
- 正文容器从全局 Header 下沿开始，维持既有外侧留白和主题圆角；有 Inspector 时保持主区与 Inspector 的连接关系。
- 删除因原浮动页面 Header 引入的正文顶部额外占位、渐变和重复背景，只保留真实正文需要的间距。聊天消息、项目正文、Room 正文和工作区滚动区域分别核对。
- 页面说明可留在正文顶部；筛选、标签页、文件编辑器路径及面板级工具栏按其控制对象归属。区分依据是操作控制范围，而不是当前组件名称。
- 文件面板和其他 Inspector 的局部 Header 可以存在，但不得再渲染主页面标题或再为红绿灯预留空间。

### 状态、交互与主题

- 切换页面、项目、Room 或 Session 时，全局 Header 与正文使用同一个当前对象来源；旧页面操作不得残留，异步加载期间不得指向旧对象。
- 搜索展开与退出保留当前行为，明确它占据全局 Header 的区域，不形成第二条永久窗口栏。
- 标题栏空白区域及允许拖动的静态文本支持原生拖动；按钮、输入框、下拉菜单、搜索结果和弹出层不触发拖动。维护原有 Tauri 权限与层级契约。
- 所有主题使用同一布局。颜色、材质、圆角、边框、阴影和控件样式由现有语义 token 与主题区域规则控制；禁止写死浅色背景或复制某一个主题的外观。
- 检查 Header 从正文区域迁入窗口区域后的主题角色，尤其是强调色控件、透明材质主题和 Brutalism。不得借此次改造抹掉主题本来的方角或阴影风格。
- 低性能、减少透明度、提高对比度模式对整个窗口材质一致生效。原生窗口失焦效果依旧遵循已有规则。

### 详细实施顺序

1. **确认起点**：查看当前未提交改动，保留其他任务的编辑。列出聊天、项目、Room、工作区各自标题、来源、搜索及操作；标明全局或局部归属，并检查历史窗口拖动和层级问题。
2. **先更新设计契约**：在共享设计规范中把“页面 Header 留在内容容器内”修正为“页面身份及页面级操作由唯一窗口 Header 承载”；同步清理旧的浮动 Header、额外控件预留和高度描述，保留独立设置页规则。
3. **建立共享宿主**：让窗口框架渲染完整顶部 Header，统一原生预留区、窗口入口、标题和操作区域。明确页面提供内容的接口，以及切换对象时响应式更新和卸载行为。
4. **跑通最小端到端**：先接通普通聊天的真实标题、来源、搜索、Mini Apps、文件面板及运行状态入口。移除原聊天 Header 与正文多余顶部占位，验证原有操作仍作用于当前 Session。
5. **同一改造内迁完相关页面**：接通项目会话、Room 和所有工作区页面。保留项目上下文、Room 会话选择和新建行为，清理重复标题和为旧 Header 保留的 CSS。不能以“其他页面以后再改”交付。
6. **接通正文与 Inspector 几何关系**：检查文件面板、执行及计划 Inspector 的开关和宽度拖动，保留局部工具栏；确认正文首屏没有遗留空行，底部输入框和独立滚动行为正常。
7. **完成主题与窄宽度适配**：逐主题核对共享背景及 Header 区域角色；检查中英文、长标题、折叠侧栏、搜索展开、Inspector 打开和透明度相关模式。使用既有组件的菜单能力处理必要溢出，不创造新产品功能。
8. **验证与对抗式审查**：按下面的可观察验收执行测试、诊断、构建及冷路径。特别尝试快速切换对象、点击最左/最右操作、拖动空白区域和窄窗口，查找旧操作残留及遮挡。
9. **交付**：更新功能实施记录与高层变更摘要，给出代表性截图、检查结果及未验证项；不得把浏览器预览描述成原生拖动或系统材质已验证。

以上顺序是开发依赖顺序，不是允许保留多页面布局不一致的分批交付。

## Testing Decisions

主验证边界为 Desktop 真实共享窗口入口：从侧栏进入页面，再操作顶部 Header 并观察正文或面板变化。优先复用现有桌面聊天 UI、项目导航和 Room 交互验证，不为每个页面建立新的测试入口。

此测试边界是本规格的建议，尚未单独取得用户确认。接手 Agent 应在实施说明中明确采用的边界；如调整会实质改变验收范围，才需要确认。

好测试验证用户可观察行为：当前标题、操作对应对象、单行全局 Header、点击有效、滚动与布局关系。不得只用源码正则确认某个 class 或 wrapper 存在，就宣称架构和交互正确。现有源码结构测试可以辅助防回退，但真实交互和原生验证不可被替代。

### 必须验收

- 普通聊天、外部渠道只读聊天、项目会话、Room，以及自动任务、技能、Mini Apps、计划和 Agents 工作区都只有一条全局页面 Header。
- 当前标题和页面级操作位于原生红绿灯同一顶部栏；正文不再保留第二条主页面标题栏，顶部没有空置的独立窗口栏。
- 切换页面和 Session 后，标题、来源及操作对象一致；搜索、文件开关、项目设置、Room 会话选择/新建等既有行为不变。使用隔离数据验证会产生写入的操作。
- 侧栏展开/折叠、Inspector 开关及面板拖动不遮挡原生控件，正文和面板无横向溢出、错误高度或重复顶部占位。
- 所有现有主题逐一检查明暗模式的顶部/左侧背景一致性和 Header 可读性；代表性的透明、强调色及 Brutalism 主题补充完整交互检查。
- 至少检查现有最小窗口宽度和正常桌面宽度、中英文、长标题、搜索展开及 Inspector 同时存在。操作可达，焦点可见。
- 低性能、减少透明度和提高对比度下，顶部与左侧材质一致；无透明叠层导致的额外色差。
- macOS 原生窗口验证红绿灯、空白拖动、按钮点击、输入框和菜单交互；浏览器预览只能验证 Web 布局与交互。
- 相关现有测试、Svelte 诊断和生产构建通过。既有无关警告明确记录，不冒充新回归。
- 使用隔离实例走冷路径：重启服务、首次打开受影响面板、切换页面/Session、服务中断后恢复。不要中断未经授权的用户服务；无法完成的必需原生或恢复检查明确列为未完成。

## Out of Scope

- 缩小或重绘原生红绿灯、采用飞书式加宽导航、逐像素复刻 Codex。
- 修改导航信息架构、主题种类、聊天业务、Composer、消息样式、权限及后端数据模型。
- 全面重做设置窗口、Inspector 编辑器或全部页面内工具栏。
- 新增窗口栏配置项、依赖、兼容模式、迁移或临时逐面板补丁。
- 自动委派其他 Agent、发布 issue、提交代码或创建 PR；本次用户要求仅为本地文档交接。

## Further Notes

- 当前共享材质与内嵌正文框架已存在，最新的“页面 Header 上移”尚未实施。之前的浏览器主题检查和测试结果只证明旧版本，不证明本规格已验收。
- 共享设计规范中仍有旧 Header 位置描述。实施前必须修正；本规格明确记录用户最新要求，不将旧文档视为保留双 Header 的理由。
- 已有 Room、项目文件面板和主题规范继续约束各自行为；本规格只取代其主页面 Header 的呈现位置，不取代局部功能需求。
- 原生拖动历史问题属于层级和事件命中范围错误。只检查拖动权限或 DOM 属性无法拦住遮挡；本次应同时验证空白可拖动和交互控件可点击。
- 本规格按用户要求保存在项目文档中。任务跟踪器和 triage 配置未提供，未发布 issue；将来若使用技能的 issue 发布流程，需要先运行 `/setup-matt-pocock-skills`。
