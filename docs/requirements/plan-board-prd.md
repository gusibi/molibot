## 1. 当前问题

当前会话计划由 `exitPlan` 生成，步骤保存在聊天消息的 `ConversationPlan` metadata 中。`PlanCard.svelte` 在聊天卡片内使用多行文本编辑步骤；`SessionPlanInspector.svelte` 已提供右侧进度视图，但未提供完整编辑体验。

接受计划后，权限按用户选择切换为 `manual` 或 `accept_edits`，客户端在当前 Session 继续模型执行，通过 `updatePlan` 更新步骤。现有 `durableExecutionId` 读取与投影代码不能证明创建关联链路已经接通；当前接受入口没有建立该关联。

独立的 Durable Execution 已有 SQLite 存储、版本校验、执行租约、attempt、证据与恢复机制，可作为复用基础；其当前交付边界以能力矩阵为准，不能据此声称计划模式已实现跨会话可靠续跑。

需要解决的问题：

1. 修改步骤依赖聊天卡片中的整段文本，难以调整局部内容、顺序和执行中的剩余工作。
2. 缺少统一列表；生成后未执行的计划、暂停的计划和历史计划难以找回。
3. 缺少可供跨 Session 准确引用的计划身份和继续执行入口。
4. 进度查看依赖现有聊天更新路径，跨会话、重新打开与断线恢复的行为未形成完整约定。
5. 长计划需要分层表达、分步执行和结果验证，不能仅靠模型打勾宣布完成。

## 2. 目标与非目标

### 目标

- 每份已保存计划具有稳定 ID、可读名称和统一列表入口；未批准执行也能找回。
- 右侧面板承载完整编辑、进度、结果入口及执行控制，聊天保留摘要与必要决策。
- 支持任务（Task）→ 子步骤（Step）两层结构；同一视图可展开查看，无需进入二级详情页。
- 支持从 A Session 执行、暂停或中断后，在 B Session 找到同一计划并继续。
- 进度与完成依据来自持久化执行记录和验收结果；面板关闭、切换会话不影响执行生命周期。
- 计划只在 Session 中生成和保存，不存在从计划列表直接新建空计划的入口。
- 计划列表与右侧面板为桌面 App 专享；外部渠道不提供计划管理。
- 生命周期：用户可主动删除计划，完成后自动归档，未完成的计划保留。
- 后续支持 100 个任务、约 400 个步骤的创建、浏览与续跑；不将该规模作为首个端到端版本的前置条件。

### 非目标

- 不做任意嵌套、通用 DAG、并行依赖调度；执行保持线性。
- 不做多人协作、指派、评论、项目管理排期或跨设备同步。
- 不建立第三套执行引擎，不为每个计划强制建立文件目录。
- 第一版不要求多列看板或列表虚拟化；根据实际体验与测量决定后续实现。
- 不提供从计划入口新建空计划的能力；计划只能由 Session 生成。
- 不在外部渠道（Telegram、飞书等）提供计划列表或详情面板。
- 不新增任务级预算的展示与控制；预算沿用既有 Session／执行层处理。

## 3. 产品结构与职责

| 部分 | 职责 |
|---|---|
| 统一计划列表 | 找到已生成计划，搜索、筛选并查看状态与进度 |
| 右侧计划面板 | 编辑结构、查看当前步骤与证据、暂停、继续、取消 |
| Session | 讨论和生成计划，承接某次执行的工具活动、结果与用户反馈 |
| 共享计划服务与执行器 | 持久化、修订校验、权限、调度、验证与恢复 |

UI 与模型工具通过同一共享服务修改结构化计划，不解析模型自然语言或 Markdown 作为进度真相源。自然语言修改请求先转为结构化修订，再经校验应用。跨会话关联、恢复与去重属于共享上层，不放入 Channel 层。

## 4. 执行架构建议

推荐复用 Durable Execution，在现有数据库与 coordinator 边界中补齐计划草稿、修订、查询、执行关联及事件读取能力。计划保存和开始执行是两个动作：未开始的计划也必须落库，但不能因保存自动排队或运行。`exitPlan` 产出的计划保存后处于“未开始／待批准”，不自动执行。首次点击“开始”须批准当前内容版本并选择执行权限；只有已经启动且安全停下的计划才显示“已暂停／继续”。恢复入口不能绕过首次批准。

先用一个小计划跑通创建、编辑、执行、暂停、跨会话恢复和验证，再扩展规模。不要先交付依赖原会话循环的独立面板进度，随后再重接执行真相源。

复用并不意味着接入成本低；创建关联、草稿生命周期、修订与运行中 attempt 的边界都需要验证。轻量平行计划库不作为本方案的分期实现。

本方案扩展了现有 `DESIGN.md` 中“面板只查看进度、在原 Session 执行”的约定。`DESIGN.md` 是其他 agent 改动本 App 的共享说明，因此本改动必须在同一 slice 内同步更新该设计条目，明确面板可编辑、执行可显式关联新 Session，而面板本身不拥有独立对话；否则其他 agent 会按过期约定实施。权限模式文档继续负责权限语义，长任务 PRD 继续负责执行语义；本文补充计划入口、编辑与会话关联，不替代这两份文档。

## 5. 标识、归属与会话关联

### 5.1 计划身份

| 字段 | 约定 |
|---|---|
| `planId` | 服务端生成的稳定唯一标识，改名、修订、换 Session 均不变 |
| `title` | 可读名称，允许同名；选择时同时显示项目、更新时间与可区分的 ID |
| `ownerId` | 所属用户；所有查询与操作都校验访问权限 |
| `projectId` | 可选的所属项目，支持无项目计划 |
| `sourceSessionId` | 初次生成计划的来源，提供返回入口；来源不可访问时计划仍可读取 |
| `currentPlanVersion` | 当前计划内容版本，用于修订与执行依据追踪 |
| 执行关联 | 记录执行实体及历次承接 Session，保留来源和续跑历史 |
| 时间字段 | 创建与最近更新时间，供列表排序与识别 |

ID 是身份；名称供阅读；目录是执行上下文。计划不以目录或文件路径作为主键。界面允许复制完整 ID 或计划引用；链接与工具操作解析为同一个 `planId`。短标识仅供展示，不依靠可能重名的标题执行操作。

实施时若 Durable Execution 的聚合 ID 能覆盖未执行计划的生命周期，可直接复用为 `planId`；否则建立明确关联，不能产生两套独立进度。

### 5.2 执行上下文

计划保存目标、输入引用、工作目录、验收要求及已完成结果。跨 Session 继续时保留这些信息，不自动套用新会话的项目目录或输入。工作目录或目标的变更属于计划修订，须显示影响；项目或权限不匹配时拒绝执行并说明原因。

新 Session 接收计划版本、执行摘要、当前步骤与所需结果引用，无需复制旧聊天全文。执行权限须按当前授权核验，不能利用跨会话继续绕过原有审批。

## 6. 数据与状态

### 6.1 两层结构

```text
Plan：翻译产品文档
 ├─ Task：入门指南                 2/4
 │   ├─ Step：读取原文             已完成 → 输入记录
 │   ├─ Step：整理术语             已完成 → 术语文件
 │   ├─ Step：翻译                 进行中
 │   └─ Step：检查并保存           待执行
 └─ Task：API 指南                 0/3
```

Task 与 Step 都有稳定 ID；排序或改名不能通过数组位置重新分配身份。普通任务可以有不同的步骤；批量同类任务可使用模板展开。

### 6.2 状态与进度

- 步骤状态与证据持久化；Task 的完成数量、结构进度由其步骤汇总，不维护第二套可独立写入的完成标记。
- Plan 的完成数量可汇总，但运行、排队、暂停、等待授权、等待用户、恢复中等状态来自执行器；不能仅由步骤推导。
- 草稿／待批准属于计划生命周期，须与执行状态区分。列表的“未开始”可聚合这些状态，但详情显示具体原因与可用操作。
- 进度显示“已完成 7/20 步”，不将步骤比例解释为时间比例。跳过的步骤单独计数，不能冒充完成；计划修订改变总数时显示版本与变更说明。
- `completed` 由验证流程决定。证据不足或执行结果不确定时不能计入已完成；需要用户验收时显示等待确认。

### 6.3 存储

在 `durable-execution.sqlite` 中复用已有聚合与版本记录，按需扩展任务归属。具体表结构在实施设计中确定，须支持稳定任务 ID、步骤顺序、草稿、版本及证据引用；不复制任务标题到每个步骤作为唯一归属依据。

所有变更经共享服务校验版本与状态。遵循项目不保留兼容层、不写 migration 的规则；现有数据的处置方式是实施待决项，本 PRD 不授权删除用户数据。

### 6.4 生命周期与保留

- 用户可主动删除已停止的计划。运行中须先取消，待执行器确认停止、释放执行权并关闭待审批／待调度操作后才允许删除；暂停请求尚未生效时不能删除。删除与启动／恢复互斥，迟到结果或旧审批不能重新启动、恢复或重建已删除计划。
- 删除移除计划及其所属结构、版本和执行记录，不删除已经生成的文件，不撤销外部副作用；共享记录不级联删除。操作前说明删除范围。旧聊天卡片或计划引用再次打开时显示“计划已删除”，不能恢复执行。
- 仅在执行器完成全部必需验收、确认整个计划为 `completed` 后自动归档；步骤执行完但仍等待人工验收或授权的计划不归档，继续出现在“需要处理”。归档是独立属性，不替代执行状态；归档计划可在归档视图查看。
- 未完成的计划（草稿、暂停、中断、失败、等待）一直保留，不自动清理。
- 来源 Session 被删除或归档不连带删除计划（沿用 `session-management-spec.md` 对 Durable Execution 的口径）；详情仍可读取，来源入口失效时隐藏。

## 7. 共享接口能力

以下名称描述能力，实施时优先复用现有工具与 API，不要求机械增加同名工具。

| 能力 | 行为 |
|---|---|
| `planCreate` | 保存名称、任务及各自步骤，返回稳定 ID；不自动执行 |
| `planList` | 按授权范围列出计划摘要，支持搜索、状态、项目筛选与分页 |
| `planRead` | 按 ID 读取计划版本、状态、步骤、上下文和证据；大计划支持范围读取 |
| `planRevise` | 按预期版本提交结构化修订，保留已完成结果与旧版本记录 |
| `planAddTasks` | 批量追加任务；模板展开由代码完成，并遵循修订规则 |
| 删除 | 仅允许已停止且无可执行待处理操作的计划；与启动／恢复互斥，明确删除范围，重复请求幂等，保留产出文件 |
| 开始／暂停／继续／取消 | 经 coordinator 校验权限、状态、租约和请求幂等性；继续可指定当前 Session |
| `planNext` | 由执行器选择下一可执行步骤，返回聚焦输入；读取不会获得第二份执行权 |
| `planMarkStep` | 提交结果与证据或失败原因，由验证器判定完成，模型不能直接宣布完成 |
| 进度读取与订阅 | 提供快照、版本及增量更新，支持重新打开与断线恢复 |

UI 编辑与模型修订走相同规则。版本冲突返回明确结果，不静默覆盖；名称检索命中多个计划时必须选择具体 ID。

## 8. 执行、暂停与跨 Session 续跑

### 8.1 执行与验证

执行器按顺序取步骤，为 attempt 提供本步输入与必要简报；保存结果与证据后验证，再推进下一步。任务分组不引入并行依赖调度。

文件存在且非空只能证明产物存在，不能证明翻译或写作质量合格。验收需结合任务约定的内容检查、确定性 checker 或人工确认。模型只提交待验收结果；无法证明完成时显示不确定或等待验收，并提供原因与处理入口。

### 8.2 跨会话继续流程

1. 用户在 B Session 打开统一计划列表，选择在 A Session 生成的计划。
2. 面板展示计划 ID、版本、已完成步骤、当前中断点、下一步和原执行上下文。
3. 点击“在当前会话继续”，服务端核验当前版本批准、授权与可恢复状态，原子取得该计划的独占执行权并关联 B Session；取得失败不改变承接关系。
4. 后续执行活动与反馈进入 B Session；来源 A 与过往执行记录仍可追溯。

继续使用同一计划及进度，不复制计划，不从头执行。若同一计划正在别处运行，仅提供状态与查看入口；需先让原执行者安全停止并释放执行权，再由新 Session 接续，不能启动第二个执行者。查看计划本身不改变承接 Session。

各 Session 独立，不同任务允许同时执行；其他任务正在执行不阻止本计划执行。目标 Session 忙碌不作为拒绝继续或强制等待其他任务结束的条件，允许本计划抢占执行调度。抢占不能串用其他任务的上下文、结果或进度，也不能把其他任务误标为完成或取消。每次执行的事件与结果按任务身份及承接 Session 路由。

独占约束以计划为单位：同一 `planId` 在任意时刻最多由一个 Session 执行，不是整个系统或每个 Session 只能执行一个任务。抢占不能绕过同计划执行租约，也不能抢走尚未安全停止的同计划执行权。

### 8.3 暂停与中断恢复

- 暂停请求先显示“正在暂停”，到安全边界后才显示“已暂停”；尚未停止的工作不能视为可修订。
- 同一计划同一时间只有一个执行者。重复点击、并发 Session 继续、恢复重试均须在共享层去重。
- 已确认完成且未被修订影响的步骤保留结果，不重复执行。
- 中断步骤若可能已产生外部副作用，先核对回执或外部状态；无法核对时等待用户处理，不能盲目重复发布、发送或写入。
- 服务重启后恢复真实状态；不能恢复的计划显示原因与处理入口，不承诺无条件自动续跑。
- 关闭面板或切换会话不等于暂停。取消须显示生效状态及已经产生的结果，不声称撤销已完成副作用。

## 9. UI 与编辑交互

### 9.1 统一计划列表

提供固定“计划”入口（桌面 App），不要求找到原聊天卡片。已生成并保存的计划立即进入列表，包括未批准、未开始、运行、暂停、等待和已结束计划。计划只能由 Session 生成，列表不提供新建空计划入口；外部渠道不提供该列表。

列表展示名称、所属项目、具体状态、完成数量、当前步骤／等待原因和最近更新时间；支持名称或 ID 搜索、项目筛选，以及“全部／未开始／进行中／需要处理／已结束／已归档”筛选。“需要处理”聚合暂停、中断、失败和等待确认，但每行保留具体原因。跨项目显示仅限用户有权访问的计划。完成的计划自动归档，默认不占用「进行中」，可在「已归档」查看；未完成的计划一直保留。列表支持用户主动删除计划。“需要处理”的提醒复用现有审批与通知流程，不新建通知通道。

点击计划打开右侧详情。列表入口负责找计划；详情显示历史已结束计划的结果，不能对已完成计划直接提供恢复按钮。返工通过修订新增工作表达：保留同一 `planId` 与历史结果、证据，保存新内容版本后退出归档并进入“未开始／待批准”；重新批准后只执行新增或明确要求重做的步骤，不能重跑未受影响的已完成步骤。保存返工修订不自动执行。

### 9.2 右侧详情面板

默认使用按执行顺序排列的分层列表，任务内嵌可展开步骤；不因状态变化自动重排任务。顶部展示名称、状态、版本、总进度、当前动作和最后更新时间；提供定位当前步骤与结果／证据入口。筛选或更新不应无故丢失滚动位置、展开项和编辑草稿。

底部固定操作区按状态提供编辑、保存、开始、暂停、继续、取消或验收操作。保存和开始执行分开；单纯保存不运行。操作提交期间防重复点击，失败保留草稿并显示原因。

多列状态看板作为后续可选视图，不作为默认布局或第一版验收要求。

### 9.3 修改计划

- 执行前：支持改标题、任务、步骤和验收要求，新增、删除、调整顺序；保存／放弃修改有明确入口。
- 执行中：允许准备剩余工作的修订草稿；应用修订前在安全边界暂停并核对版本，避免执行器继续领取旧步骤。
- 已完成步骤的正文、结果和证据不能被改名替换成另一项工作。需返工时新增步骤；修订影响已有结果适用性时，明确列出受影响结果与需重做的工作，保留历史证据。
- 自然语言修改：例如“后面的翻译改成日语”，先显示新增、删除、修改范围及执行影响，用户确认后保存。请求本身不直接批量覆盖计划。
- 实时进度与编辑草稿分离。保存时校验内容版本与运行状态；冲突时展示差异并允许重新应用，不能静默覆盖任一方。
- 关闭面板或切换计划时，未保存修改不得静默丢失：保留草稿或提示保存／放弃。

### 9.4 聊天摘要与决策

聊天展示计划名称、状态、进度和“查看计划”入口。待批准时保留接受／修改／拒绝决策，修改打开面板；批准绑定当前版本，过期卡片须先刷新，不能执行旧内容。聊天与面板操作同一计划，不维护两份编辑内容。

### 9.5 实时更新与恢复

打开面板先获取最新快照，再接收增量事件。快照与订阅之间须有版本／游标衔接或补读机制，避免漏更新；丢弃重复和过期事件，不能让旧状态覆盖新状态。

计划监控不能依赖当前聊天流仍然打开。关闭后重开、切换 Session、网络重连都须补齐最新状态；显示断线状态与最后更新时间，不把旧进度伪装成实时状态。列表与详情使用同一真相源，接收更新后进度一致。

### 9.6 响应式与设计约束

复用共享 Inspector 的流内布局与宽度约束，桌面优先常驻右侧；窄窗采用单列或全屏详情并保留返回入口。不能用固定悬浮层绕过现有窗口拖拽区域约束。

沿用 `DESIGN.md`、共享语义 CSS、主题 token 和已有 shadcn-svelte 组件；适配中英即时切换、明暗主题与移动宽度。状态不只靠颜色区分。宽度持久化若涉及 settings，必须验证 save → 新 store → load 的整对象回归。

## 10. 规模策略

批量同类任务可输入任务列表与步骤模板，由代码展开；普通任务支持各自不同步骤。计划总步骤数不受原有 30 步上限约束，生成、保存、编辑、读取和执行各入口均不得静默截断。单次批量请求仍可有数量与输入大小限制；超限须明确报错并允许分批提交，不能截断后返回成功。大计划不要求模型每次读取全部节点。

先用任务折叠、搜索、状态筛选与范围读取控制展示量；保留单任务展开能力。以 100 任务、400 步实测创建、滚动、编辑和实时更新，再决定是否需要虚拟化，不能仅凭 DOM 数量预先强制复杂实现。

执行始终分步持久化，复用已有排队与恢复规则；任务级预算与配额沿用 Session／执行层既有处理，本 PRD 不新增其展示或控制。实际耗时与成本包含模型调用、工具执行、重试和验收，不等于一次对话成本。

## 11. 分期与第一版范围

| 阶段 | 交付 | 复杂度 |
|---|---|---|
| P1 最小端到端链路 | 稳定 ID、保存与读取、小计划列表和右侧详情、基本修订、接通 Durable Execution、实时状态、暂停及跨 Session 继续、结果验证 | 中高 |
| P2 第一版交互完成 | 完整两层编辑、自然语言修订预览、冲突处理、列表搜索筛选、删除与归档保留、断线补齐、阻塞处理、结果入口、中英与主题适配 | 中高 |
| P3 规模化 | 批量模板、100 任务／400 步验证，按测量优化读取与渲染；多列看板按需求另行评估 | 中高 |

第一版验收范围为 P1 + P2。P1 用小计划验证完整架构，不作为缺少编辑与恢复体验的最终交付。两层结构能力属于第一版，400 步规模验证属于后续阶段。

## 12. 风险与实施待决

- Durable Execution 复用是推荐架构；实施前落实草稿、修订和执行聚合的关系，不把已有测试当作新接入链路的验证。
- 确定 `planId` 是否直接复用聚合 ID、任务表结构及现有数据处置；不引入兼容层或 migration，不隐含授权破坏性数据操作。
- 按现有事件机制确定快照与增量的游标衔接方式；不能只沿用聊天 SSE 名称就认为完成跨会话订阅。
- 安全暂停与外部结果核对受工具能力限制；无法核验的非幂等操作必须暴露等待处理状态。
- 线性调度是本期边界。未来并行或 DAG 需要独立决策，不能由任务分组暗中引入。
- 在同一 slice 内同步相关 DESIGN 约定（它是其他 agent 改本 App 的共享说明）；功能落地后按实际证据更新能力矩阵和交付记录。此次方案更新不改变当前交付状态。

## 13. 验收条件

### 第一版必须通过

1. **可找回**：生成并保存但不执行的计划出现在统一列表；无需原聊天卡片即可打开。支持搜索与状态／项目筛选，空列表和无匹配结果有明确提示。
2. **身份稳定**：同名计划可区分；改名、排序、修订、换 Session 后 `planId` 不变，Task／Step 不按数组位置串身份。
3. **完整编辑**：面板支持任务与步骤的增删改排序、验收要求修改、保存与放弃；保存不触发执行，自然语言修改先展示范围。
4. **修订安全**：执行中应用修订须等待安全暂停；旧版本不能继续领取步骤。已完成结果不被覆盖，返工有新步骤；进度更新不覆盖草稿，版本冲突明确可处理。
5. **跨会话续跑**：在 A 会话生成并执行部分工作，暂停后从 B 会话列表找到同一计划，核对中断点并继续；已确认完成步骤不重复，后续活动进入 B，来源 A 可追溯。
6. **并发幂等与抢占**：两个 Session 同时继续同一计划、重复点击或请求重试，只产生一个执行者；原执行者安全停止前不能转移该计划执行权。不同任务可独立并发，目标 Session 忙碌不阻止本计划继续，允许抢占调度；其他任务不被误取消或标完成，任务上下文、事件与结果不串用。只查看或认领失败不转移执行关联。
7. **上下文与权限**：换会话保留目标、目录、输入、版本和验收要求；不继承不相干的新项目环境，不绕过审批，不显示无权访问的计划。
8. **真实进度**：完成数与跳过数区分；暂停、排队和等待来自执行状态，列表与详情一致；证据不足不标完成，内容质量要求可进入人工验收。
9. **中断处理**：模拟副作用成功但回执未保存，恢复时先核对；不能证明结果时等待处理，不盲目重做。
10. **实时恢复**：面板关闭重开、会话切换、断线重连及乱序／重复事件后显示最新状态；快照与订阅衔接不漏更新，断线时展示最后更新时间。
11. **交互与适配**：两层同视图可展开；当前步骤与结果可定位；固定操作区可用；中英即时切换、明暗主题、窄窗与窗口拖拽区域均正确。
12. **冷启动**：在隔离实例重启服务，首次打开列表和面板、切换 Session、服务中断恢复均正确；计划、版本、进度和结果保留。
13. **范围与入口**：计划只能由 Session 生成，列表没有新建空计划入口；列表与面板仅桌面 App 可用，外部渠道不可管理计划。
14. **生命周期与提醒**：仅整个计划验收完成后自动归档；步骤做完但等待验收仍出现在“需要处理”。未完成计划保留，操作按批准与可恢复状态提供；等待确认／授权、中断、失败等复用现有通知流程提醒。
15. **首次批准**：`exitPlan` 保存后显示未开始／待批准，不运行；首次开始批准当前版本并选择权限，不能调用继续入口绕过批准。
16. **删除安全**：运行中删除被拒绝并引导先取消；确认停止后可删除，产出文件保留。并发恢复、迟到结果和旧审批不能复活计划；重复删除幂等，旧聊天入口显示已删除。
17. **归档返工**：对归档计划新增返工步骤并保存，ID 与历史证据不变，新版本退出归档并待批准；批准前不运行，批准后仅处理新增或明确重做的工作。
18. **无静默截断**：至少 31 步的计划能完整生成、保存、重读、编辑和执行；超过单次请求限制明确报错，分批提交后所有步骤保留，不静默截成 30 步。

持久化与恢复测试使用临时数据库或可注入 store；行为实施后运行相关测试、svelte-check、build 和真实冷路径走查。无法执行的必需检查明确标为未完成。

### 规模化阶段验收

100 个任务、约 400 个步骤可批量创建、浏览、修订和续跑；读取与渲染按实际性能验证，无明显交互阻塞。是否采用虚拟化由测量决定，不将具体优化技术作为产品验收目标。
