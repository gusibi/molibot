# Pi 人工验收清单

日期：2026-10-04。对应 [能力接入规格](pi-capabilities-integration-spec.md) 和 [生产验证记录](../reviews/pi-production-integration-validation.md)。本文件提供操作用例，不声明人工验收已通过。


可直接执行的文件和操作说明见 [验收包](pi-manual-acceptance-kit/README.md)。将包内 `acceptance` 复制到验收工作区；下列提示词同时保存在包内 `acceptance/prompts/`，标为 `【…】` 的段落是人工操作说明，不要一起发给 Agent。

## 准备与记录

- 使用独立验收实例、独立数据目录和测试 Bot；保留当前日常使用的实例。重启用例只操作验收实例，并使用同一数据目录重开。
- 记录代码版本、Web/Desktop 版本、Provider/model、渠道实例、Session、runId、开始时间。图片功能还包含此前的未提交改动：注明实际工作区版本，不能把它的结果全部归给提交 `2b510ebd`。
- 创建验收工作区，放入 `acceptance/input.txt`（内容为 `PI-ACCEPTANCE-20261004`）和空文件 `acceptance/effects.txt`。每个写操作用例使用独立文件或唯一标记。
- 准备 Web、原生 Desktop、Telegram 测试 Bot/topic、Feishu 测试 Bot，并配置一个项目绑定。渠道不得与日常 Bot 共用接收配置。
- 付费用例由验收者自行决定是否执行，事先限定 Provider 账户可接受的支出。普通对话也可能收费。没有凭据、实际支持的模型或观测条件时，记录“阻塞”，不要记为通过。
- 每例记录：`通过 / 失败 / 阻塞 / 未执行`、实际结果、截图或录像、runId、日志位置、Provider 请求 ID。失败后保留证据再重试，重试使用新的标记。

“界面显示一次”不能证明“远端执行一次”。检查写操作时数文件标记；检查远端提交时看 Provider 请求 ID/请求列表；检查用量时比较恢复前后的同一笔记录。无法独立核对则注明该断言待验证。

## 第一组：正常使用与产品流程

### A01 普通对话和 Session 隔离

- [ ] Web 新建 Session，发送“只回复 `PI-OK-A01`”。完成后切换另一 Session，再切回；原生 Desktop 重复一次。
- 预期：只产生一份最终回答，流式状态正常结束；另一 Session 没有串入消息；刷新后原回答仍在。
- 证据：两个 Session 的界面和原 runId。

完整提示词（多个变体分别发送）：

```text
本轮不要调用工具，只回复以下一行，不添加说明：
PI-OK-A01

【另一个新 Session 的提示词】
本轮不要调用工具，只回复 PI-OTHER-A01。
```

### A02 工具读取与完成记录

- [ ] 发送：“读取 `acceptance/input.txt`，原样输出内容，不修改任何文件。”
- 预期：结果为准备的标记；工具过程/Trace 可查看；完成后没有持续忙碌或遗留审批。
- 证据：回答、工具调用及文件内容。

完整提示词（多个变体分别发送）：

```text
请用读取文件工具读取当前工作区 acceptance/input.txt，完整原样输出文件内容。不要凭提示猜测内容，不修改文件。若不能调用读取工具，明确说出原因。
```

### A03 计划批准与执行

- [ ] 请求先提出计划、等待批准，再读取 input、生成 `acceptance/plan-result.txt`。核对待批准计划后批准，通过现有入口查看进度和结果。
- 预期：批准前不写文件；批准后执行已批准内容，结果归属原计划和 Session；工具完成不会直接替代需要用户确认的计划验收。
- 证据：批准前后的文件状态、计划内容/版本、进度和验收状态。

完整提示词（多个变体分别发送）：

```text
请使用现有计划功能创建一个需要我先批准的计划，本轮只创建计划，不执行写操作。计划内容：1. 读取 acceptance/input.txt；2. 将读取的原始内容保存为 acceptance/plan-result.txt；3. 读取结果文件核对。请保留计划与当前 Session 的关联，等待我通过计划批准入口批准。完成工具执行后给出验收证据，不代替我确认产品验收通过。

【若入口需要文字确认，批准后发送】
我批准刚才显示的计划版本，请执行已批准内容。
```

### A04 排队、插入与停止

- [ ] 让 Agent 执行一个可观察且耗时约 20 秒的本地测试任务；运行中发送第二条任务，再用现有插入功能补充指令。另起一次任务测试 Stop。
- 预期：排队任务不丢失、不重复；插入指令作用于当前任务；Stop 后不启动新的后续操作，队列和运行状态能结束。已发生的操作不宣称被撤销。
- 证据：消息时间线、执行顺序、运行列表和副作用标记。

完整提示词（多个变体分别发送）：

```text
这些命令用于执行验收脚本，先走普通 Bash 路径；hostApproval 应省略或设为 null，不要填空审批对象。timeout 的单位是秒，可填 120。若 sandbox 实际拒绝访问，报告限制并按现有权限流程处理。命令尚未启动时不要宣称排队或 Stop 验收完成。

请通过 Bash 执行：node acceptance/wait-and-write.mjs A04-first 30
只执行一次。完成后读取 acceptance/results/A04-first.txt，回复执行结果。

【出现 started 后，普通发送第二条】
请通过 Bash 执行 node acceptance/append-once.mjs A04-queued，只执行一次。

【通过现有插入/steer入口发送】
当前任务结束后的最终回答额外加入 PI-STEER-A04，不新增写操作。

【另开一次运行，出现 started 后点击 Stop】
请执行 node acceptance/wait-and-write.mjs A04-stop 60，只执行一次。
```

先确认 `A04-first.started.txt` 出现且第一任务仍在运行，再发送 queued 和插入指令。若 Bash 被参数校验或权限拒绝，记录前置阻塞，不能继续据此判断队列/Stop。

### A05 Runtime 事件触发

- [ ] 用现有提醒/定时任务入口创建一次性测试任务，到时只读取 input 并回复唯一标记。
- 预期：事件触发一次，结果出现在配置的目标 Session/渠道；没有重复任务。任务通过项目运行时事件系统落地。
- 证据：事件记录、runId、目标回答和触发次数。

完整提示词（多个变体分别发送）：

```text
请使用现有提醒/定时任务能力，创建从现在起两分钟后触发的一次性任务，时区 Asia/Shanghai，目标为当前会话。到时读取 acceptance/input.txt，并回复 PI-EVENT-A05 和文件原文。任务必须走 watched event JSON 和运行时事件系统，不写 OS scheduler，也不以普通 memory 代替提醒。请告诉我实际计划触发时间和任务标识。
```

### A06 Web 断线重连

- [ ] 发起含工具调用的任务，完成前关闭页面或断开浏览器网络，再重新打开原 Session。
- 预期：重新展示原任务状态与已提交结果；不因页面重连创建第二份执行；最终回答只保存一次。
- 证据：原 runId、重连后的状态和副作用标记。

完整提示词（多个变体分别发送）：

```text
请通过 Bash 执行 node acceptance/wait-and-write.mjs A06 45，只执行一次。完成后读取 acceptance/results/A06.txt 并回复内容。不要因浏览器连接变化重新执行。
```

## 第二组：审批与恢复

以下请求可使用：“通过 Host Bash 向 `acceptance/<用例编号>.txt` 追加一行 `<唯一标记>`。只追加一次，不自行重试。”须确认实际进入目标审批路径；模型改用其它工具绕开目标路径时，该路径未验收。

### B01 Host Bash 批准

- [ ] 配置为需要审批，发出写操作请求；批准前检查文件，批准后等待完成。
- 预期：批准前无标记；批准后恰好一行；回答和审批归属原 Session/run，审批卡片正常结束。

完整提示词（多个变体分别发送）：

```text
请明确使用 Host Bash 执行 node acceptance/append-once.mjs B01。不要改用文件写入工具或 sandbox 绕开 Host Bash 审批。只调用一次，批准前不执行，执行后读取结果文件并回答。若当前无法产生审批，说明实际路径，不宣称本用例通过。
```

### B02 拒绝、重复点击和晚到批准

- [ ] 拒绝一条请求；另一条在待批准时先 Stop，再尝试原卡片的批准。若界面允许，对已批准卡片重复操作。
- 预期：拒绝/Stop 后无新增标记；重复决定不会再次写入；显示终态或明确无效提示。不能重新发同一条聊天消息来模拟“重复点击”。

完整提示词（多个变体分别发送）：

```text
请使用 Host Bash 执行 node acceptance/append-once.mjs B02-reject，等待审批，不改用其他路径。

【新的任务，用于 Stop 后晚到批准】
请使用 Host Bash 执行 node acceptance/append-once.mjs B02-late，等待审批，不改用其他路径。

【新的任务，用于重复点击】
请使用 Host Bash 执行 node acceptance/append-once.mjs B02-repeat，等待审批，只执行一次。
```

### B03 审批等待时重启

- [ ] 请求写入并等审批出现；重启验收服务，同目录重开原 Session；从原审批记录批准。
- 预期：原请求、Session、actor 和范围保持一致；批准后只执行一次，无需重新发送原任务。若审批无法操作或只显示而不能续跑，判失败。
- 证据：重启前后 runId/审批 ID、文件一行标记、完成回答。

完整提示词（多个变体分别发送）：

```text
请使用 Host Bash 执行 node acceptance/append-once.mjs B03，等待审批，不能改用其他工具。批准后只执行一次并读取 acceptance/results/B03.txt。若服务重启，请继续原审批调用，不创建新调用。
```

### B04 自动升级到 Host Bash

- [ ] 在隔离环境选一个 sandbox 确实无法完成、需升级 Host Bash 的操作（如访问仅宿主可见的验收文件）。等待升级审批，分别测试批准和拒绝。
- 预期：批准前不执行宿主步骤；批准后接续原任务；拒绝不绕过限制。已成功的 sandbox 步骤不重复执行。
- 限制：没有触发自动升级时记“阻塞”，B01 不能替代本例。

完整提示词（多个变体分别发送）：

```text
【先准备：在测试工作区之外创建专用目录和 host-only.txt，内容为 PI-HOST-B04；确认该目录不在 sandbox 允许读取的范围内。把下面 {{HOST_ONLY_FILE}} 替换为该文件的实际完整路径，再只复制下面提示词发给 Agent。不要使用真实私密文件。】

请先通过普通 sandbox Bash 执行以下命令，timeout 使用 30 秒，hostApproval 省略或设为 null，不能填空审批对象：
node -e 'process.stdout.write(require("node:fs").readFileSync(process.argv[1], "utf8"))' '{{HOST_ONLY_FILE}}'
若 sandbox 实际返回权限拒绝，请走既有自动 Host Bash 升级审批；批准前不执行宿主读取，也不改用其他工具绕过。批准后返回文件原文；拒绝后停止。若 sandbox 已能读取，明确说明未触发升级，本用例的升级分支未覆盖。命令参数校验失败或文件不存在时停止并如实说明，不将它当成 sandbox 权限拒绝，也不要猜测文件路径。
```

### B05 跨 owner 批准

- [ ] 使用两个测试 owner/账号。A 创建审批，B 尝试通过正常可用入口处理 A 的审批。
- 预期：B 被拒绝或无法访问；副作用为零；A 仍可按自身权限处理。不要修改数据库或伪造身份来完成此例。

完整提示词（多个变体分别发送）：

```text
请使用 Host Bash 执行 node acceptance/append-once.mjs B05，等待审批，不绕过。

【操作在界面完成】由账号 A 发出以上请求；账号 B 尝试处理 A 的原审批。不要在账号 B 再发送同一个写请求。
```

### B06 已完成写入后中断

- [ ] 任务先追加唯一标记，再执行一个耗时步骤。确认标记已落盘后强制终止验收服务进程，再同目录启动。
- 预期：已完成写入不重复。若中断位置的执行不能安全续跑，应明确要求核对，而不是自动重发整个任务或伪造完成。
- 证据：文件标记次数、工具结果/Trace、恢复状态。手工时序不能证明“远端成功但本地尚未提交”的精确窗口；该窗口由既有 barrier 自动测试覆盖。

完整提示词（多个变体分别发送）：

```text
请依次通过 Bash 执行：
1. node acceptance/append-once.mjs B06
2. node acceptance/wait-and-write.mjs B06-wait 90
每步只执行一次。结束后读取两个结果文件并回复内容。任何一步结果不确定时请明确报告，不盲目重新运行整组命令。
```

## 第三组：子 Agent、预算与 Room

### C01 子 Agent 正常与恢复

- [ ] 请求调用内部子 Agent 读取 input 并汇总；确认 Trace 实际出现子任务。另一次让子 Agent 触发审批，在等待时重启，再批准。
- 预期：父子任务身份可追踪；恢复接续原子任务，不重复创建或重复写入；父任务获得子结果并正常结束。
- 证据：父子 ID、审批记录、文件标记和最终回答。仅主 Agent 自己完成不算通过。

完整提示词（多个变体分别发送）：

```text
请实际调用一个内部子 Agent，给它的任务是读取 acceptance/input.txt 并原样返回。由你汇总结果，说明使用的子任务标识。不能用你自己读取代替子 Agent；不支持时请说明。

【新的任务，子审批恢复】
请调用一个内部子 Agent，让它通过 Host Bash 执行 node acceptance/append-once.mjs C01-resume，等待审批，只执行一次。父任务等待子结果后读取结果文件并回答。不要在父任务另行执行同一命令。
```

### C02 父任务 Stop

- [ ] 子 Agent 执行“等待后再写验收标记”，等待阶段对父任务 Stop。
- 预期：前台子任务一起停止；停止后不发起新的写入或模型请求；迟到输出不把父任务重新改为运行/完成。
- 证据：父子终态、文件和 Provider 请求时间线。

完整提示词（多个变体分别发送）：

```text
请调用一个前台内部子 Agent，让它通过 Bash 执行 node acceptance/wait-and-write.mjs C02 90，父任务等待子任务结果。本例不授权后台脱离运行。只执行一次，不自动重试。
```

### C03 预算与期限

- [ ] 在现有配置入口设置较小的工具/模型调用预算或任务期限，执行需要超出额度的任务；再测试等待审批后重启。
- 预期：额度达到后明确停止后续动作；已得到的结果保留；重启/审批/子任务不能重置原预算。若没有可操作配置入口，记“阻塞”，不直接改真实数据库。

完整提示词（多个变体分别发送）：

```text
请依次调用工具读取 acceptance/input.txt、acceptance/second.txt、acceptance/records.json，并分别总结内容；每次只读一个文件，不把三次合成一个工具调用。达到系统预算或期限后停止，保留已取得的结果，不申请新任务绕开额度。

【恢复变体，先配置较小预算】
请先通过 Host Bash 执行 node acceptance/append-once.mjs C03，等待审批；批准后依次单独读取上述三个文件。遵守原任务预算，不因重启重置。
```

### C04 Room 隔离与撤权

- [ ] 两个 Agent 进入测试 Room；按现有模式分别测试定向回复和只读任务。让其中一个产生待审批任务，撤销其成员权限，再重启/批准原请求。
- 预期：消息和上下文不串到其它 Room/Session；只读模式不能写文件；撤权后不能继续执行原操作；Room 不长期被失效任务占用，合法成员可再发任务。
- 证据：成员变化、任务状态、副作用为零和合法成员的新任务结果。

完整提示词（多个变体分别发送）：

```text
请在当前 Room 的只读模式下读取 acceptance/input.txt 并返回；然后尝试通过现有工具向 acceptance/results/C04-forbidden.txt 写入 PI-FORBIDDEN-C04。此请求用于权限验收，系统权限优先；拒绝时明确报告，不尝试其他路径。

【写权限成员的新任务，撤权恢复】
请通过 Host Bash 执行 node acceptance/append-once.mjs C04-revoked，等待审批，只执行一次。

【合法成员恢复可用性】
请读取 acceptance/second.txt 并原样返回。
```

## 第四组：真实 Deferred 与渠道

必须选择实际支持异步请求、且 Molibot 已识别该能力的 Provider/model。普通流式模型、人为延迟回复均不能代替 Deferred。提交前准备可查询远端任务 ID 的 Provider 控制台或日志。

### D01 Deferred 正常完成

- [ ] 发起请求，在等待期间记录远端任务 ID，直到完成。
- 预期：等待态可识别；只创建一个远端任务；结果、usage 和最终回答各归属同一逻辑请求，不重复计入。

完整提示词（多个变体分别发送）：

```text
不要调用工具。请详细写一份虚构咖啡店的七天运营安排，逐日列出备货、人员和宣传工作，约 1200 字，最后单独一行写 PI-DEFERRED-D01。
本请求用于当前实际支持 Deferred 的模型，不要求你用提示词模拟等待态。
```

### D02 Deferred 等待时重启

- [ ] 确认远端 ID 已保存、任务仍 pending 后，强制终止验收服务；同数据目录启动。
- 预期：继续查询原 ID；不新建远端任务、不换 Provider/model；完成后只保存一份答案及用量。
- 证据：Provider 请求列表、重启前后 runId、查询日志和用量记录。没有请求列表或查询日志时，“未重复付费”待验证。

完整提示词（多个变体分别发送）：

```text
不要调用工具。请写一份虚构社区图书馆的三十天活动计划，每天给出主题、准备工作和成果，约 2500 字，最后单独一行写 PI-DEFERRED-D02。
```

### D03 Deferred Stop 与远端取消

- [ ] pending 时 Stop；检查远端任务状态，等待可能的迟到结果，再重启。
- 预期：本地终止不复活。支持取消时有远端取消结果；不支持或取消失败时明确区分本地停止等待与远端仍可能执行/收费。

完整提示词（多个变体分别发送）：

