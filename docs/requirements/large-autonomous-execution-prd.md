# 规模化自主长任务 PRD

日期：2026-10-07。优先级：P1。阶段：方案设计；尚未实施。本文描述拟议行为，不代表能力已经交付。

## Problem Statement

用户希望只提交一次大型目标，Agent 就能自行规划、拆分、执行、修复、验收和汇总。任务可能持续数小时或数天，包含数百个工作项。例如翻译一本 1000 页的书：分析目录、建立术语表、分章翻译、处理图片文字和图注、校对、排版并交付完整文件。用户不应因为执行轮数或单批任务数耗尽而不断发送“继续”。

本需求包含三个维度：执行时间长、工作项多、计划在执行中继续细化。单纯提高调用次数和超时不能满足它。模型能读写文件也不意味着运行时能自动续跑、知道哪些产物已经验收，或安全恢复不确定的外部操作。

现有基础包括 Durable Execution、Pi 持久化执行、预算、审批、事件续跑、计划记录和上下文压缩；其交付边界以能力矩阵为准。普通 Run 默认总工具预算为 24 次，内部子工具也计入父预算；单个子任务默认 30 分钟、100 次工具调用，单次委派默认最多 4 项、并发 2 项。此前的 12 次正常模型轮数上限已改为失败重试预算，但这没有建立规模化调度。现有 Session Plan 批准后的执行仍走普通会话轮次，不能视为独立的批量执行引擎。

用户当前遇到的结果是：正常推进被误当成超限，子任务停止导致整体停止，执行结束与目标完成混淆，必须人工追踪未完成项。

## Solution

将一个用户目标绑定到同一个 Durable Execution，以多个有界 Execution Attempt 持续推进。主 Agent 规划和协调；共享调度器保存状态、领取可执行项、控制并发并安排下一轮；子 Agent 处理明确范围的工作。主 Agent 不需要保持一个连续数天的模型调用或 HTTP 连接。

用户提交一次目标后，系统自动：

1. 保存目标、授权范围、输入版本和可验证的验收要求。
2. 识别工作结构，建立可继续细化的计划和依赖。
3. 分批执行可就绪的工作项，完成后提交产物与证据。
4. 正常达到单轮额度时保存并续跑；遇到错误时仅处理受影响工作。
5. 中断后核对恢复点，继续未完成项。
6. 校验整个目标；只有必需验收要求满足才报告完成。

书籍示例：目录与输入清单 → 术语基线 → 各章节分块翻译及图注处理 → 章节校验 → 全书一致性校验 → 汇总导出 → 最终验收。独立章节可并行；需要术语基线的章节先等待基线完成；最终汇总等待所有必需章节通过校验。

用户可随时查看、暂停、继续或取消。等待权限、达到费用额度、结果不确定或反复无进展时，系统明确展示阻塞原因。阶段收尾与最终收尾都必须说明状态、已完成内容、停止位置、停止原因和未完成项；阶段消息不能误写成整个目标完成。

## User Stories

1. 作为用户，我希望一次提交大型目标，以便不必按章节反复下指令。
2. 作为用户，我希望 Agent 自动识别需要跨轮执行的任务，以便不用猜测运行模式。
3. 作为用户，我希望 Agent 保存目标和验收要求，以便后续执行不偏离原始需求。
4. 作为用户，我希望 Agent 分析输入结构，以便章节、附件和图片都有明确处理范围。
5. 作为用户，我希望过大的章节能继续拆分，以便单项工作可以在有限上下文内完成。
6. 作为用户，我希望任务总数不受单次委派额度限制，以便数百项工作能分批完成。
7. 作为用户，我希望正常达到单轮额度后自动续跑，以便无需发送“继续”。
8. 作为用户，我希望独立工作有限并行，以便提高速度并控制消耗。
9. 作为用户，我希望依赖步骤按正确顺序执行，以便不会提前汇总缺失内容。
10. 作为用户，我希望术语和格式规范在章节间共享，以便全书风格一致。
11. 作为用户，我希望每项工作有独立输出范围，以便并行任务不会互相覆盖文件。
12. 作为用户，我希望每个产物有来源和版本，以便能核对它对应的输入。
13. 作为用户，我希望完成一部分就保存一部分，以便中断不丢失已完成工作。
14. 作为用户，我希望重启服务后安全续跑，以便意外退出不要求从头开始。
15. 作为用户，我希望关闭任务面板后继续执行，以便无需一直盯着界面。
16. 作为用户，我希望设备离线时保留任务，以便服务恢复后仍能继续。
17. 作为用户，我希望网络故障经过退避重试，以便短暂故障不会终止整个目标。
18. 作为用户，我希望脚本和内容错误可以被修复并重新验证，以便文件读写能力真正参与纠错。
19. 作为用户，我希望失败项独立恢复，以便一个图片错误不拖住所有章节。
20. 作为用户，我希望重复失败或没有进展时得到说明，以便避免无限循环。
21. 作为用户，我希望不重复已确认完成的操作，以便避免重复写入和额外费用。
22. 作为用户，我希望无法确认外部结果时先核对，以便不会重复发布或发送。
23. 作为用户，我希望能暂停并保留进度，以便稍后在同一任务上继续。
24. 作为用户，我希望取消后不再启动新工作，以便停止指令真实生效。
25. 作为用户，我希望等待审批时保留恢复位置，以便批准后不重复先前工作。
26. 作为用户，我希望修改输入或计划时能看到受影响范围，以便不会默默混用不同版本。
27. 作为用户，我希望调整目标时保留旧证据，以便明确区分复用和返工。
28. 作为用户，我希望看到待执行、执行中、已验收和阻塞数量，以便理解真实进度。
29. 作为用户，我希望增加拆分工作后进度仍有解释，以便百分比变化不会造成误解。
30. 作为用户，我希望预算包括子任务消耗，以便不会低估总费用。
31. 作为用户，我希望达到费用额度时暂停并说明，以便控制开支。
32. 作为用户，我希望最终检查正文、图片及图注覆盖，以便“完成”意味着交付完整。
33. 作为用户，我希望区分机器可校验和主观质量要求，以便知道哪些结果仍待人工验收。
34. 作为用户，我希望失败收尾也有明确报告，以便知道停在哪里以及剩余工作。
35. 作为用户，我希望刷新界面或重开 Session 后看到同一状态，以便不依赖一次即时消息。
36. 作为用户，我希望跨 Session 查看和继续同一目标，以便不创建重复任务。
37. 作为用户，我希望在聊天中获得关键阶段通知，以便不用读取完整工具日志。
38. 作为用户，我希望导出汇总文件和执行报告，以便检查、分享和保存成果。

## Implementation Decisions

以下设计已于 2026-10-07 经用户确认并修订；尚未实施，不修改现有已接受 ADR，也不代表能力已交付。

### 1. 聚合与执行职责

- 复用 Durable Execution 的稳定身份、目标、计划版本、验收、权限和控制动作，不新增第二套“长任务”聚合。
- Execution Attempt 是推进目标的一轮执行，不是整个目标。正常让出执行权不等于失败或完成。
- 采用调度器直接派发：运行时按代码规则领取已就绪工作项并调用子 Agent，不逐项唤醒主模型，也不要求主模型每轮调用委派工具。正常派发不消耗协调轮工具额度；子执行及校验仍受各自额度约束，并归入目标账本。
- 主 Agent 只在初次规划、必要细化、失败恢复决策、共享规范合并及最终语义验收等决策点介入，承担整体结论。运行时执行已有计划、确定性校验、预算检查和唤醒；不能仅靠提示词让模型记住所有未完成项。
- Pi 继续独占已提交模型与工具执行状态。Molibot 保存计划、业务状态和指向 Pi 结果的证据，不维护第二份可写的工具执行日志。
- 所有编排在共享 Agent/Application 层实现。Channel 只负责收发和转换，不能为各渠道单独实现续跑。

### 2. 自动识别与计划细化

- 主 Agent 判断任务需要跨轮推进时，调用明确的“开始长任务”工具，提交目标、初步工作规模、验收规则及输入引用；运行时进入估算和授权检查，再开始执行。不为每个简单问答增加分类模型调用。
- 既有显式恢复、事件入口和首次副作用前的安全升级保留；升级到同一 Durable Execution，不能因触发入口不同创建重复目标。
- 启动前按页数、工作项数、输入量和工具种类给出费用及耗时区间、依据和不确定性；无法估算的部分明确标注。已有授权与可用费用上限足够时直接执行，不强制再次确认；没有费用上限时，只进行既有授权内的有界估算，展示建议上限并等待用户一次确认，不能默认无限预算。无法形成可信金额估算时，说明缺口并确认保守资源额度。
- 用户确认的目标范围、权限和额度在后续批次持续有效；只在达到上限或实质扩大范围、权限、费用时请求决定。估算不能代替授权，也不保证精确时长或精确账单。
- 先保存目标、输入引用、验收和首批工作，再产生副作用；中途升级吸收已完成前缀，不重新执行。
- 计划按需细化，不要求一次模型响应枚举全部页级任务。分批追加必须幂等，并保存扫描范围与生成游标，证明输入没有遗漏。
- 可执行工作项保持稳定 ID。细化父项后，父项仅作汇总，不与子项重复领取；父项完成取决于所有必需子项验收。
- 允许增补计划并保存版本、原因和影响范围；已完成证据不能被覆盖。输入变化时，仅失效受影响项及其依赖，创建明确返工记录。

### 3. 最小依赖调度

- 扩展现有线性计划为工作项间的显式前置依赖，支持分发与汇总；不建设通用可视化 DAG 编辑器或任意流程语言。
- 依赖必须属于同一 Execution，引用有效且无环。只有必需前置项通过验收、权限允许且额度足够的项才可领取。
- 同一目标允许多个独立工作项有限并行；每项最多一个有效执行者。调度器通过事务、版本与 lease 校验防止重复领取。
- 单批任务数与并发数是瞬时容量，不能累计成目标的总任务上限。后续批次由就绪队列自动补充。
- 同时推进多个目标时保证公平，避免一本书占满所有槽位。共享写入和最终构建串行；独立章节采用互不重叠的输出范围。
- 续跑通过既有 watched event JSON 和 Runtime Event 系统触发；事件携带目标与版本身份，只负责唤醒，不成为计划状态来源。重复事件不产生第二个 attempt。

### 4. 预算语义

| 预算 | 达到额度后的行为 |
| --- | --- |
| 单轮工具调用／时间额度 | 安全提交进度、释放槽位并安排下一轮；目标仍未终结 |
| 子工作项执行额度 | 保留证据；续跑或进一步拆分；无安全恢复点时阻塞该项 |
| 模型失败重试额度 | 仅失败计数；瞬时错误退避；耗尽后转入工作项恢复决策 |
| 工具修复额度 | 修改输入、脚本或执行方式后重新验证；重复同类失败进入阻塞 |
| 目标累计费用／资源额度 | 暂停整个目标并输出已用额度与未完成项，不能自动刷新 |
| 并发额度 | 等待槽位，不记失败 |

- 继续保留普通 Run 的保护额度；长任务每轮消耗分别记账，同时汇总到目标账本。不能直接全局取消工具上限。
- 子 Agent 消耗仍计入目标总消耗，但不因协调轮的短额度让已授权的大量章节被整体判失败。
- 12 次是当前子模型失败重试默认值，不是目标总轮数、章节数或子 Agent 数。成功不消耗失败预算；重复 generation 失败只计一次。
- 达到失败额度后不能靠创建相同工作的新 ID 清零。新尝试继承项的失败记录；只有输入修订或明确恢复决策才能重新授权尝试。
- 费用可计量时记录实际值与估算值的区别；价格或使用量缺失必须可见，不能承诺精确硬限额。下一次派发前检查剩余额度，保留在途请求造成超额的边界说明。

### 5. 恢复、错误与无进展

- 每个产物记录输入版本、输出引用、校验结果和来源证据。推进点以提交结果为准，不以最后一条模型陈述为准。阶段 A 即保留已有安全恢复约束；阶段 C 完成全面重启矩阵，不允许前期盲目重放不确定副作用。
- 服务启动核对失效 lease 和未完成执行；已提交结果重建投影，确定安全的工作自动续跑，不确定的副作用进入恢复核对。
- 文件、远端回执与业务状态跨存储不保证同事务。写入完成但记录缺失时，按稳定操作身份核对产物，不能承诺所有工具恰好执行一次。
- 网络错误退避等待并持久化下次尝试时间；认证、权限和不可修复输入错误进入明确阻塞，避免机械重试 12 次。
- 脚本退出或内容校验失败交回 Agent；Agent 在授权内修改后再验证。重新调用失败命令本身不算修复。
- 无进展按确定性证据判断：同一工作项重复错误指纹、相同输入与操作、没有新提交的产物或恢复点。模型文字增加不能证明进展。
- 失败项可被拆小、修复或转为等待处理；不受影响项继续。必要依赖失败时，后继等待并明确列出原因。
- 达到恢复额度后必须报告阻塞；不要求无条件无限执行。用户明确跳过必需项时，必须同时修订验收范围，否则整个目标不能判完成。

### 6. 状态与控制

- 复用现有 Execution 状态集合与等待原因；新增工作项就绪、依赖阻塞、退避和尝试记录，避免把所有状态塞成一个“失败”。正常切片结束回到可调度状态。
- 提供共享动作：提交目标、读取快照／增量、追加或细化计划、领取工作、提交证据、请求修订、暂停、继续、取消和验收。动作绑定 owner、Execution、版本和幂等请求 ID；工作提交另绑定工作项与 lease 身份。
- 暂停先停止领取，等待或中断在途任务到安全点后确认暂停；取消优先级高于迟到完成。旧 lease、旧事件和旧审批不得复活已取消目标。
- 关闭页面不取消任务；服务关闭或设备休眠期间不承诺继续计算。服务恢复后按安全恢复规则续跑。用户主动暂停的目标不会自动恢复。
- 同一 Session 保留用户追问与控制能力；长任务不永久占用交互队列。后台工作拥有独立但受同一目标约束的 Agent Context。
- 可选防休眠能力单独交付，不作为阶段 A 前置条件。用户启用后，仅在目标实际运行期间持有系统防休眠请求；暂停、等待、结束或服务退出时释放，多个目标共用请求时按活动目标计数。它不保证合盖、关机、断电或系统强制休眠期间执行，也不等于阻止屏幕熄灭。

### 7. 上下文、产物与验收

- 主 Agent 上下文包含目标、当前计划摘要、术语和规范版本、阻塞项与证据引用。正文和所有工具日志不塞入协调上下文。
- 子 Agent 只读取本项输入、必要依赖产物与共享规范；提交结构化结果和产物引用。章节基于固定术语基线执行，新建议集中记录并由协调步骤合并与版本化。
- 基线建立后的术语变更默认在最终一致性校验阶段统一定位和修正，修正后重验受影响产物，不使已译章节失效或触发整章重新翻译。语义错误或输入修改确实需要返工时，走明确计划修订并记录影响范围；不将术语建议当成自动连锁返工信号。
- 可复用子上下文，但必须绑定工作身份和输入版本；不因工作数量无限增长一个上下文，也不强制每个小片段新建 Agent。
- 产物写到用户授权工作区；状态写到既有业务域数据库。状态、版本、依赖、lease 与可查询字段使用列；大内容保存为安全产物引用。
- 每个工作项在创建或细化时绑定验收规则：必需输出、输入覆盖范围、检查器种类及参数、通过条件、失败处置与规则版本。规则缺失的工作项不得领取，修改规则走计划修订。
- 子 Agent 只能提交待验证结果；运行时调用已注册的确定性检查器（文件存在、格式可读、覆盖清单等）或独立评审 Agent，保存判定与证据后才能标记验收通过。执行者的“完成”声明不是通过条件；独立模型评审仍有误判边界，主观要求可保留人工验收。未知检查器和验证异常不能默认为通过。
- 完成条件：所有必需工作通过验证，所有必需验收条件有有效证据，无未处理的阻塞与不确定副作用，最终产物可读取。
- 书籍是验收素材示例：任务方案可组合源页／章节映射、正文与图注清单、缺失项、引用、格式可读及术语检查。引擎提供通用检查器和评审接口，不写死书籍专用流程。语义质量另用抽样人工／模型评审并声明局限，不能把结构完整等同于翻译准确。

### 8. 用户呈现与实施顺序

- 复用计划列表、详情和聊天状态，不新增独立“长任务管理器”。展示已验收／待验证／执行中／就绪／阻塞数量、最新提交时间、费用和产物入口。
- 大量工作项按章节或工作分组折叠，提供分页和状态筛选，不将数百项全部平铺。动态细化时展示分母变化；完成数、跳过数和等待验收数分别统计。没有可靠权重时不显示误导性的百分比或完成时间。
- 持续执行阶段汇报进度；等待、失败、取消和最终完成必须有持久化结论。主模型无文本时共享运行层从真实证据生成兜底报告。
- UI 改动遵循既有设计体系、中英、明暗主题和窄屏规范；本 PRD 不指定新视觉风格。
- 阶段 A：线性、串行推进同一目标，交付跨轮自动续跑、预算分离、独立验收、真实完成和兜底报告；保留已有暂停、取消、授权与恢复保护。启动估算和费用授权检查复用现有能力，缺失时明确等待，不放行无限执行。
- 阶段 B：动态细化、待办队列、有限并行、输出隔离和完整目标累计费用控制；以独立工作批次为主，汇总采用阶段屏障，不提前建设通用依赖图。
- 阶段 C：显式依赖调度、多目标公平、全面重启恢复验证、百项／千页规模及真实质量验收。
- 各阶段沿同一聚合和共享调度实现，不建立临时旁路。A 单独验收并可交付；通过后能力矩阵改为“部分交付”，写明线性串行边界和 B/C 缺口。全部必需范围通过后才标“已交付”；可选防休眠另记状态，不阻塞主能力交付。

## Testing Decisions

### 主验收入口

通过真实共享 Chat/Application 入口提交用户目标，观察持久化任务状态、公开控制动作、产物和最终消息。使用真实 Runner、Pi 和事件调度，模型与外部工具采用可控替身；测试不直接修改内部状态来制造“成功”。现有真实 Runner、临时数据库、重启服务和审批恢复测试可复用。

该入口是主测试边界。只有精确验证依赖环、预算计数和 lease 竞争等无法从入口稳定覆盖的规则时，补充共享模块级测试。真实模型容量与翻译质量单独验收，不能用确定性替身证明。

用户已于 2026-10-07 确认上述主验收入口：模型与外部工具使用可控替身，真实书籍另做容量验收。

### 阶段 A 独立验收

1. 从共享用户入口一次提交至少 30 个线性工作项，总工具执行超过默认 24 次；不再发送“继续”即可逐项验收并汇总，正常让出额度不标失败。
2. 调度器无需逐项调用主模型；模型请求记录证明正常领取／派发按代码规则推进，只有已定义决策点调用主模型。子调用与校验消耗正确计入目标。
3. 工作项绑定规则，子 Agent 提交“完成”但产物缺失或格式错误时，运行时拒绝验收；修复后重验成功才能推进后继。
4. 注入可恢复失败与失败额度耗尽，前者保留提交进度并恢复，后者明确停在当前项，给出状态、停止位置、原因和未完成项；父模型静默仍有持久化报告。
5. 重复续跑事件不产生重复执行；暂停、取消和审批沿既有安全规则工作，不因换轮刷新授权或累计消耗。目标有额度时按其额度运行；缺少可用上限时等待一次确认。
6. 页面关闭、刷新和 Session 重开后，公开状态与已提交产物一致；阶段 A 不承诺 B/C 的并行或完整崩溃恢复矩阵。

A 通过后独立交付并更新能力矩阵为“部分交付”，不得把尚未执行的规模与质量验收写成已通过。

### 阶段 B/C 必须通过的外部行为

| 场景 | 可观察的通过条件 |
| --- | --- |
| 连续推进 | 一次提交至少 100 个工作项，跨越默认 24 次工具额度；无需再次发送“继续”，全部必需产物经过验收 |
| 动态细化 | 大章节继续拆分、分批追加，稳定 ID 与源输入覆盖保留，没有重复执行父项 |
| 依赖与并发 | 只有前置项验收后才启动后继；独立项可并行；在途数量不超额度；共享输出不发生冲突 |
| 多目标公平 | 一个大目标持续有工作时，第二个目标仍可获得执行槽位 |
| 重启 | 在提交前、提交后投影前、下一轮唤醒前强制终止隔离服务；重启后同一目标安全推进，已确认完成项不重做 |
| 不确定副作用 | 外部操作成功但回执缺失，先查询核对；不可核对时明确阻塞，无盲目重放 |
| 单项失败 | 注入脚本错误、网络错误与坏输入；可修复项恢复，独立项继续；退避和阻塞原因可见 |
| 失败耗尽 | 失败预算耗尽不会通过新子任务 ID 清零；目标报告未完成与剩余项 |
| 无进展 | 相同失败操作循环不会无限占用模型；阻塞有证据和原因 |
| 控制与竞态 | 重复继续、重复事件只启动一次；暂停后不领新项；取消与迟到结果竞争时取消保持终态 |
| 计划修订 | 运行中修订安全应用；旧版本不能提交新结果；完成证据保留，必要返工可追溯 |
| 权限与等待 | 审批绑定原任务和动作；等待后安全继续；跨 owner／Project 访问拒绝；恢复不扩大权限 |
| 费用 | 子任务费用归入目标；正常切片不刷新累计额度；到限暂停、在途费用和未知费用可见 |
| 启动授权 | 已有授权与上限足够时直接执行；缺少上限时展示估算区间并一次确认，后续批次不重复打扰 |
| 术语演进 | 合并新建议不重新翻译已完成章节；最终一致性修正后重验产物，证据与版本可追溯 |
| 交互与历史 | 后台推进时可追问／暂停；关闭页面后任务保持；重读历史仍有未完成或完成结论 |
| 完成真实性 | 故意缺正文、图注或最终文件，不能标完成；修复并验证后才完成；静默父回复仍有兜底说明 |
| 真实冷路径 | 隔离服务重启、首次打开计划、切换 Session、断线恢复；快照和增量不漏进度 |

### 阶段 C 规模与质量验收

- 确定性规模测试：至少 100 个工作项、400 个步骤，分页读取和分批创建无静默截断，状态与产物覆盖完整；记录耗时、存储增长、内存峰值及协调上下文占用，不用测试机器固定绝对耗时推断所有环境性能。
- 1000 页验收材料：使用有处理权限的书籍或合成文档，预先登记章节、页、图片与图注清单；覆盖不同长度章节、缺失页及 OCR 失败。验收覆盖率必须可计算。
- 真实 Provider 的长时运行作为交付前必需证据，在已授权费用内验证持续推进、重启恢复和产物汇总；未执行时标为未完成，不用替身结果替代。
- 人工抽查关键章节及术语一致性，记录抽样方法和缺陷；不承诺对任意书籍零错误。
- 可选防休眠单独验收：实际运行时持有，暂停／等待／结束释放；多个活动目标不互相提前释放，退出后不残留。不能用该测试证明合盖或关机可执行。
- 测试只使用临时数据库、隔离数据目录和授权材料，不重启用户正在使用的服务。行为实施时运行适用测试、类型检查、构建和界面冷路径。

## Out of Scope

- 无限制费用、无限失败重试、保证任意任务最终成功或完全无人介入。
- 设备关机时继续在本机计算；云托管与多机分布式执行另行设计。
- 更换 Pi 内核、引入另一套工作流存储或建设通用 DAG 可视化产品。
- 重写 OCR、翻译模型、图像生成和排版引擎；复用现有工具并明确能力缺口。
- 任意书籍像素级复刻、自动保证语义零错误或未经授权的对外发布。
- 取消普通短任务的安全预算、将业务编排放进 Channel、用 Markdown／memory／OS scheduler 作为运行状态来源。
- 重写计划板已有编辑交互或扩大外部渠道管理计划的产品入口。
- 兼容层、自动迁移或未授权地删除既有运行数据。
