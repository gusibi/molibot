# Agent 共享工作区与 Session 数据迁移

日期：2026-10-10。状态：已实现；隔离验证及剩余检查见 [实施记录](../work/progress/agent-session-storage/progress.md)。代码提交等待用户确认。

## Problem Statement

普通对话的运行数据按 Channel、Bot、Chat 分散存储。用户以 Agent 管理个人助理，却必须跨目录查找对话、技能、事件和产物。仅聚合列表不能消除运行时对旧目录的依赖。用户需要统一实际存储，并在 App 中确认迁移，保留旧数据以便核验和重新操作。

## Solution

每个 Agent 拥有一个 sessions 树中的共享工作区；Skill、Event、附件、scratch、上下文与运行记录位于其中。Session 是 contexts 中的文件及配对元数据，不增加 Session 或 workspace 目录。Agent 身份与人格配置独立管理，渠道连接与平台数据仍属于 Channel。App 启动检测可迁移数据，展示摘要并等待用户确认；成功后 Runtime 和界面只使用新存储。源目录保留且不再被应用写入，不自动删除。

## User Stories

1. 作为用户，我希望按 Agent 统一存储对话，以便不再按渠道寻找历史。
2. 作为用户，我希望每次 New 只创建上下文及元数据，以便目录保持简单。
3. 作为用户，我希望同一 Agent 的对话共享 Skill，以便能力不因入口而变化。
4. 作为用户，我希望事件由 Agent 统一管理，以便跨渠道查看任务。
5. 作为用户，我希望附件和 scratch 由 Agent 共用，以便复用产物。
6. 作为用户，我希望保留上下文原有格式和正文，以便历史内容完整。
7. 作为用户，我希望启动时自动发现旧数据，以便无需手工运行迁移脚本。
8. 作为用户，我希望确认前看到数量、目标和冲突，以便知道将发生什么。
9. 作为用户，我希望取消或稍后迁移，以便自己决定迁移时间。
10. 作为用户，我希望迁移前不产生新的旧布局数据，以便不会继续扩大分散存储。
11. 作为用户，我希望旧目录保留且应用不再写入，以便自行验证和删除。
12. 作为用户，我希望迁移失败后能重试，以便不用手工清理半成品。
13. 作为用户，我希望重复迁移不复制对话，以便历史列表不会重复。
14. 作为用户，我希望重复迁移不覆盖新目录中的后续对话和产物，以便重试不丢新数据。
15. 作为用户，我希望同名上下文不会覆盖，以便每个原始对话都能保留。
16. 作为用户，我希望事件继续发到原 Bot、聊天和话题，以便提醒不会发错位置。
17. 作为用户，我希望各聊天仍能找到原来的当前 Session，以便继续对话不串上下文。
18. 作为用户，我希望附件链接和产物预览仍可用，以便迁移后历史可阅读。
19. 作为用户，我希望 Agent 归属固定，以便 Bot 改绑定不会改变历史归属。
20. 作为用户，我希望无明确绑定的已配置 Bot 归属 Momo，以便 global 含义一致。
21. 作为用户，我希望无法确定归属的数据被明确报告，以便不会默默丢失或错误合并。
22. 作为用户，我希望 Skill 和配置冲突不被静默覆盖，以便保留自定义内容。
23. 作为用户，我希望对话复制路径、删除、归档、导出使用新位置，以便管理行为一致。
24. 作为用户，我希望删除单个 Session 不删除 Agent 共享资源，以便其他对话不受影响。
25. 作为用户，我希望重启后直接使用迁移结果，以便无需重复确认已完成的迁移。
26. 作为用户，我希望迁移弹窗支持中英、明暗主题和窄窗口，以便在现有 App 中正常操作。
27. 作为用户，我希望渠道认证和群聊权限保持有效，以便存储合并不会改变消息访问边界。

## Implementation Decisions

- 普通 Agent 工作区采用 sessions、Agent ID 两级归属；其下保留 skills、events、attachments、scratch、contexts、run-details 和运行摘要这些语义目录或记录。Momo 固定 ID 为 default。
- Session 上下文保留 JSON 或 JSONL 格式及配对元数据。元数据存储固定 Agent 身份和原 Channel、Bot 实例、Chat 来源；不从物理目录推断归属。
- 统一存储路径解析、上下文读写与发现作为共享模块能力。Runtime、Runner 缓存、技能加载、任务工具、调度器、历史列表、附件授权、预览、删除、归档、导出与复制路径全部使用该能力。
- Channel 只负责连接、收发与平台适配。凭据、Bot 用户名、话题注册表和平台连接状态独立保留。目录合并不取消渠道认证、白名单和发送权限。
- 当前 Session 路由以 Channel、实例、Chat 和必要的平台话题为键。Session 身份与入站路由分离，不合并独立对话上下文。
- Event 显式保存完整回复目标、所属 Agent 及可选创建 Session；保持 watched JSON 与 Runtime Event 调度机制。内部事件、Project 事件保留各自目标语义。
- Desktop 等待服务 ready 后检测迁移。启动中的连接失败不弹迁移错误窗口，恢复后自动检测；关闭未完成的迁移弹窗时，主区域明确显示阻塞原因与处理入口。移除“稍后”，不可排除的资源/Bot 不显示忽略按钮。所有异步操作和轮询校验当前服务与请求代次。
- 缺失 Bot 可明确选择不迁移其全部旧会话、资源、事件、当前路由和普通 Web 展示副本；不修改或删除原文件，不影响其他 Bot、Project 与 Room。确认前可撤销，确认时保存，重启记住选择；全部排除可确认进入空工作区。可恢复队列、Durable 任务、事件租约或审批引用该 Bot 时需先处理，终态历史保持原样。
- 缺失 Bot 且历史会话未记录 Agent 归属时，可直接选择现有目标 Agent，按渠道/Bot 认领未固定归属的会话、资源和当前路由；Web 展示与事件同步解析归属。预览不保存，确认才原子保存选择。确认前可改选或撤销，已准备的迁移归属固定以支持重试，旧文件与 Bot 配置不变。
- 缺失 Bot 且历史会话未记录 Agent 归属时，界面明确说明渠道、Bot ID、受影响会话与迁移阻塞原因；合并同一 Bot 的连带报错，保留可展开的完整诊断。不存在的已指定 Agent 单独说明。
- 迁移状态接口提供是否需要迁移、可迁移数量、冲突和阶段；执行接口仅接受用户确认后的操作。前端确认弹窗展示进度、结果及失败重试入口。
- 有待迁移数据时，暂停受影响的旧布局写入、队列推进和事件消费；取消迁移不会偷偷写旧目录，也不会启动一套空数据冒充迁移成功。提供只读状态与重新打开迁移入口。
- 迁移先生成稳定源身份到目标身份映射，再复制到暂存目标、校验和切换。源身份包含旧 Channel、Bot、Chat 和 Session，不能仅以文件名去重。
- 同名 Session 分配唯一目标 ID，并更新 UI 会话索引、当前路由、事件、运行状态和持久引用。来源明确的持久引用准确改写；缺少唯一来源的终态运行、已结束审批、trace 和记忆历史保留原 Session ID；按 task ID 查询的媒体记录在任何状态下均保留歧义的原 ID，可恢复任务和未知表的歧义仍阻塞。历史正文不改写；产物引用由结构化记录或迁移映射解析。
- 同名相同 Skill 可去重；不同内容不得静默覆盖。附件、scratch 和事件冲突保留原始内容并生成稳定目标名称或明确阻塞项。规则合并不得改变既有有效人格而不报告。
- scratch 内的 `.venv`、`node_modules`、`__pycache__`、`.pytest_cache`、`.mypy_cache` 和 `.ruff_cache` 可重建，扫描前自动跳过，包括其中的符号链接；正常产物与源目录保留。
- 后台迁移运行时，进度查询只读取迁移清单；桌面重连后接续查询并禁用重复提交。复制和发布每 32 个文件保存检查点，阶段结束保存完整进度；中断重试必须校验检查点之后已写入的文件，内容不同仍阻塞。
- 资源冲突可按具体路径显式忽略，重新计算摘要后确认迁移其余数据；选择可恢复，只有确认时才保存，重启后保留。忽略资源不进入新工作区，原文件不删除。Context 正文、身份、路由和持久运行引用冲突仍阻塞；被可恢复事件租约引用的资源不得忽略。
- 源目录原始文件不修改、不删除，不自动修改文件系统权限；只读表示应用所有入口禁止继续写入源布局。渠道资料也以复制方式整理，源副本保留。
- 迁移清单记录映射、校验结果、阶段和提交点；中断可恢复。已完成项重复执行不生成副本；目标被用户修改时不覆盖，新增源项可被重新扫描并报告。
- 成功后只使用新布局，不保留长期双写或旧路径运行 fallback。未完成迁移的源目录不得被历史扫描重复加入列表。
- 全仓审计运行代码、桌面桥接、工具说明、内置提示词、测试夹具与当前文档中的目录约定；发布历史和归档保持历史事实。随包内容变化按项目规则 bump 版本。
- 保留分域数据库和现有持久执行机制。迁移需在隔离的 Runtime 生命周期阶段进行，不与运行任务或事件重复执行竞争。

## Testing Decisions

- 主测试边界：使用临时数据根和临时数据库，通过迁移状态、执行与 Runtime 启动接口验证可观察行为；优先复用现有 SessionStore、MomRuntimeStore 和应用初始化注入入口。
- 核心端到端回归：构造多 Channel、多 Bot 绑定同一 Agent 的旧数据，确认迁移，启动新 Runtime，列出并继续历史对话，创建新对话，读取附件，触发模拟事件，验证回复目标和实际新写入位置。
- 覆盖依赖缓存自动跳过、损坏资源单项忽略/恢复、预览不保存或启动 Runtime、确认后重启保留选择，以及可恢复事件租约拒绝忽略。
- 比较迁移前后源树内容和元数据，证明未修改原数据；模拟失败、重启和再次迁移，证明幂等及不覆盖目标后续修改。
- 覆盖同名 Session、共享附件冲突、Skill 内容冲突、缺失 Bot、禁用 Agent、空绑定 Momo、JSON 与 JSONL、Web 展示与执行日志配对、事件 Session 引用、队列恢复及历史链接。
- 复用现有 Session 归属回归、文件访问授权测试、事件 lease/recovery 测试和 settings 临时数据库 round-trip 模式；仅对无法在主边界稳定覆盖的路由/授权合同补针对性测试。
- Desktop 走查启动检测、确认/取消、进度、失败重试、完成后列表和菜单、中英/明暗/窄窗口。执行隔离冷启动、Session 切换和服务中断恢复。
- 执行相关后端测试、类型检查、Desktop 测试和构建，再按项目要求执行最终完整检查。禁止测试读写真实用户目录或真实渠道、付费模型。
- 上述测试边界已由用户于 2026-10-10 确认，作为实现验收依据。

## Out of Scope

- 自动删除旧目录、修改源文件权限或迁移前直接操作真实数据。
- 自动合并多个 Session 的上下文，以及自动把不同渠道接入同一个对话。
- 取消渠道安全边界、重构分域数据库、改变 Project 与 Room 的产品归属。
- 将共享产物按 Session 重新拆成独立工作区。

## Further Notes

这是用户明确要求的数据迁移，属于项目通常不保留兼容层规则的本次授权例外；迁移完成后旧结构只作为用户自行保管的快照。

该规格补充 Personal Agent Desktop V1 的存储部分。真实数据迁移由 App 中的确认操作触发；开发验证仅使用临时数据。
