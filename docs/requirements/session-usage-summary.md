# Session 累计用量与上下文容量

日期：2026-09-12。状态：已交付——输入框统计面板以 Session 累计用量为主数字、"当前上下文"（已使用上下文）单列展示；回复下方仍保留本轮用量。当前上下文 = 最后一次模型请求的输入 + 该次回复的输出，即下一次发送的起点；汇总来源为共享用量账本按 sessionId 的服务端聚合，经会话详情接口随 transcript 一起返回；统计读取失败显示"统计暂不可用"，与真实零用量可区分。覆盖边界：账本只能证明自会话归属生效（2026-09-12）起的调用，响应中的 `coverageStart` 字段（最早计入记录的时间）即显式覆盖边界，面板不以消息加总伪造更早的历史。

## 产品行为

每条回复下方保留本轮模型调用的累计用量。Chat 输入框底部的统计面板以整个 Session 已发生的累计用量为主要内容，另外展示最近一次模型请求的上下文容量。

Session 累计用量跨轮次保留。压缩上下文、删除部分消息、切换模型、切换会话和重启服务，都不能减少已经计入该 Session 的模型用量。删除整个 Session 后不再提供该 Session 的统计入口；本需求不改变全局用量记录的保留策略。

术语定义见[领域词汇表](../reference/CONTEXT.md)。模型用量以 API 报告为依据，沿用[Trace 设计的统计原则](../designs/trace/agent-run-trace-and-hooks.md#19-token-统计方案)。本需求替换输入框统计面板的展示口径，不替换 Trace 的诊断职责。

## 面板内容

| 区域 | 展示内容 | 数据含义 |
| --- | --- | --- |
| 本会话累计用量 | 总 tokens、输入 tokens、输出 tokens、缓存读取、缓存写入、缓存命中比例 | 已归属到该 Session 的实际模型调用累计 |
| 最近一次上下文 | 当前已使用上下文 / 模型窗口、容量进度条 | 最后一次请求的输入（含缓存）+ 该次回复输出，即下一次发送的起点 |
| 上下文组成（估算） | 消息、MCP 工具、系统工具、系统提示词、技能、其他 | 最近一次 dispatch 的分类估算 |

输入量包含未命中输入、缓存读取和缓存写入。缓存读取、缓存写入作为输入明细显示，不能再与完整输入相加计算总量。输出中的思考量是否单列，不改变输出及总量的加法关系。

Session 缓存命中比例 = 累计缓存读取 / 累计完整输入。不得对每轮百分比做算术平均。输入为零时显示无可用比例，不显示伪造的 0% 命中率。

累计消耗没有上下文窗口上限，不能使用“累计 tokens / 模型窗口”计算百分比。触发器的进度环和容量进度条只表达当前已使用上下文占用。当前上下文的估算规则：有 dispatch 快照时取该次请求的真实输入（含缓存）加该次回复的实测输出；中间工具调用的输出已包含在最后一次输入内，回合聚合输出会带来每次调用几十 token 的正偏差，可接受。无快照的旧会话退化为回合聚合用量（输入+输出）对照模型配置窗口，多次调用的回合会高估。分类估算不能当作整个 Session 的精确用量分布。

## 数据与更新

共享用量记录是累计统计的数据来源。当前消息列表和模型上下文会随删除、压缩、重试回滚发生变化，不能承担 Session 历史用量账本的职责。

服务端完成 Session 身份与访问范围校验后，按该 Session 查询用量，并通过会话详情接口返回汇总。主 Chat 与 Project Chat 复用同一汇总定义和展示组件。前端不得拉取全局用量明细后自行过滤，也不得将流式回报与已落盘汇总重复相加。

新会话的已记录累计为零；尚无模型回报时，上下文容量显示空态。切换会话时立即切换统计归属，旧请求延迟返回不能覆盖当前会话。模型回报用量后才能计入，不根据正在输出的文本估算消耗。失败或未能读取统计时保留明确的不可用状态，不能把读取失败当作零用量。

已有用量记录不能证明完整历史时，不以消息加总或字符估算伪装成完整账本。需要明确记录覆盖边界。

## 待确定的归属边界

- Session 累计是否包含其触发的子 Agent、自动压缩及失败但已报告用量的请求。
  当前实现：凡账本记录携带该 sessionId 即计入（含失败但已回报用量的请求）；子 Agent 不经共享漏斗分发、账本本就不带该 sessionId，天然不计入。
- 编辑重发创建的新分支是否仅统计新分支创建后实际发生的请求。
  当前实现：fork 生成新的子会话 id（`sessionForkId`），分支的累计从零起算，只统计分支创建后实际发生的请求；源会话的累计不含分支新产生的调用。

## 验收

- 三轮已报告总量为 45,521、20,760、21,803 时，回复下方分别保持各轮数字；Session 汇总为 88,084，当前上下文为 21,803（最后一次请求输入 21,050 + 该次回复 753）。
- 累计缓存读取 8,114、完整输入 84,028 时，Session 缓存命中比例为 9.66%，不能显示按轮平均得到的 6.3%。
- 删除部分消息或完成上下文压缩后，累计用量不减少；容量仅随最新模型请求变化。
- 带用量的重试、模型切换及恢复不会漏计或重复计入；不同 Session、Bot、渠道与 Project 的数据不会串入。
- 重新打开会话及重启后显示相同已记录累计。统计读取失败与真实零用量可区分。
- 主 Chat 与 Project Chat 同步实现，并验证中英文即时切换、明暗主题、移动宽度、键盘访问及空态。
- 持久化回归使用临时数据目录或可注入 store。UI 验证包含隔离实例的冷启动、首次打开、会话切换与服务中断后恢复。
