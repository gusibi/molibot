# Molibot 统一 Skill Manager Spec

日期：2026-10-27；实施状态更新 2026-10-29。状态：V1 已实施并验证（发现、来源、Copy/Link 安装、预检、冲突、备份恢复、分发、卸载保护、平台配置、Runtime 加载状态）；V1.1 更新管理待排期。测试边界已由用户确认。V1 为统一发现、安装与分发，V1.1 为更新管理。实施记录见 `features.md`，能力状态见 `personal-assistant-capability-matrix.md`。

## Problem Statement

用户在多个 Agent 工具中维护 Skill，需要手动寻找目录、复制文件或创建链接，无法在 Molibot 中统一判断来源、安装位置和可用范围。同名 Skill 可能内容不同，共享目录又可能同时被多个工具读取，简单按名称或平台计数会产生误判。

Molibot 当前已有全局及 Agent Skill 展示、启停、文件预览和内置 Skill 更新，Runtime 另有 Project 加载及作用域优先级。管理扫描和 Runtime 扫描分别实现，当前均未处理目录符号链接。仅扩展页面或创建链接，不能保证 Agent 真正加载安装后的 Skill。现有文件扫描也无法恢复外部来源、安装时版本和文件操作归属。

## Solution

将现有技能工作区升级为统一 Skill Manager。用户能发现 Server 所在设备上其他平台的 Skill，查看文件和来源，明确选择 Copy 或 Link 安装到 Molibot，并验证其在指定 Agent/Project 上的实际可用性。用户还能把 Skill 分发到已授权的其他目标，并安全移除由 Molibot 管理的安装。

V1 从第一次安装起保存来源、版本基线和操作记录，完成冲突处理、替换前备份和失败恢复。V1.1 在这些记录上增加更新检测、Diff、版本回滚、批量操作和依赖诊断。已有 Skill 原地识别；不强制搬迁目录，不要求重新安装，不新增旧接口兼容层。

## User Stories

1. 作为用户，我希望发现其他 Agent 工具中的 Skill，以便复用已有能力。
2. 作为远程 Desktop 用户，我希望知道扫描的是哪台 Server，以便避免混淆两台设备的文件系统。
3. 作为用户，我希望按平台查看扫描目录和错误，以便判断为何没有发现 Skill。
4. 作为用户，我希望只扫描已配置根目录和已登记项目，以便避免全盘扫描。
5. 作为用户，我希望添加自定义平台和扫描目录，以便使用预置列表以外的工具。
6. 作为用户，我希望禁用扫描或删除平台配置不删除文件，以便安全调整管理范围。
7. 作为用户，我希望外部发现的 Skill 显示为尚未安装到 Molibot，以便准确判断安装状态。
8. 作为用户，我希望全局安装数量不包含 Agent/Project 专属技能，以便理解统计口径。
9. 作为用户，我希望仍能查看 Agent 和 Project 专属技能，以便保留现有管理入口。
10. 作为用户，我希望已禁用的 Skill 仍显示为已安装，以便区分文件存在和允许使用。
11. 作为用户，我希望损坏链接及无效 Skill 单独显示异常，以便定位和修复问题。
12. 作为用户，我希望搜索名称、描述并筛选来源、平台、范围和安装方式，以便快速找到 Skill。
13. 作为用户，我希望同一真实目录的多个入口合并展示并保留入口明细，以便避免重复操作。
14. 作为用户，我希望同名不同内容的 Skill 分别展示，以便比较后决定采用哪个。
15. 作为用户，我希望查看元数据、完整说明、目录树和有界文件预览，以便了解安装内容。
16. 作为用户，我希望通过 Copy 安装外部 Skill，以便得到不受外部后续修改影响的副本。
17. 作为用户，我希望通过 Link 使用自己维护的公共 Skill，以便让多个工具共享内容。
18. 作为用户，我希望安装前看到来源、目标路径、方式和冲突，以便确认实际文件操作。
19. 作为用户，我希望从本地目录安装 Skill，以便使用未被其他工具发现的内容。
20. 作为用户，我希望从 Git 仓库的指定子目录安装 Skill，以便避免复制无关仓库文件。
21. 作为用户，我希望记录实际安装的 Commit 和内容基线，以便以后检查变更。
22. 作为用户，我希望冲突时能保留、取消或明确替换，以便避免静默覆盖。
23. 作为用户，我希望替换前保留旧内容，以便失败时恢复原安装。
24. 作为用户，我希望重命名 Copy 时同时校验技能名称，以便目标工具能识别它。
25. 作为用户，我希望链接安装后能被真实 Runtime 发现，以便安装结果能够用于任务。
26. 作为用户，我希望查看指定 Agent/Project 未加载某技能的原因，以便理解禁用、覆盖和范围限制。
27. 作为用户，我希望启停状态在重启后保留，以便不重复配置。
28. 作为用户，我希望将 Molibot Skill 分发到已配置平台或已登记项目，以便减少手动安装。
29. 作为用户，我希望知道某个目录被多个平台读取，以便理解一次操作的影响。
30. 作为用户，我希望分发失败不掩盖其他目标的成功，以便逐项处理失败项。
31. 作为用户，我希望卸载链接只删除入口，以便保留外部源目录。
32. 作为用户，我希望移除源 Skill 前看到它支撑的外部分发链接，以便避免制造损坏链接。
33. 作为用户，我希望已有但来源不明的 Skill 正常显示，以便继续使用已有安装。
34. 作为用户，我希望服务中断后能恢复或明确报告未完成操作，以便不把半成品误认为成功。
35. 作为用户，我希望中英切换、明暗主题和窄窗口下操作都可用，以便在不同环境中管理技能。
36. 作为用户，我希望区分文件已安装与目标平台已验证加载，以便不把目录存在误认为功能正常。
37. 作为用户，我希望外部 Skill 安装时不执行脚本或改变审批规则，以便保留现有执行边界。
38. 作为 V1.1 用户，我希望检查 Git 子目录和本地 Copy 来源的变化，以便只处理真正影响该 Skill 的更新。
39. 作为 V1.1 用户，我希望来源未知、不可访问或检查失败时显示具体原因，以便不误认为已经是最新版本。
40. 作为 V1.1 用户，我希望更新前查看 Diff 和本地修改，以便决定保留、备份更新或手动合并。
41. 作为 V1.1 用户，我希望恢复历史备份并保留当前恢复点，以便撤销错误更新。
42. 作为 V1.1 用户，我希望批量更新跳过冲突项并逐项报告，以便安全处理多个 Skill。
43. 作为 V1.1 用户，我希望配置更新检查频率但不自动安装，以便控制实际内容变更。
44. 作为 V1.1 用户，我希望查看已知依赖和未验证项，以便判断某 Skill 是否适合当前环境。

## Implementation Decisions

### 交付范围与顺序

- V1 第一个端到端切片完成：本地发现、Copy/Link 安装到 Molibot、Runtime 加载、禁用、卸载和重启回读；来源及操作记录随切片一起实现。
- V1 随后补齐预置平台适配、自定义平台、本地文件夹与 Git 子目录安装、外部分发、冲突处理、备份和失败恢复。单目标流程先通过，再实现多目标分发；多目标分发逐项执行和报告，不承诺跨平台原子事务。
- V1.1 实现 Git/本地/Registry 更新检测、文件 Diff、本地修改识别、历史备份管理与回滚、批量更新和依赖诊断。V1 不显示尚未实现的更新入口或虚构的可更新数量。
- V1 支持 macOS Server 上的文件操作；其他系统不得仅凭适配器存在宣称通过验证。Web 和 Desktop 共用服务端能力和授权边界。

### 管理与 Runtime 的边界

- Skill Manager 负责发现、来源、安装关系和文件生命周期；Runtime 继续负责有效技能选择、按需加载、工具权限和审批。
- 提取共同的有界目录扫描、链接解析和 frontmatter 校验能力。管理目录保留禁用项、同名项及异常诊断；Runtime 在扫描结果上应用现有规则，不从管理列表直接继承展示去重结果。
- 保持当前 Runtime 同名选择顺序：Project 优先于工作区、全局和旧 Chat 范围。管理层不重排优先级；已有 Agent 专属停用、全局停用及工作区允许范围仍生效。
- 现有路径形式的停用配置继续有效。文件去重可使用真实路径，但启停匹配必须保留安装入口身份，不能因解析 Link 而丢失原入口的禁用约束。两个安装入口指向相同内容，不自动共享启停状态。
- 只有实际全局技能根下有效的目录或 Link 入口计为 Molibot 全局已安装。Agent/Project 专属技能分别统计；异常入口不计入有效安装数量。
- Installed、Enabled、Available 分别计算。格式有效仅说明可被解析；Available 表示在指定上下文中通过加载筛选，不承诺任务成功。手动调用限定技能可以 Available，但不自动出现在模型发现目录。
- 安装和外部变更需使受影响的技能索引及提示词缓存失效；下一次加载读取最新状态，不改写已经发出的模型请求。最终渲染提示词保持精简技能目录，正文继续按需读取，不新增重复 section 或动态长前缀。

### 发现与平台模型

- 默认扫描 Server 设备，返回设备标识和执行位置。Desktop 的目录选择与“打开位置”不能把远端路径当作本机路径；远端场景只提供受控预览、复制路径或明确的不可用说明。
- 预置 Molibot、Codex、Claude Code、OpenClaw、Gemini CLI、Cursor、OpenCode、GitHub Copilot。每个适配器明确候选目录、共享读取目录、项目相对目录、写入能力及验证状态；实现时按官方规则核对，目录不存在只表示该扫描位置缺失。
- 用户可覆盖或补充扫描根。项目扫描仅使用已登记项目；不遍历整个 Home。自定义平台采用标准 Skill 格式和默认技能文件名，不在 V1 提供任意文件格式解析器。
- 平台是读取规则；物理入口才是安装及文件操作单位。多个平台读取同一入口时，保留平台可见性关系，不能创建重复物理安装记录或把扫描位置当成原始安装者。
- 同一真实目录可聚合展示；不同目录即使名称和内容相同，仍保留独立入口与来源，仅允许展示分组。同名不同内容显示冲突。展示分组不改变 Runtime 选择。
- 扫描限定深度、条目数、单文件及总读取大小、并发和耗时。忽略依赖目录、仓库元目录、备份和暂存目录；达到限制返回截断诊断。权限错误、断链和单根失败不影响其他根。
- 区分最近成功扫描、缓存数据和当前失败。旧缓存不能证明当前目录仍有效，也不能作为执行写操作的依据。

### 来源、版本、安装和持久化

- Skill 使用独立稳定标识，名称和内容哈希都不充当长期身份。分组不是身份合并，文件改动不自动生成新 Skill 身份。
- Source 保存 builtin、git、registry、local 或 unknown 来源及定位信息；共享 Source 不保存所有安装共用的单一“已安装版本”。
- 每条 Installation 绑定来源、安装入口、范围及 Agent/Project 归属、方式、管理归属、安装时间和具体版本基线。具体 Commit、子目录、内容清单与安装哈希属于该安装基线或其引用的不可变快照。
- Copy 的基线对应安装完成时的完整内容；Link 记录最近观察内容，明确其随源目录变化。发现未知普通目录时不猜测它是 Copy；已有 Link 可以确认链接方式，但不能据此认定由 Molibot 创建。
- 从其他平台 Copy 得到的副本保留来源定位和上游归属，不因内容相同就继承另一来源的 Git 或 Registry 信任关系。
- 内容哈希覆盖相对路径、文件字节和影响执行的权限位，并明确内部链接策略。安装基线与后来扫描到的当前哈希分开保存；刷新扫描不能覆盖用于识别本地修改的基线。
- 遵循按业务域分库的 ADR：Skill Manager 的来源、安装、操作意图和恢复记录使用独立的可注入 SQLite store；状态、版本和并发字段使用真实列。大文件、暂存内容和备份保存在受控文件区，数据库引用它们。平台设置采用实体级保存，避免提交整个运行设置对象。
- 文件系统是安装存在及有效性的事实来源，数据库保存无法从扫描恢复的来源、归属、基线与操作历史。启动和操作完成后重新校验；差异显示为缺失、异常或未完成，不伪造成功，不自动接管未知外部文件。
- 已有内置 Skill 继续由现有版本描述符及备份机制管理，统一界面投影其状态；不引入第二个竞争的内置更新写入者。

### 安装、分发与卸载

- 来源支持已发现本地 Skill、本地目录、Git 仓库指定 Skill 子目录和现有内置 Skill。Git 安装解析指定分支或 Ref 为确定 Commit，再获取受限内容，不执行仓库脚本、过滤器或安装钩子，不递归获取无关子模块。
- Git Copy 从暂存候选复制；Git Link 指向由 Molibot 管理的持久本地源目录，不能指向下载临时目录。源内容由同一文件操作服务维护，引用尚在使用时不得回收。
- 不强制迁移到统一 Library。外部目录可保留原位置；Molibot 全局安装入口仍位于实际全局技能根内。
- 外部平台拥有的目录默认 Copy；用户明确维护的共享目录可推荐 Link。Link 确认中说明源修改即时影响消费者、源删除会断链，且其他平台不一定立即重新加载。
- 预检返回来源身份、确定的目标入口、写入清单、冲突、共享消费者和当前版本指纹。执行请求引用服务端解析的标识及预检结果，写入前重新校验；预检失效返回可重试的冲突，不沿用过期授权。
- Copy 保留技能所需资源和可执行权限，排除仓库与无关依赖内容。Skill 根入口可以链接到已授权目录；内部链接仅允许解析到该技能真实根内，外逃、循环或不可验证目标拒绝安装及预览。不静默跟随链接复制其他目录。
- 无冲突才直接安装。已有入口可保留或取消；替换需要显示精确路径、影响和备份位置，用户明确确认后执行。目标若是不归 Molibot 管理的外部内容，默认只读，不通过普通分发操作替换或删除。
- 重命名仅用于独立 Copy，同时校验或调整目录名和 frontmatter 名称，并提示内部引用需要检查。Link 不提供仅改入口名的通用冲突解法，不修改外部源文件；改用 Copy 或取消。
- 按目标物理入口串行执行操作，并对源及目标版本作并发校验。暂存、备份、替换和验证使用持久操作意图及收据；文件系统与数据库不假装具有跨介质事务。中断后依据记录恢复、回退或明确进入待处理状态。
- 失败不得标为成功。替换失败优先恢复原版本；恢复失败时保留恢复材料和错误，不删除最后一份可恢复内容。备份、暂存和操作记录不进入技能发现。
- 多平台分发按物理目标去重并分别报告成功、失败和跳过；不因一个平台失败删除其他成功安装，不承诺外部工具热重载。
- 普通卸载只处理已确认的 Molibot 管理入口。Link 仅删除链接本身，绝不递归删除其真实目标；Copy 只处理对应安装目录。来源未知或用户手工创建的入口不因存在于扫描结果就被自动删除。
- 删除 Molibot 管理的源目录前，检查已记录的分发引用；仍有引用则阻止删除并列出受影响入口。解除相关管理引用需要单独明确操作；对未被扫描或记录的外部引用不声称可完整识别。
- 删除平台配置或关闭自动扫描只改变配置；不删除安装，不代表其他工具停止读取共享目录。记录安装、启停、分发、卸载、失败、恢复及来源配置变更，日志不含凭据。

### 服务接口与界面

- 在共享服务层实现查询、扫描、详情、预检、安装、分发、启停、卸载和操作查询，Web/Desktop 作为传输和显示入口；不把生命周期逻辑放到 Channel 或界面组件。
- 查询返回稳定标识、范围、来源、入口关系、状态维度和诊断。列表避免返回完整路径和凭据；详情及预检在鉴权后按需显示实际文件位置。客户端不能提交任意删除路径。
- 所有管理入口复用现有认证及 owner 授权，读写均受已配置根和实体范围限制。自定义根配置是显式的扫描或写入授权，不是任意文件系统 API。
- 首版主视图为“已安装”“已发现”“平台”；“已安装”明确全局口径，并提供 Agent/Project 专属技能范围入口和独立计数。未安装内置技能继续可恢复安装，不因视图更换丢失入口。
- 复用既有紧凑网格、选中后主从详情和文件树，遵循共享设计规范及 shadcn 组件体系。路径、完整描述和元数据留在详情；主要操作依安装归属及权限显示。
- 平台设置及其他保存表单使用固定操作底栏；支持中英即时切换、明暗主题和窄宽度。保留搜索、范围和选择状态，服务失败显示错误，恢复后能够重试，不沿用另一 Server 的扫描或操作结果。

### V1.1 更新管理

- Git 更新比较指定跟踪 Ref 对应的 Skill 子目录内容，而非只比较仓库 HEAD；固定 Commit 来源显示为固定版本，只有用户选择新目标版本或跟踪 Ref 后才形成候选更新。
- 本地 Copy 分别比较来源当前内容、安装基线和本地当前内容，区分上游变化与本地修改。Link 的源变化作为观察到的内容变化刷新索引，不显示重复复制操作。
- 来源未知、不可访问、失败及从未检查不能显示“最新”。绑定来源只建立用户确认的来源关系，不伪造历史安装 Commit 或消除本地修改。
- 更新先下载候选、验证、展示文件增删改及 Diff，再明确确认。保留当前版本或备份后更新；手动合并由用户完成，不提供复杂自动三方合并。
- 历史回滚先保留当前恢复点，再恢复选定版本并验证安装及来源基线。外部拥有的 Link 源保持只读；需要独立更新或回滚时先明确转为受管理 Copy，不通过链接覆写外部源。
- 批量更新只处理来源有效、无未解决本地修改冲突且通过必要检查的项。依赖诊断区分已知满足、缺失和未验证，不执行 Skill 脚本探测，也不凭格式合法宣布跨平台兼容。
- 默认不自动安装新版本。V1.1 支持手动检查及有缓存和频率限制的自动检查，周期检查经 watched event JSON 和 Runtime 事件系统落地，不使用 OS scheduler 或模型记忆代替。

## Testing Decisions

- 用户已确认：共享 Skill Manager 服务/API 是主要集成测试边界；以临时文件树、临时数据库、本地 Git 仓库和本地模拟模型验证完整行为。只在不能通过此边界覆盖的格式解析及文件安全处补底层定向测试。
- 好的测试断言用户可观察的响应、业务状态和实际文件结果，不断言内部 helper 调用顺序或具体表结构。安全失败要证明目标未写入、外部源未删除、原内容仍可恢复。
- 复用现有 Runtime 技能加载测试、内置技能安装与备份测试、Desktop 技能映射/预览测试、设置整对象 round-trip 测试，以及隔离技能管理 UI 测试夹具；不建立另一套平行测试基础设施。
- V1 服务集成验收覆盖：外部仅发现；全局目录有效安装；有效与损坏 Link；禁用仍已安装；Agent/Project 单独统计；Copy 独立性；Link 源变化可见；同真实目录聚合；同名异内容冲突；无权限根局部失败；未知来源保留；自定义配置回读；重复操作幂等；多目标部分失败。
- Runtime 验收通过真实加载和最终渲染提示词验证 Copy/Link 能被发现、禁用后不被调用、被 Project 覆盖的全局项仍留在管理列表、手动调用限制保留、切换 Project 不串缓存。用本地模拟模型执行一个无副作用的 fixture Skill，不用“列表存在”代替实际读取和调用验证。
- 文件操作验收覆盖循环与逃逸链接、目标父目录链接替换、预检后目标变化、大小限制、可执行位保留、Git 子目录外逃、恶意安装钩子不执行、卸载仅移除链接、未知外部入口拒删、已分发源删除阻止及备份不参与发现。
- 在暂存完成、备份完成、文件替换后而收据尚未保存等边界注入故障并重建服务/store，验证恢复和准确状态；同一目标并发请求只产生一个确定结果，不丢失原内容。
- 平台配置、来源、安装及基线验证 save → 新建 store → load。启停验证现有设置整对象 round-trip，避免因细粒度操作丢失其他已支持字段；路径解析和临时目录注入不得访问真实用户数据库或 Skill 根。
- 界面只补直接相关交互：切换视图/范围、搜索、详情预览、Copy/Link 预检及确认、冲突、结果反馈、平台保存、远端设备说明；校验中英即时切换、明暗和移动宽度。现有内置安装/更新/备份、Agent 配置和文件预览断言保留。
- 冷路径在隔离实例执行：服务启动后首次打开、首次安装、切换 Session/Project/页面、服务中断再恢复、重启后安装及禁用回读。涉及桌面原生 API 传输或打开位置时增加对应原生定向验证；环境不足明确标为未验证。
- Bug 修复先用守卫复现修复前失败，再确认修复后通过。新用例加入测试集前连续运行五次并证明对应故障会使其失败；不通过延长等待或重试掩盖竞态。
- V1.1 补充 Git 仓库其他目录变化不提示更新、Skill 子目录变化提示更新、固定 Ref、来源失联、本地和上游同时变化、Diff 截断/二进制、失败回退和回滚后基线一致的用例。
- 实施时只运行改动直接相关用例和类型检查；UI 改动完成适用的 Svelte 检查与构建。全量验收保留 `pnpm verify:feature`、`pnpm test:ui` 和 `pnpm test:app` 供用户主动执行，不因编写本规格运行产品测试。

## Out of Scope

- V1 的远程更新检查、Registry 安装与搜索、Diff 界面、历史版本回滚和批量更新；它们属于 V1.1。V1 替换前备份及操作失败恢复仍是必需项。
- 商业 Marketplace、跨设备同步、Desktop 本机独立扫描、任意磁盘扫描和未登记项目发现。
- 自动转换平台专属工具语义、自动安装 CLI/MCP 依赖、以静态扫描证明第三方 Skill 安全或能够成功执行。
- 默认执行第三方安装脚本、自动更新安装内容、调整 Runtime 权限或审批策略。
- 强制统一物理 Library、迁移已有 Skill、保留过时接口兼容层、改写现有同名加载优先级。
- 自动接管或删除来源未知和外部拥有的文件；承诺发现所有未登记消费者或控制其他平台热重载。
- 复杂自动三方合并、Skill 分组收藏、使用统计和未使用清理建议。
