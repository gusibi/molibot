# Personal Agent Desktop V1 — Implementation Spec

确认日期：2026-10-09。实施完成：2026-10-10。产品范围和测试边界已由用户确认；当前状态见 [能力矩阵](personal-assistant-capability-matrix.md)，验证证据及限制见 [实施记录](../work/progress/personal-agent-desktop-v1/progress.md)。

## Problem Statement

Desktop 的普通对话导航以 Channel 和历史 Session 为中心，用户难以辨认助手身份、直接选择助手开始交流。普通会话尚未保存独立的 Agent 归属，部分执行配置来自当前渠道绑定，不能保证历史恢复与实际执行身份一致。

## Solution

以 Agent 为 Desktop 普通聊天的主要入口：展示身份、独立 Session、轻量新对话首页和完整历史，保留现有项目工作台与 Inspector。通过固定的 Session Agent（会话所属 Agent）、共享执行校验和明确的记忆作用域保证真实身份连续性。独立 Web 界面保持现状。

## User Stories

1. 作为Desktop 用户，我希望在侧栏直接选择 Agent，以便知道自己正在和哪个助手交流。
2. 作为Desktop 用户，我希望通过头像、名称和定位区分 Agent，以便无需进入技术配置页。
3. 作为Desktop 用户，我希望点击 Agent 主体进入可直接输入的新对话首页，以便快速开始新话题。
4. 作为Desktop 用户，我希望新对话默认使用当前 Agent，没有明确选择时使用默认 Agent，以便无需每次手动选择。
5. 作为Desktop 用户，我希望首次发送前切换 Agent，以便确定谁负责这段对话。
6. 作为Desktop 用户，我希望首次发送时创建并保存 Session 归属，以便后续执行身份保持一致。
7. 作为Desktop 用户，我希望同一 Agent 下维护多个独立 Session，以便隔离不同话题的上下文。
8. 作为Desktop 用户，我希望打开历史后恢复所属 Agent 与模型覆盖，以便可靠地继续工作。
9. 作为Desktop 用户，我希望已有 Session 的 Agent 标识固定不可切换，以便避免无意改归属。
10. 作为Desktop 用户，我希望重启后恢复上次页面，以便接续使用。
11. 作为Desktop 用户，我希望分别展开多个 Agent 的最近历史并保存展开状态，以便按自己的习惯导航。
12. 作为首次使用者，我希望历史默认折叠，以便避免侧栏过长。
13. 作为Desktop 用户，我希望区分当前 Agent 和当前 Session 的选中状态，以便准确判断所在位置。
14. 作为Desktop 用户，我希望查看 Agent 完整历史并按更新时间排序，以便找到旧对话。
15. 作为Desktop 用户，我希望按现有检索能力搜索历史、筛选来源，以便缩小查找范围。
16. 作为Desktop 用户，我希望使用已有重命名、归档和删除操作，以便整理对话。
17. 作为Desktop 用户，我希望跨 Agent 搜索可访问的普通对话，以便无需逐个展开助手。
18. 作为Desktop 用户，我希望查看外部会话来源和只读标识，以便理解操作限制。
19. 作为Desktop 用户，我希望切换 Agent 时保留各自未发送草稿，以便避免串话或丢输入。
20. 作为Desktop 用户，我希望执行中切换页面后结果和审批仍属于原 Session，以便可靠管理后台工作。
21. 作为Desktop 用户，我希望在首页直接输入并将任务建议填入草稿后自行发送，以便保持发送控制权。
22. 作为Desktop 用户，我希望只在输入区设置 Session 模型覆盖或跟随 Agent，以便避免重复模型控件。
23. 作为Desktop 用户，我希望沿用文件和小程序 Inspector，以便保留熟悉的交付物查看流程。
24. 作为Desktop 用户，我希望创建 Agent 后无需配置渠道即可聊天，以便降低创建成本。
25. 作为Desktop 用户，我希望修改显示名称而不改变稳定身份，以便保留历史归属。
26. 作为Desktop 用户，我希望设置有效且启用的默认 Agent，以便随时能开始对话。
27. 作为Desktop 用户，我希望禁用 Agent 后折叠展示并查看历史，以便保留资料但阻止新执行。
28. 作为自动任务用户，我希望禁用期间跳过定时执行并记录原因，重新启用不补跑，以便避免集中产生意外操作。
29. 作为Desktop 用户，我希望删除 Agent 后归档其普通 Session，以便保留可查历史。
30. 作为Desktop 用户，我希望删除受引用或仍有运行审批的 Agent 时得到明确阻止原因，以便先处理相关对象。
31. 作为Project 用户，我希望Agent 升级与删除不影响 Project 会话和文件，以便继续现有工作流。
32. 作为管理员，我希望隐藏内部 Agent 但仍能管理，以便避免普通导航混入业务助手。
33. 作为渠道用户，我希望Bot 改绑后新消息进入新 Agent 的新 Session，旧 Session 归属不变，以便避免上下文和身份串用。
34. 作为Desktop 用户，我希望在未分配历史中只读查看无法确认归属的旧普通 Session，以便保存历史且避免错误执行。
35. 作为Desktop 用户，我希望显式认领旧普通 Session 后继续原本可续聊的会话，以便恢复历史工作。
36. 作为Desktop 用户，我希望历史认领不解除外部会话只读限制，以便保持权限边界。
37. 作为owner，我希望普通助手按授权共享用户事实与偏好，以便跨助手保持必要连续性。
38. 作为owner，我希望不同 Agent 私有知识隔离且同 Agent 跨 Session 可访问，以便保持角色连续性而不串知识。
39. 作为owner，我希望删除 Agent 后私有记忆保留但停止正常检索和注入，以便避免无意丢失或转移资料。
40. 作为owner，我希望同名新 Agent 不继承已删除身份和私有记忆，以便保持身份隔离。
41. 作为Desktop 用户，我希望中英文即时切换、明暗主题和窄窗口下正常操作，以便在不同环境使用。
42. 作为Desktop 用户，我希望会话列表按需加载，模型只使用当前 Session 所需历史，以便避免历史数量增加导致请求上下文增长。

## Implementation Decisions

- 复用现有 Agent 配置、共享会话存储、统一历史查询、运行器、Memory 引擎和 Desktop 组件；不创建第二套系统，不新增迁移、兼容层或默认身份 fallback。
- 普通 Session 创建时持久化稳定的 Session Agent 标识。服务端以其确定执行身份并拒绝不一致请求；历史归属不随渠道改绑、名称或模型变化。Primary Agent 保留其现有 Room 默认收件人含义。
- 新建普通对话首次发送前可换 Agent，首次发送建立 Session 和绑定。创建 Agent 后直接使用 Desktop 共享执行入口，不能借另一个 Agent 的入口冒充执行。
- 外部渠道改绑后新入站消息创建或进入改绑后新 Agent 的新 Session；不继续旧 Agent 上下文。外部执行路由在共享层解决，Channel 仅承担连接与消息适配。独立 Web UI 不改，已有功能继续可用。
- 可靠证据不足的旧普通 Session 放入未分配历史。明确授权的用户可以显式认领后续聊；不能用当前 Bot 绑定猜测历史。认领不改变外部会话只读属性，Project 不参与。
- Session 显式模型覆盖优先，其次使用 Agent 当前配置，再继承现有默认配置。后续轮次使用当前有效配置，历史消息不改写；模型不改变归属。
- Owner 事实与偏好在同一 owner 的普通助手间按授权共享；Project 保持既有作用域；Agent 私有知识按稳定身份隔离，写入、反思、检索和最终模型注入一致。内部业务 Agent 不扩大授权，既有 turn-retention 规则继续生效。
- 禁用 Agent 默认折叠且历史可查看，阻止新建、续聊及自动任务新触发。既有运行不因禁用自动停止，已有停止与恢复控制保留。禁用期间定时任务跳过并记录原因；重新启用不补跑。
- 删除前校验渠道/任务引用、非终态运行与待审批，存在阻塞时显示需处理对象。删除和普通 Session 归档幂等，失败时不能出现已删除身份仍可执行。保留原归属，历史只读且可找到；Project 会话和文件不受影响。
- 删除保留私有记忆但从正常检索和模型注入中排除，不转归默认 Agent；私有记忆删除需单独明确操作。同名新 Agent 不继承旧身份。Owner 和 Project 知识不随 Agent 删除。
- 默认 Agent 始终在 Desktop 列表首位置顶并标明默认，全局新对话使用它；每个启用的 Agent 提供独立“＋”新对话入口。默认 Agent 必须存在且启用，禁用/删除前先选择有效替代项。可见性与启用状态独立，内部 Agent 默认隐藏而仍可管理。显示名称可改，稳定 ID 不改。
- Project 和 Project Session 不新增 Agent 绑定、选择或身份恢复；Room 保持现有独立模型。自动任务只增加本次身份与禁用校验，不重设计调度。
- Desktop 沿用统一紧凑窗口 Header、底部 Composer 和唯一文件/小程序 Inspector。历史会话显示 Agent 与标题，不加入大头像介绍或重复标签栏；模型只在 Composer 提供一个入口。Agent 主页提供身份、直接输入、填入草稿的示例建议和最近历史。
- 导航 Agent 一级、Session 二级；主体点击与展开独立，可多项展开、首次折叠并保存用户选择。启动恢复上次页面，Agent 主体打开新对话首页，具体 Session 才续聊。按 Agent 与 Session 分别显示选中态，草稿和后台结果不串归属。
- 完整历史按 Agent 限定范围，复用现有搜索能力、分页与生命周期操作；外部来源标记只读，归档与未分配历史可访问。Project 列表独立且行为不变。
- 必要 Agent 元数据、默认选择与导航状态沿用细粒度保存路径，整对象 round-trip 不丢字段。管理保存使用固定底栏，复用共享语义样式与既有组件；中英文、主题和窄窗口均适配。
- 先落实共享身份闭环，再接通生命周期与记忆，最后统一 Desktop 呈现。跨面板设计概念先落设计规范，在同一实现单元统一应用。已评审图是视觉方向，图中样例文字不是数据或能力证明。

## Testing Decisions

- 用户已接受测试边界：以现有共享会话服务与真实 Runner 的集成链路为主要测试入口，不为每个面板创建独立业务测试接口。
- 好的测试只断言外部可观察行为：真实执行身份、持久归属、消息和审批投影、授权后的检索/注入、拒绝原因及重启恢复；不绑定私有 helper、组件源码文本或实现步骤。
- 复用会话生命周期服务装配测试、统一 Desktop 历史查询测试和真实 Runner 审批/恢复集成测试先例，使用临时数据库与隔离数据目录。覆盖创建 Agent → 首次发送 → 新建 store/服务重启 → 历史恢复 → 同 Agent 继续执行。
- 覆盖错配执行拒绝、渠道改绑后的新 Session、未分配历史的只读和显式认领、外部历史权限不变、重复请求与生命周期重试。Project 原行为作为回归负保证。
- 复用 Memory Gateway 端到端、命名空间授权和最终 prompt 验证入口，覆盖允许共享的 owner 记忆、Agent 隔离、同 Agent 跨 Session、反思写入一致、内部授权、删除后不可注入及同名新 Agent 隔离。保留既有 retention/suppression 行为。
- 沿用 settings 临时数据库 save → 新建 store → load 整对象回归，覆盖新增字段、其他配置完整性和导航状态重启保留。
- 通过现有 Runtime Task 触发入口验证禁用跳过、原因记录、重新启用不补跑，以及既有运行停止/恢复不被破坏。
- Desktop 验证主体/箭头/Session 的不同操作、展开与恢复、各 Agent 草稿隔离、后台结果/审批归属、历史权限、直接创建、Inspector 复用和固定保存底栏。
- 完成相关测试、Desktop svelte-check 和构建；使用隔离服务走真实冷路径：重启、首次打开/点击、切换页面/Session、服务中断后恢复。检查中英即时切换、明暗主题、窄窗口和键盘焦点；不得中断未经授权的用户服务。
- 以请求证据验证不拼接其他 Session 完整历史，按需加载大量历史；不宣称未经测量的 token 节省比例。任何无法执行的必需检查明确报告。

## Out of Scope

- 独立 Web 界面改版；Project 或 Project Session 新增 Agent 绑定；Agent Room 重设计。
- 永久主对话、跨 Session 完整上下文合并、跨 Channel 无缝续聊。
- 新 Memory 引擎、多 Agent 自动协作、新任务中心、Activity Feed、社区和全套设置重设计。
- 随删除助手自动删除私有记忆或项目文件、向新同名助手转移身份。
- 新增分享发布流程、自动迁移旧历史、兼容层和推测性配置体系。

## Further Notes

- 固定 Session Agent 是执行事实，不仅是 UI 分类。Project 不加入该新模型，外部渠道只读历史也不能经认领绕过权限。
- 普通 Agent 的记忆读取、写入、反思和最终 prompt 统一按稳定 ID 授权。关闭 owner 共享后仍可使用本 Agent 私有记忆。
- 保留此规格作为身份、权限和生命周期的持续验收约定；PRD 保留产品背景。旧未知归属历史在所有入口只读，Desktop 显式认领后可继续；独立 Web 页面没有新增认领控件。
- 本次交付为本地实现与代码提交，不包含产品发布或 issue tracker 发布。
