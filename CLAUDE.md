## Quick Rules

- Layer separation: Channel layer is **messaging only**; shared upper logic (queues, recovery, task orchestration) must not leak into channels.
- Frontend: use Shadcn components from `src/lib/components/ui`. Custom app-level styles must use semantic class names (see DESIGN.md).
- **All toggle/switch controls must use `IosSwitch`** (from `$lib/components/ui/ios-switch`). Do NOT use the generic `Switch` component — its styling does not clearly convey an on/off state. `IosSwitch` provides the expected iOS-style toggle appearance.
- Never hard-code absolute paths (`/Users/...`) into code, docs, or prompts.
- After any feature change, update `features.md` and `CHANGELOG.md`. (Old entries in `prd.md` / `CHANGELOG.md` / `features.md` are archived quarterly in `docs/archive/`).
- Bug fixes: BEFORE debugging, search `CHANGELOG.md` (+ archives) and the pitfalls below for prior occurrences of the same symptom/surface. BEFORE merging, answer the "Fix 收尾三问" in AGENTS.md §开发流程沉淀规则 (root-cause class → machine guard → pitfall entry). A second occurrence of the same root-cause class makes a machine guard mandatory.
- No band-aid-then-root-fix: if a fix needs caller-side gating/special-casing instead of a shared-layer solution, either do the root fix now or file it in `prd.md` with the band-aid's removal condition.

## Recurring Pitfalls (distilled from CHANGELOG.md / prd.md — read BEFORE touching these areas)

**Mini App 安装链补充守卫（pitfall 21(d)）：**候选包的 `validate` / smoke / install 同样属于第三方进程故障域，不得通过测试 seam 把候选模块动态 `import()` 回服务进程。机器守卫必须从 Agent `miniAppManage` 入口注入 `process.exit()`；只测已安装 App Host 不算覆盖安装链。

**审批等待伪装成服务崩溃：**如果日志停在 `tool_start`、客户端在固定超时后 `fetch failed`、却没有 crash report，先查 ApprovalBroker/Host Bash 两套存储里的 pending 请求和客户端超时，不要把 eval 的清理信号当成服务自杀。统一审批卡的 list 与 resolve 必须覆盖同一组后端并按 Session 校验；eval 如需批准，必须在任务 YAML 显式声明并走正式审批 API，禁止绕过生产策略。

**请求覆盖值不得伪造缺省：**request-level model/thinking/profile 字段是可选覆盖，不是第二套默认值。输入缺失或非法时必须保持 `undefined`，让共享 Runtime 按正式优先级解析；禁止在 API parser 里 sanitize 成 `off`、默认模型等有效值。主 Agent 与 Subagent 的自定义模型兼容元数据必须来自同一份模型声明。

**上下文闸门必须守最终 Provider 边界：**预算必须包含最终 system prompt、序列化工具 schema、历史和当前消息，并在 role/tool/image patch 之后、网络 dispatch 之前再次 fail closed。压缩只改变模型上下文；当前超长输入只能裁剪送模副本，不能改写持久化原文。机器守卫必须证明超限时 Provider callback 未被调用。

**长任务的传输超时不得短于任务超时：**eval/客户端允许任务运行数分钟时，HTTP headers/body timeout 必须显式覆盖同等或更长窗口；固定约 300 秒 `fetch failed` 且 `serviceExit=null` 首先判定为 Undici 传输超时，而不是服务崩溃。

Each item below caused **multiple** shipped bugs. Check the relevant one before writing code.

1. **Session-list leakage** (fixed 4+ times): any surface that lists conversations (sidebar, browser dialog, external `contexts/` projection, more-conversations dialog) MUST filter out automation sessions — `origin: "automation"`, current `t-*` or legacy `task-*` session keys, legacy `[EVENT:...]` first-message sessions — and keep only `purpose === "conversation"`. Do the filtering in the shared query layer (`src/lib/server/app/desktopConversations.ts` / `externalSessionsFromContexts.ts`), never per-channel or in UI.
2. **Svelte 5 reactivity** (fixed 3+ times): a legacy `$:` derivation does NOT subscribe to runes `$state` from another module — it runs once and goes stale (symptom: blank on first open, works after a round-trip). New components use runes (`$props`/`$state`/`$derived`); legacy surfaces read live controller state only through its `view` store (`$conversationView` pattern). Never call a no-arg helper from a template and expect its internal state reads to be tracked — pass deps explicitly. Never trigger the same async load from both `onMount` and a `$:` block (they race on init). Corollary (fixed 2+ times, symptom: the composer advertises the global default model while the runtime uses the session's own): a `$:` reading a `toStore` projection re-runs on EVERY store tick because the projection returns a fresh object — gate such loads on the value actually changing (`if (x && x !== lastX)`), and never let a refresh handler reset per-session state (model/thinking selection) to a global default unconditionally. Guarded by `apps/desktop/src/chat-ui.test.mjs`.
3. **Stale async responses** (fixed 2+ times): list/transcript/detail fetches must carry a request generation plus owner IDs (projectId/sessionId) and be validated before mutating visible state; a late response must never replace the currently selected session. A generation guard governs shared visible state, not the value returned to the caller: an interactive operation that awaits its own refresh must consume that request's result directly, or a simultaneous background refresh can suppress the state write and make the caller observe a false empty list. Guarded by the Artifact turn-file refresh race assertion in `apps/desktop/src/chat-ui.test.mjs`.
4. **Theme through the resolved appearance and family attributes** (whole-surface silent failure): Desktop stores brightness (`light` / `dark` / `system`) separately from the family (`macos` / `rose-pine` / `catppuccin` / `midnight`). `App.svelte` writes `data-appearance`, the actual `data-resolved-appearance` (`light` or `dark`), and `data-theme-family`; it no longer uses a single `data-theme` value. Rules that depend on real brightness must use `data-resolved-appearance`, while family tokens belong under the family + resolved-appearance combination. Style ordinary surfaces through semantic tokens (`--card-bg`, `--label-primary/secondary/tertiary`, `--separator`, `--chrome-border`, `--fill`, `--accent`, `--online`, `--danger`, `--warning`) so every combination follows automatically. Reach for a per-family declaration only for a value no shared token can express (e.g. `--agent-city-sky`, which must match the WebGL clear colour), and mirror it into every family/brightness context that needs it. Status tints use `color: var(--danger); background: color-mix(in srgb, var(--danger) 14%, transparent)`, never a baked light hex. Sidebar glass is a shared layering contract: normal paths keep the translucent `--sidebar-material-tint` and `--sidebar-material-filter`, while reduced transparency, increased contrast, and low-performance paths alone disable the filter; dark family tints become transparent under system-dark. Guarded by the token/appearance-family and sidebar-material assertions in `apps/desktop/src/chat-ui.test.mjs`.
5. **CSS token drift**: referencing an undefined `var(--token)` or keyframe fails silently (no error, just broken styling — e.g. `--shadow-card`, `animation: spin`). Desktop app uses Geist tokens per `DESIGN.vercel.md`; verify a token exists before using it, and snap sizes/spacing to the Geist scale (no 13.5px, no ad-hoc shadows outside the 3 elevation tiers).
6. **Path validation vs. external IDs**: external channel identifiers legitimately contain `@ : + %` (e.g. WeChat `...@im.wechat`). Don't tighten segment/path validation without covering these; conversely, never expose absolute host paths, secrets, or saved API keys to the WebView — return opaque IDs and replace/clear semantics for credentials. Corollary (fixed 2+ times): **one path string must mean one thing in every tool.** `bash` goes through a shell and expands `~`/`$HOME`; `resolveToolPath` used `path.resolve`, so the same `~/x` became `<scratch>/~/x` and failed with a "Path not found" pointing at a path that never existed. Equally, an allowed-roots list is a *product* decision, not a security default: `miniapp-creator` scaffolds into `<dataRoot>/miniapps/apps` and then asks the agent to edit the result, so a guard that omits that root makes the whole workflow read-only through `bash cat`. Whenever a Skill or scaffolder writes outside cwd/Workspace, check the guard in the same change. Guarded by the home-expansion and Mini-App-root assertions in `src/lib/server/agent/tools/path.test.ts`.
7. **Reuse shared modules, no forked copies**: session rows use `ConversationRow`, composers use `ChatInputArea`, completed messages use the shared transcript renderer, turn logic goes through `ConversationController` with a host adapter. Generic shared components must not contain project/channel conditionals — callers inject differences.
8. **CJK handling**: any tokenizer, relevance scorer, or token estimator must handle Chinese explicitly (whitespace splitting collapses CJK to one token; chars/4 under-counts CJK ~3-4x and silently disabled compaction). Use `package/mory/src/moryTokenize.ts` for keyword scoring; weight CJK chars ≈ 1 token when estimating.
9. **Verification convention**: desktop UI changes = `svelte-check` 0 errors/0 warnings + `vite build` + desktop UI tests; agent/runtime changes = agent test suite + `tsc` on touched files. State the results in `CHANGELOG.md` entries.
10. **Cold-start smoke walk** (many shipped bugs were "first open blank / first click dead / reset after restart" — tests and builds passed): after UI/desktop changes, additionally exercise the real cold path — restart the service, first-open/first-click every affected pane, switch sessions, and recover from a service interruption — before claiming done.
11. **Settings round-trip** (fixed 3+ times): every new/changed settings field needs a save → fresh store → load round-trip regression against a temporary database; narrow serialization silently resets fields on restart. The round trip does not end at the database: every hand-written *projection* on the way back — `providerItemToUpdateRequest()` rebuilding the inline editor draft from the saved record, a page's `loadAll()` mapping into its form, that page's own save serializer — must copy the new field too. Any one of them omitting it empties the control the instant the save succeeds, and the next save writes the loss back (issue #28, the model alias). Prefer spreading the source over enumerating fields; where enumeration is required, assert the new field in that projection's unit test.
12. **Out-of-band execution must reuse the in-run context**: an approved Host Bash command can execute from two places — inside the run (`bash.ts`, which holds the agent's real `ctx.cwd`) or from an approval handler after the run ended (`/api/chat` `_handleWebHostToolsCommand`, `baseRuntime`). The out-of-band callers must resolve cwd/project/model through the same helpers the runner uses (`resolveSessionWorkingDir`, `buildRunnerProjectContext`), never re-derive them; picking the chat scratch dir made a project session's `git push` fail with "not a git repository". Guarded by `src/lib/server/agent/hostBashExecContext.test.ts`. Shared approval storage does not imply shared execution ownership: `bash:*` requests belong to HostBashStore, and Broker request lookup/listing must exclude them. Match suspended Host Bash results by approval request ID, never by a command string with potentially different arguments. Guard this boundary with both stores on the same temporary database (`hostApprovalDispatch.test.ts`). Background continuation callbacks must honor `respond(..., false)` as progress and `replaceMessage` as replacement; persist one sourced answer plus structured activities. Clients must observe run state, never assistant-row count, to detect completion (`backgroundConversation.test.ts`, `approvalContinuation.test.ts`). Corollary: when the out-of-band path fails, it must still rewrite the suspended toolResult and resume — a failure that only exists in an HTTP response body reaches neither the user nor the agent, and reads as "the button did nothing".
13. **Desktop settings invalidation** (fixed 3+ times): Settings and Chat share one WebView, so a successful Provider/Agent/Profile/model mutation must publish the shared same-document settings event; do not rely on `BroadcastChannel` for local cache freshness. A consumer that is connecting or already refreshing must retain one pending refresh and replay it after settlement instead of dropping the event. An event only reaches mounted consumers: mutually exclusive Settings sections cannot depend on hearing each other's save event, so a section that projects another section's mutable records must refresh on every entry instead of trusting an endpoint-keyed cache. Guard both the real save → Chat selector seam and Provider save → re-enter Models seam whenever a settings mutation changes model options.
14. **User cancellation is not an error, and Stop is not a queue reset** (Issue #24): an aborted request's rejection shape is transport-specific — Tauri's HTTP plugin throws a plain `Error("Request cancelled")`, `fetch` throws a `DOMException("AbortError")`, and the server may emit an SSE `error` frame before the client aborts at all. Decide "was this cancelled" from the *intent* flag plus the shared `apps/desktop/src/lib/chat/turnAbort.ts` helper, never from one error class. Equally, Stop ends the current turn only: it must not silently discard queued follow-ups (drain them once the aborted turn has unwound), and a running turn must always offer a way to inject a queued message (`/api/stream/steer` → shared `RunnerPool.steer`) rather than only wait. Guarded by `apps/desktop/src/lib/chat/turnAbort.test.ts`, `src/routes/api/stream/steer/server.test.ts`, and the queue/steer structural guard in `apps/desktop/src/chat-ui.test.mjs`. Second occurrence, same family (a run killed by the tool-failure budget), so four rules are now mandatory. (a) **A guard winds a turn down; it does not kill it.** `agent.abort()` on budget exhaustion killed the in-flight request, so the run ended on a transport string (`Request aborted`) and lost the answer that turn had already produced. Withdraw the tool list and hand the model a runtime notice instead — the tool-*call* budget always did this and the two paths are now one. (b) **An abort message is a symptom; report the cause.** Whatever ended the run must own `errorMessage`, and the user-facing sentence must be written for a person (the budget's `exceededReason` is an instruction addressed to the model). (c) **Status is never content.** `conversationProjection` collapses tool-loop progress; using `content || errorMessage` per entry let a trailing content-less aborted entry overwrite the real reply. The error may stand in as the body only when the turn produced no text at all, and the transcript renders it as a separate note. (d) **One user turn has one answer container, and a corrective control is steering.** Multiple textual terminal assistants in one run must all remain visible inside that answer in emission order; non-terminal progress cannot overwrite them or manufacture another answer row. Runtime-authored corrections raised during tools use `steer`, not `followUp`, or they can arrive after completion and manufacture a redundant closing reply. Guarded by `src/lib/server/agent/core/runtimeBudget.test.ts`, the multi-terminal and aborted-turn cases in `src/lib/server/app/conversationProjection.test.ts`, the Runner notice-queue contract in `src/lib/server/agent/core/runner.test.ts`, and the interrupted-turn structural guard in `apps/desktop/src/chat-ui.test.mjs`.
15. **Enabled sandbox must fail closed**: unsupported platforms, missing dependencies, and provider initialization errors must never return the original Bash command or inherit the host environment. The shared Agent/Subagent sandbox boundary either produces a sandboxed command or a structured blocked result. Host execution is legal only after explicit sandbox disable or through the Host Bash approval path. Persisted legacy `warn-disable` values must normalize to `block`; guard provider-unavailable execution and settings round-trip behavior with machine tests.
16. **A resizable column is not the viewport, and a flexible track needs a floor** (one root cause, three shipped symptoms: header title overlapping the action buttons, composer controls spilling past the pane edge, transcript crushed to a sliver when the file panel opened). Two rules: (a) inside any pane whose width is set by a sibling panel — Chat's transcript column, Project Chat, the file panel — never size with `vw`/`vh`. `max-width: 46vw` on the header title and `clamp(20px, 5vw, 56px)` gutters on `.messages`/`.composer-wrap` kept their full-window value after the file panel narrowed the column. Use column-relative `%` (padding and max-width percentages resolve against the containing block) and let flex do the truncating: the title block takes the slack (`flex: 1 1 auto`, `min-width: 0`) while the action row keeps its natural width. (b) a multi-panel grid needs `minmax(floor, preferred)` on the *panels* and `minmax(--chat-min-w, 1fr)` on the content, so the panels give width back first; when the floors stop fitting, drop the SIDEBAR and keep every remaining panel **in flow**. Never resolve a narrow layout by making a panel `position: fixed` over the content: the overlay needs a `z-index`, that `z-index` makes the panel a stacking context, and the panel's own head (`z-index: 31`, deliberately above the `z-index: 30` window drag mask) gets trapped under the mask — its close/refresh buttons go dead with nothing in the console — while the content pane's action row, still laid out full-width underneath, paints straight through the panel. Any absolutely positioned resize handle is driven by the *stored* width, so the stored value must be clamped to the same budget or the handle drifts off the track edge it drags. Only one media tier may own a given `with-files` split; a second full re-declaration in a lower tier fought the first and left an empty panel track. (c) **A flex item's size can silently collapse to zero, and a flex chain breaks at the first item that won't shrink** (issue #28 & Memory advanced modal, recurring symptom): `container-type: inline-size` applies inline-size *containment*, which sizes the box as if it had no contents — on a content-sized flex item that is 0 width, and with `overflow: hidden` the control's text disappears with nothing in the console (this erased the composer's model name). Only make a query container out of a box whose inline size comes from outside its contents. Conversely, a scrollable modal body needs every ancestor between the `overflow: hidden` dialog and the body to pass the height budget down (`display: flex; flex-direction: column; min-height: 0`); one plain `<form>` wrapper or `.modal-body` without `min-height: 0` retains its automatic minimum content size, refuses to shrink, and the body silently never scrolls (Project settings and Memory advanced modal clipped their tails). In WebKit (macOS WKWebView), scroll containers must also be `display: flex; flex-direction: column; overflow-y: auto;` rather than `display: grid; align-content: start;` (which swallows mouse-wheel events), and dialogs must set an explicit `height: min(...)` budget. Enforced in the shared `.modal-body` rule with `flex: 1 1 auto; min-height: 0; overflow-y: auto;`. A list-owned editor must also portal explicitly to `body`; relying on an implicit portal target lets its placement regress back to the list's scroll position. Guarded by the floor / clamp / gutter / in-flow / single-tier assertions, the no-containment pill assertion, and the project-settings/editor-dialog/modal-body scroll and portal assertions in `apps/desktop/src/chat-ui.test.mjs`.
17. **Theme a third-party widget through its own variables, and verify against its real markup**: `diff2html` (and anything like it) ships a stylesheet with its own `--d2h-*` token set and multiple colour-scheme classes. Overriding a couple of its rules (`.d2h-ins`, `.d2h-del`) recolours only what you named and silently leaves the library's default palette on everything you didn't — hunk row, `d2h-change`, borders, gutter, stat chips — which is what reads as "half-restyled". Remap the library's variables instead, and cover *every* scheme set it defines (`--d2h-*` and `--d2h-dark-*`), since the renderer picks the class (diff2html defaults to `light` regardless of app theme). Equally important: a CSS probe written from hand-authored markup proves nothing about the cascade — it omits the wrapper classes, ancestor selectors and competing rules the library actually emits. Reproduce the vendor's real DOM (or render through the library) before claiming a restyle works. Guarded by the `--d2h-*` remap assertions in `apps/desktop/src/chat-ui.test.mjs`.
18. **Window drag is an ACL problem before it is a CSS problem** (fixed 2+ times, symptom: "the window only drags from its edges" / "the title bar is dead"): both drag paths — Tauri's built-in `data-tauri-drag-region` handler and `WindowDragMask`'s `startDragging()` — invoke `plugin:window|start_dragging`, and `core:window:default` does **not** grant it; the capability must list `core:window:allow-start-dragging` explicitly or every drag is denied at the IPC layer with no console output. Diagnose in that order: check `src-tauri/capabilities/default.json` first (a denied drag that still double-click-maximizes is the tell, since `allow-internal-toggle-maximize` *is* in the default set), and never let a `startDragging()` call swallow its rejection. Only then look at layering: the top 60px is a single `.window-drag-mask` (`z-index: 30`), and a container lifted above it so its buttons stay clickable (`.header-actions`: `flex: 1` + `z-index: 31`) turns its *empty* area into an invisible drag blocker — lift such a container with `pointer-events: none` on itself plus `pointer-events: auto` on its direct children. Note the built-in handler only fires when the element carrying a bare `data-tauri-drag-region` is the direct event target (use `deep` for a subtree), so the attribute on elements *underneath* the mask does nothing. Capability edits need a Rust rebuild, not a WebView reload. Guarded by the top-chrome drag test in `apps/desktop/src/chat-ui.test.mjs`.

19. **Tool syntax in prose is never an answer, on either side of the call** (fixed 2+ times, same root-cause class): weak models on an `@app` turn write the invocation as text. That habit produces two failures with opposite gates, and fixing only one leaves the other shipping. (a) *Before* the call — nothing ran, the reply reads like a success, the user's task was silently dropped. Retry once with an execution-only runtime instruction; the zero-tool gate (`!attemptExecutedTools`) is what makes that retry safe. (b) *After* the call — the work happened and the model closed by writing the call out again (`run tool miniapp__expense-tracker__add with amount is 20 ...`), so the user sees internal syntax and cannot tell whether anything was saved. Here retrying is forbidden: it would replay the side effect. Repair in place instead, by recovering the reply from the last successful Mini App tool result — those results are already written for a human reader, which is what lets the runtime fix this without knowing the app's domain. Detection must differ per side: after a real call, naming a tool can be legitimate, so require invocation-shaped text rather than a bare id mention. Corollary: any runtime instruction about the *shape* of a Mini App reply is shared by every installed app — never name one app's fields (amount/category/date) in it, or it silently misdirects the next app. Guarded by `src/lib/server/miniapps/toolCallIntent.test.ts` and the pseudo-call recovery / domain-agnostic-instruction structural guards in `src/lib/server/agent/core/runner.test.ts`.

20. **A UI reference marker is not a filesystem path, and prose is not a mutation receipt** (second occurrence in the Project `@` feature): the composer may render a readable token such as `@[file](path)`, but the shared Runtime must parse it, validate it against the registered Project root, and hand tools only the canonical path value — never the leading `@`, display label, or raw Markdown. Preserve the display syntax in the transcript and keep the validated mapping transient. Equally, `git diff` written by a model proves nothing: claims that a file was created, edited, or saved require a successful machine-owned `write`/`edit` receipt from that run; a failed tool or empty real diff must remain a failure. Guarded by `src/lib/shared/projectFileReference.test.ts`, `src/lib/server/projects/fileReferences.test.ts`, and `src/lib/server/agent/core/runnerRetryState.test.ts`.

21. **A liveness probe must exercise the real runtime, and a supervisor must never close its own control channel** (root cause of "service 503 behind a green light" + "crashed, had to restart the whole app" + "upgrade left `{workspace}/miniapps` uncreated"): (a) `/api/desktop/handshake` and `/health` are static literals — they answer 200 from a process whose `getRuntime()` throws on every request, and because `getRuntime()` caches nothing on failure the 503 is *permanent*. Any "is it alive" check the supervisor trusts must call a route that actually builds the runtime (`/api/desktop/health?deep=1`), gated behind a handshake capability so an older adopted build answering 404 is not read as unhealthy. (b) Adoption without version identity runs the *old* build's process after an upgrade, so none of the update's migrations or new directories run — compare the running version against the bundled `molibot-runtime.version` and replace on mismatch. (c) A guard *winds a run down; a supervisor must not give up*: returning after N failures drops the `Receiver`, and every later `request_restart`'s `let _ = send()` then fails silently — the "Restart service" button goes dead with nothing in any console. Report `Error` but keep retrying with capped backoff, and park on the channel (never return) after an unrecoverable setup failure. (d) Mini App / Pi 扩展必须保持进程故障域：第三方运行模块不得重新动态 `import()` 回服务进程；Mini App 维持每 App 子进程，Pi 扩展维持独立扩展进程，调用必须带 deadline、abort 与进程组清理。主进程 crash handler 只负责服务自身故障报告，不得再被当作第三方隔离方案。(e) Directory bootstrap is data-driven with per-dir try/catch; a test asserts every `*Dir` in `storagePaths` is in the bootstrap list. Guarded by the supervisor Rust suite (`should_replace_adopted`, health classification, backoff cap, `supports_deep_health`), `scripts/runtime/crash-report.test.mjs`, `src/lib/server/infra/db/storage.test.ts`, `src/lib/server/app/runtimeHealth.test.ts`, Mini App process-isolation tests, and Pi extension load tests.

22. **A hand-written packaging manifest drifts from the import graph, and diagnostics must never be a boot dependency** (second occurrence: `bin/molibot-release.sh` first omitted `skills/`, then omitted `scripts/runtime/crash-report.mjs` + `file-logger.mjs`, which made v2.9.0 die at boot with `ERR_MODULE_NOT_FOUND` and restart-loop forever — issue #30). The release script copies runtime modules by **glob** (`scripts/runtime/*.mjs`, minus `*.test.mjs`), never file-by-file: adding a module next to `start-server.mjs` must not require remembering a second edit in a shell script no test exercises. Equally, a module whose only job is observability (crash reports, file logging) is loaded through `loadOptionalRuntimeModule()` and used with `?.` — a missing diagnostic degrades to one stderr line, it does not prevent the service from starting, because the supervisor's restart loop turns any startup-fatal error into a permanently dead app. Guarded by `scripts/runtime/release-bundle.test.mjs`, which resolves every relative `*.mjs` specifier reachable from `scripts/start-server.mjs` and asserts each one is inside the globbed directory.

23. **Liveness is ownership, a lock is not a status, and a guard must never have a silent give-up branch** (root cause of "两个任务一直转圈，而且以后再也不执行了"): (a) **age is not evidence that something is alive.** `recoverStaleRunning` reclaimed only leases older than their timeout, but after a restart *no* `running` lease can still have an in-process owner — a crash inside the timeout window (38s into a 10min budget, in production) left it `running` forever, which pinned the UI *and* made `hasActiveForTask` suppress every future run of that task. Leases carry an `owner_id`; anything owned by another process identity is reclaimed as `interrupted`. (e) **automatic replay of a side-effecting task needs a time bound** — catch up only within a window, otherwise report the interruption and wait for the next slot. 27. **A third-party payload's size is not the third party's decision, and compaction cannot shrink what it must keep** (root cause of a provider 400 reporting ~2.88M tokens of input against a 1M-token endpoint — ~11 MB arriving in ONE tool step, not gradual growth): (a) **every path that puts foreign bytes into the context needs the shared budget.** `read` and `bash` truncate to `DEFAULT_MAX_BYTES`/`DEFAULT_MAX_LINES` and spill the rest to disk, but MCP results were inlined verbatim — `item.text`, `resource.text` and `structuredContent` (pretty-printed, so *larger* than the wire payload).
