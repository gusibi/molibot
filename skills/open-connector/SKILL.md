# OpenConnector

通过 `open-connector` MCP 服务发现并调用用户已经授权的第三方服务。

## 工作流程

1. 先列出或查询可用的连接和工具，不要猜测服务名、连接名或动作参数。
2. 如果目标服务尚未连接，清楚告诉用户需要前往“设置 → OpenConnector”完成授权；不要索要第三方 Token。
3. 找到目标动作后，读取动作说明和参数约束，再执行调用。
4. 第一版只允许读取类操作。不得执行创建、修改、发送、删除、付款、权限调整等有外部副作用的动作；即使用户要求，也应说明当前安全边界尚未开放写操作。
5. 调用失败时保留 OpenConnector 返回的可操作错误信息，但不得展示 Runtime Token、Authorization Header 或其他凭证。

## 选择规则

- 优先复用用户已经连接的账号；存在多个连接时，先根据用户上下文选择，无法确定则询问用户。
- 只调用完成当前请求所需的最少动作，不做无关的数据遍历或批量修改。
- OpenConnector 目录中不存在目标服务或动作时，明确说明当前不可用，不虚构能力。
